S30 livre le **MemoryFirewall** §119.1 comme une capacité de l'**Archive** (`back/archive/brain/firewall`) : la **porte** du store `/brain` qui interdit à tout `MemoryItem` d'atteindre le noyau autrement que par le flux obligatoire à sens unique `Memory → ContextPack → Idea → Mirror → Goal → Kernel`. Le firewall **réutilise** S01/S02 (le content-hash), S13 (le `BlockReason`) et S27 (l'`ideas.Idea` pour le handoff `ViaIdea`) **sans** les redéfinir. La **règle** — « la mémoire propose ; le noyau déclare le vrai » — est celle de l'humain (KRD §119.1). Aucune vérité écrite par l'agent (le mur) ; le store `/brain` est **sous** la ligne de flottaison (l'agent lit/ajoute la mémoire), mais une mémoire ne peut **jamais** déclarer le vrai.

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/archive/brain/firewall/firewall.go`** — le firewall pur. Le **`MemoryItem`** porte `content` + `provenance` + `validity_scope` + `expires_at` + `confidence` + `taint []Taint` + `branch` — et **aucun** champ `Version` ni `Mirror` (le type les rend **irreprésentables**). **`Capture(CaptureInput) → (MemoryItem, error)`** calcule l'id = `records.Hash(records.Canonicalize(body))` (S01/S02 réutilisés — le corps canonique ne porte **aucune** clé `version`/`mirror`). **`Propose(m, goal) → ContextPackEntry`** empile la mémoire dans une entrée et **porte le taint en avant** (jamais perdu). **`ToKernel(m) → *BlockReason`** refuse **toujours** l'arête directe avec **`MEMORY_CANNOT_DECLARE_TRUTH`** — il ne rend **jamais** `nil`, quels que soient `confidence`/`taint` (aucun bypass « mémoire propre »). **`ViaIdea(m) → (IdeaCandidate, error)`** remet le `content` à l'**idea-intake** S27 comme **`ideas.Idea`** `draft` de provenance `memory:<id>` (via `ideas.Hashed`), avec `WroteKernel == false` (aucune écriture noyau). **`CheckKernelWrite(ProvenanceKind) → *BlockReason`** est le décideur pur auquel le hook délègue : `mirrored_idea` passe, `memory` et l'inconnu sont **bloqués** (fail-closed). Tout est **pur et total** — sans horloge, sans rng, sans I/O, ne panique jamais.
- **`back/runtime/blockreason/blockreason.go`** — **un code ajouté** à l'enum clos : **`MEMORY_CANNOT_DECLARE_TRUTH`** (extension additive, `change_type: refine`, jamais une suppression ; via ChangeSet + SemanticDiff + ADR 0024). Son `how_to_fix` nomme le **flux complet** (`memory_to_contextpack_to_idea_to_mirror_to_goal_to_kernel`, puis `write_mirror_run_goal_freeze`). Code non vide (jamais une prison).
- **`back/hooks/memory-firewall/main.go`** — le hook **PreToolUse MemoryFirewall** (la règle non-contournable, CLAUDE.md §5). Il **DÉLÈGUE** à `firewall.CheckKernelWrite` (determinism-first — il ne réimplémente pas la règle). Il lit la **provenance injectée** (`target_schema`, `provenance`) — il ne **plonge pas** dans `kernel`/`mirrors` (le mur ; un read de vérité dans un hook serait lui-même une violation). Il **compose additivement** : il **AJOUTE** le garde-fou du raccourci `memory → kernel` ; le mur S04 bloque toute écriture de l'agent au-dessus de la ligne, le promotion-gate S27 bloque `idée → noyau` sans miroir, S30 bloque **exactement** ce raccourci. **Fail-closed** : un événement non décodable ou une provenance inconnue est refusé (exit 2, `MEMORY_CANNOT_DECLARE_TRUTH`).
- **`back/migrations/brain_memory_item_baseline.sql`** — migration **expand-only / append-only** ajoutant le schéma **`brain`** et `brain.memory_item` : `id text PK` (= hash du corps), `body jsonb` (`{kind, content, provenance, validity_scope, expires_at, confidence, taint, branch}`), `branch text`, `created_at`. **Aucune** colonne `mirror` ni `version` ; trois contraintes **CHECK** (`kind = 'memory_item'`, `NOT (body ? 'mirror') AND NOT (body ? 'version')`, `body->>branch = branch`). **GRANT — l'asymétrie** : l'agent obtient `INSERT, SELECT` sur `brain.memory_item` (le store est **sous** la ligne — il lit et ajoute), mais **`UPDATE/DELETE` révoqués** (append-only, gardé) et **aucun** grant sur `kernel`/`mirrors`/`fitness` (le mur réaffirmé). C'est le MemoryFirewall au **niveau de la ligne**.
- **Pas de nouveau MCP, pas de Skill** : l'idea-intake S27 reçoit le handoff `ViaIdea` (un MCP store/reader mémoire relève de l'étape ultérieure ContextRouter — OpenQuestion s'il émerge) ; le flux passe par les gestes existants `/grill → /goal`. Pas de codegen (une mémoire est du carburant-candidat, rien à émettre).

## Méta — pourquoi cette forme

<Field name="L'absence est le contrat (type + corps + schéma s'accordent)" type="ni Version ni Mirror, à trois niveaux">
  Ce qui distingue une mémoire d'une vérité, c'est ce qu'elle **n'a pas**. Plutôt qu'une colonne `mirror` laissée vide (une porte latente), S30 rend l'absence **irreprésentable** : pas de champ Go, pas de clé dans le corps canonique, pas de colonne Postgres (+ une contrainte CHECK qui refuse la clé). Le **type**, le **corps** et le **schéma** s'accordent — c'est le même choix qu'à S27 pour `ideas.Idea`, une couche plus bas.
</Field>

<Field name="ToKernel ne lit jamais la confiance — comme IsClosed à S29" type="aucun seuil, aucune exception 'mémoire propre'">
  S29 a posé que « done » est calculé **sans** lire la confiance de l'agent. S30 pose le **dual** côté mémoire : `ToKernel` bloque **sans** lire la confiance de la mémoire. Une mémoire `confidence == 1.0`, `taint == []` reste bloquée. La confiance est du **contexte** (elle module le `ContextPack`), jamais un **droit** d'entrer dans le noyau.
</Field>

<Field name="Le hook délègue à un décideur pur (determinism-first)" type="CheckKernelWrite est l'algorithme ; le hook est de la plomberie">
  Le verdict est une fonction **pure et totale** de la provenance injectée — pas un jugement d'agent. Le hook ne fait que **router** stdin → `CheckKernelWrite` → exit code. Même entrée ⇒ même verdict ; le miroir de reproductibilité (rapid + fast-check) l'épingle. Un firewall « LLM qui devine la provenance » serait un **trou de déterminisme** — interdit.
</Field>

<Field name="Le store sous la ligne, la vérité au-dessus — l'asymétrie EST le firewall" type="INSERT/SELECT sur brain.*, aucun grant sur kernel/mirrors">
  Le `/brain` est du **carburant inscriptible** : l'agent y ajoute librement. Mais ce carburant ne peut **jamais** devenir une vérité sans le flux complet. La migration grave cette asymétrie dans les GRANTs Postgres (défense de niveau 2, comme S04). Le firewall en code et le firewall en GRANTs disent la **même** chose à deux niveaux.
</Field>

## Méta-méta — la loi que ça sert

<Field name="« La mémoire propose ; le noyau déclare le vrai » (KRD §119.1)" type="incident → idée → miroir, jamais incident → noyau">
  Tout le LIVRE XXIV tient en une asymétrie : la mémoire est **lisible, indexable, branch-aware** — et **non-décisoire**. Un item de `/brain` ne peut faire **échouer** un run que s'il est **promu** en miroir ou en sensor (par le flux). S30 est l'**incarnation mécanique** de cette loi : il rend le chemin `incident → idée → miroir → /goal` **obligatoire** et le raccourci `incident → noyau` **impossible**.
</Field>

<Field name="Un firewall de provenance, pas un contrôle d'accès" type="par quel chemin, jamais qui">
  La distinction est centrale (CONTEXT.md _Avoid_) : ce n'est **pas** une ACL/un sanitizer/une couche de validation. Il ne décide pas *qui* a le droit, mais *par quel chemin* une mémoire peut influencer la vérité. Cela généralise le mur (S04, « l'agent n'écrit jamais la vérité ») à la **mémoire** : même chose, descendue au niveau de l'origine d'une écriture.
</Field>

<Field name="Le firewall est le point unique — pas de monstre" type="chaque arête du flux a sa ligne de fixture">
  La loi de complétude (§29/§33) exige que chaque comportement ait son miroir vivant. La fixture couvre **chaque** arête (`capture`, `propose`, `to_kernel → Blocked`, `via_idea`) ; la propriété rapid épingle l'invariant ∀ ; le test d'injection de faute du hook prouve qu'il rougit quand une provenance mémoire est forgée. Le MemoryFirewall est le **seul** point qui force « pas de raccourci mémoire → noyau » — aucun monstre, aucune arête sans preuve.
</Field>

## Tests (miroirs)

- **`firewall_fixture_test.go`** (N2, `authority: above`) — `state → command → events` sur la mémoire `stale-discount-claim` : `capture` (taint `[user_claim, stale]`, confiance 0.4) → fuel sans version/mirror ; `propose_to_contextpack` → le taint voyage ; `to_kernel` → **Blocked** `MEMORY_CANNOT_DECLARE_TRUTH` (le cas done) ; `via_idea` → idée `draft` de provenance `memory:<id>`, sans écriture noyau.
- **`firewall_property_test.go`** (N1, rapid, `authority: below`) — ∀ mémoire : `ToKernel` bloque **toujours** (indépendant de confiance/taint, mémoire propre incluse) ; jamais de champ `version`/`mirror` ; `id == content hash` ; `Propose` ne perd jamais le taint ; `ViaIdea` rend une idée draft sans écriture noyau ; déterminisme.
- **`back/hooks/memory-firewall/main_test.go`** — injection de faute : provenance `memory` forgée ⇒ **rouge** ; `mirrored_idea` ⇒ **vert** ; provenance inconnue & garbage ⇒ fail-closed ; écriture non-noyau ⇒ non concernée.
- **`front/web/lib/firewall.test.ts`** (fast-check) — le jumeau front pin le **même** invariant que le rapid Go.
- **`tests/e2e/memory-firewall.spec.ts`** (Playwright) — `/memory-firewall` rend le pipeline à six étages, le raccourci rouge bloqué, la carte mémoire avec taint + marqueur « pas une vérité », et le chemin `via_idea` → idée draft « toujours pas de miroir ».
