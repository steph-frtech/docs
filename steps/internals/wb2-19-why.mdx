## Implémentation

**Le twin `lib/v2/why.ts`** ajoute le **WhyTree** par **réutilisation** de la projection v1 `lib/caused-by.ts` (FK12, elle-même miroir du Go `back/kernel/causedby`) — aucune règle de remontée inventée :

- **Réutilise & ré-exporte** (depuis `../caused-by`) : `trace(symptom, edges)` (la remontée `caused_by` pure, BFS déterministe nearest-first, refus de cycle `ERR_CYCLE`, round-trip content-adressé), `validate`, `isPinned`, `refString`, `serializeEdgeBody`, les types `Edge` / `Ref` / `CauseChain` / `TraceResult`, et le sentinel `CAUSED_BY_KIND`. Ré-exporte aussi `CAUSED_BY_CASES` (les graphes d'exemple de FK12).
- **Ajoute** (le neuf de WB2-19) :
  - `whyTree(symptom, edges, opts)` → `WhyTreeResult`. (1) **Remontée** : `trace(symptom, edges)` ; un cycle ⇒ `{ ok: false, error: ERR_CYCLE }`. (2) **Arbre** : on reconstruit l'adjacence `caused_by` (du → vers, arêtes valides, ordre préservé) et on déplie un arbre depuis le symptôme, chaque enfant à `depth + 1`, ids content-adressés (`w0`, `w0.0`, …), un `seen` empêchant la re-visite (le cycle est déjà refusé, l'arbre est fini). (3) **Hors-graphe gaté** : chaque `OffGraphCause` `reproduced` est **greffée** sous son parent (`under`) avec `verdict: "reproduced"` + son `why` ; chaque `rejected` est **élaguée** (poussée dans `pruned`, jamais retenue). (4) **Terminaison** : si `opts.terminal` est absent ou `mirrorId` vide ⇒ `{ ok: false, error: WHYTREE_NO_MIRROR }`. Sinon `{ ok: true, root, chain, terminal, pruned }`. PURE + TOTALE + DÉTERMINISTE.
  - `arboristWhyTree(root)` : projette la racine `WhyNode` vers la forêt React Arborist `{ id, name, cause, verdict, depth, leaf, children? }` (content-adressée par les ids `w…` déjà déterministes).
  - `whyTally(root)` = `{ nodes, leaves, offGraph, maxDepth }` ; `verdictLabel(v)` (étiquette FR d'un statut).
  - `WHY_CASES` : le registre **clos** des cas d'exemple — `chain` (la chaîne checkout → migration, close par un miroir), `off-graph` (la chaîne + une cause hors-graphe reproduite **gardée** + une rejetée **élaguée**), `cyclic` (→ `ERR_CYCLE`), `no-mirror` (sans `terminal` → `WHYTREE_NO_MIRROR`) ; `whyCaseIds`, `whyCaseById`, `caseWhyTree` (la porte unifiée de l'écran). Réutilise les arêtes `caused_by` de FK12.

**L'écran `app/v2/why/`** (route neuve, aucune route existante touchée) :

- `page.tsx` (Server Component) : charge le namespace `v2Why` via `getTranslations`, projette les clés en `strings`, et monte `<WhyClient cases={WHY_CASES} t={strings} />`. En-tête + note du mur (`v2-why-wall-note`) + note de déterminisme.
- `WhyClient.tsx` (`"use client"`) : état `selectedId` ; mémos `result = caseWhyTree(selected)`, `forest = arboristWhyTree(result.root)`, `tally = whyTally(result.root)`. Actions : `v2-why-sample-<id>` (choisir le symptôme), `v2-why-build` (l'affordance de construction), `v2-why-reset` → `setSelectedId(null)`. Le conteneur `v2-why-tally` porte `data-nodes/leaves/offgraph/depth` ; chaque nœud `v2-why-node-<id>` porte `data-verdict` + `data-depth` et un `v2-why-toggle-<id>` (déplier/replier). Sur un refus, `v2-why-refused` porte `data-refusal` (`CAUSED_BY_CYCLE` | `WHYTREE_NO_MIRROR`) et **aucun** arbre n'est rendu. Le miroir terminal (`v2-why-terminal` + `data-mirror`) et les causes élaguées (`v2-why-pruned`) sont affichés. L'arbre est rendu par **React Arborist** (`<Tree>`, `openByDefault`, indent/rowHeight) — le même composant que `/v2/policy`.
- **Le namespace bilingue `v2Why`** (fr + en, **neuf**, additif) : eyebrow/title/subtitle/wallNote, samplesHeading/Hint, buildBtn/resetBtn, les quatre libellés de tally, treeEmpty/treeHint, refusedCycle/refusedNoMirror, terminalHeading/terminalCovers, prunedHeading, la légende (legendInGraph/Reproduced/Leaf), determinismNote. Plus la clé `gestureWhy` ajoutée au namespace `v2Grille` (le lien du hub).

**Les miroirs.** Le **miroir de reproductibilité** `lib/v2/why.test.ts` (Vitest + fast-check) — 16 tests : le **déterminisme** de `whyTree` (property : deux fois → arbre byte-identique), **remontée == chaîne `trace`** (l'ensemble des causes de l'arbre == l'ensemble atteignable vers le haut), l'arbre **ne contient jamais** le symptôme, **profondeurs croissantes** (`parent.depth + 1 == enfant.depth`), **refus de cycle** (`ERR_CYCLE`), **refus sans miroir terminal** (`WHYTREE_NO_MIRROR`, y compris `mirrorId` vide), **hors-graphe** (reproduite greffée + verdict + why ; rejetée élaguée + listée dans `pruned`), `arboristWhyTree` + `whyTally` cohérents, le registre `WHY_CASES` clos et conforme à chaque `expectRefusal`. L'**e2e Playwright** `tests/e2e/v2-why.spec.ts` : choisir le symptôme `off-graph` → **un arbre monte** (`v2-why-node-w0` == `checkout-accept`, `data-nodes > 0`, `data-offgraph = 1`), la cause reproduite greffée (un nœud `data-verdict="reproduced"`), la rejetée **absente** de l'arbre mais listée dans `v2-why-pruned` (`moon-phase`), le **miroir terminal** affiché, déplier/replier la racine, « Réinitialiser » vide l'arbre, puis le cas **no-mirror** → `data-refusal="WHYTREE_NO_MIRROR"` (pas d'arbre) et le cas **cyclic** → `data-refusal="CAUSED_BY_CYCLE"`, et **aucune écriture** POST/PUT/PATCH/DELETE. **GREEN** (port 3411). Non-régression : vitest `lib/v2` + `app/v2` = **240/240 GREEN** (224 + 16) ; `next build` GREEN avec `/v2/why` (ƒ) ; `tsc --noEmit` clean ; Biome clean.

## Méta

**Pourquoi `trace` est réutilisé et non recodé (ADR 0007).** Le critère de done dit « remontée pure + property (déterministe) ». La remontée `caused_by` **existait déjà** en FK12 — BFS nearest-first, refus de cycle, content-adressée — et elle est **pure** et déjà épinglée par son propre miroir property (en jumeau du Go `causedby`). La recoder en v2 aurait introduit une **seconde** sémantique de remontée, donc un risque qu'un symptôme remonte différemment selon l'écran. WB2-19 **ré-exporte** `trace` et n'ajoute que la **projection en arbre** (`whyTree`), le **gate hors-graphe** et la **terminaison**. Le test « remontée == chaîne `trace` » verrouille ce choix : l'arbre ne peut pas inventer ni oublier une cause par rapport à la chaîne plate.

**L'anti-confabulation est une frontière de code, pas une consigne.** « Le LLM est gaté pour le hors-graphe avec cause vérifiée » n'est pas une recommandation de prompt : c'est un **type**. Une `OffGraphCause` porte un `verdict: "reproduced" | "rejected"` ; le code **branche** dessus — `reproduced` greffe, `rejected` élague vers `pruned`. Le LLM ne peut écrire qu'un `why` (du texte) ; il ne peut pas se déclarer reproduit. C'est la même discipline que WB2-15 (le placement clampé) : le jugement irréductible du LLM est **isolé** à la plus petite surface, et la **structure** est jugée par le code.

**La terminaison obligatoire est une garde de forme, pas un effet de bord.** `whyTree` refuse un arbre sans miroir terminal **avant** de retourner `ok: true` — c'est un **invariant de retour**, vérifié par deux tests (absence + `mirrorId` vide). L'écran ne peut donc jamais montrer un arbre « ouvert ». Mais refuser n'**écrit** rien : le miroir terminal est une **référence** que l'arbre exige, pas une vérité que l'écran pose. La promotion réelle (la racine → `/learn` → un miroir) reste au-delà du mur.

**Le mur, jusque dans la causalité.** Construire un WhyTree, déplier une cause, lire le miroir terminal : aucune de ces gestes n'écrit. L'e2e le prouve avec `writes === []`. Le WhyTree est une **lecture** du graphe `caused_by` — un diagnostic au-dessus du mur, pas un éditeur de causalité.

## Méta-méta

**Le WhyTree est l'inverse exact de la vague de rouge.** La vague de rouge (WB2-17, S22) propage **en avant** : une cause change, ses dépendants deviennent stale (rouge). Le WhyTree propage **en arrière** : un symptôme est rouge, on remonte à sa cause. Les deux lisent le **même** tissu de liens — `impacts` dans un sens, `caused_by` dans l'autre — et le `caused_by` est précisément la **septième** sorte de lien, ajoutée à côté des six de §41 (anti-overwrite §9). WB2-19 n'invente donc pas une causalité : il **retourne** une structure déjà déclarée. C'est pourquoi sa remontée est une simple ré-exportation de `trace`.

**Le « 5-pourquoi » est dangereux sans reproductibilité.** Le 5-pourquoi humain dérive vite vers la **rationalisation** : on enchaîne des « parce que » plausibles jusqu'à une cause qui arrange. AIDOS le **redresse** en exigeant que chaque maillon soit **reproductible** — déjà dans le graphe, ou vérifié. Une cause non reproductible n'est pas « peut-être » : elle est **élaguée**, et visiblement (barrée, listée dans `pruned`). Le pourquoi devient un **diagnostic**, pas une histoire. C'est la même honnêteté que le contrat refuse au monstre : on ne retient que ce qui est prouvable.

**La terminaison en miroir ferme la boucle de l'apprentissage.** Un diagnostic qui ne change rien est du folklore. WB2-19 **interdit** un WhyTree qui ne se termine pas en miroir : la cause racine **doit** repartir vers `/learn` → un miroir d'anti-récurrence — la garantie que **ce** symptôme, identifié une fois, sera **détecté** s'il revient. Le WhyTree n'est donc pas le bout de la chaîne : c'est la **charnière** entre la réalité (un incident rouge) et le kernel (un nouveau miroir), exactement comme `/learn` est l'unique rampe légale de la production vers la vérité. Le code remonte la cause ; il ne décide pas seul de la garde — il **oblige** seulement à en poser une.

## Place dans le cliquet KRD

WB2-19 est la **charnière qui ramène vers le cliquet** : il remonte d'un symptôme (un incident rouge) à sa cause racine via `caused_by`, et **exige** que l'arbre se termine en miroir — la rampe légale `/learn` → un miroir d'anti-récurrence, donc une **future dent**. L'écran reste au-dessus du mur : il diagnostique, il n'écrit aucune vérité (`whyTree` est pur, aucune écriture réseau). Sa construction a cliqueté red → green — le miroir `lib/v2/why.ts` (fast-check : remontée == `trace`, refus cycle/no-mirror, gate hors-graphe : reproduite greffée / non reproductible élaguée) rouge d'abord, puis vert, plus l'e2e « un symptôme → un arbre ». Il **réutilise sans forker** la projection `trace` de FK12 (`lib/caused-by.ts`) et **laisse** une phase stable où un incident est diagnostiqué et **obligé** de poser sa garde — fermant la boucle réalité → kernel.
