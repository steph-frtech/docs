S08 livre **l'Expr DSL** (KRD §24.5) : un AST JSON typé — `lit / ref / call / obj / arr` — sur un catalogue de fonctions **clos** et des refs `$`-racinées, plus un évaluateur **pur**. Il existe pour qu'une condition de bouton (`visible_when`, `enabled_when`, KRD §24.1) soit un **artefact exécutable et versionnable du noyau**, jamais du code libre. Cette étape livre la forme de l'AST + l'évaluateur + son miroir de fixture ; elle ne câble ni contrôle, ni action, ni codegen (étapes ultérieures).

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers, schéma. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

Le paquet vit dans `back/kernel/expr/` (Kernel), en quatre pièces :

- **l'AST typé** (`expr.go`) — un type Go par sorte de nœud (`LitNode`, `RefNode`, `CallNode`, `ObjNode`, `ArrNode`), tous implémentant une interface `Expr` **scellée** au paquet (`isExpr()` privé) : la grammaire est close, aucun nœud externe ne peut exister.
- **`Parse(jsonb) (Expr, error)`** (`parse.go`) — décode + valide l'AST en deux passes (lire la `kind`, puis le reste), rejetant *kinds* inconnues, fonctions hors catalogue, arités fausses et refs malformées — par une **erreur typée**, jamais un panic. Plus `Canonicalize(Expr) ([]byte, error)` : l'encodage JSONB déterministe (clés triées récursivement) qui est la source de hash du content-address, réutilisant le même schéma que `records.Canonicalize` (un seul espace d'adresses).
- **le catalogue clos** (`catalogue.go`) — l'allow-list `{lowercase, concat, now, uuid, randomToken, >, &&, !, length}`, chacune avec son arité (variadique = -1 pour `concat`). Rien au-delà de ce que KRD §24.5 nomme ou qu'un exemple exige (la règle d'honnêteté : ne jamais inventer une fonction). L'étendre est un changement de contrat → ChangeSet + SemanticDiff.
- **`Eval(expr, Env) (Value, error)`** (`eval.go`) — l'évaluateur **pur** : pas d'I/O, pas d'horloge, pas de RNG. `now`/`uuid`/`randomToken` résolvent par des `Providers` **injectés** ; un `defer recover` transforme tout panic résiduel en erreur typée (l'invariant no-panic en défense en profondeur).

La table `kernel.expr` (migration Atlas `kernel_expr_baseline.sql`, expand-only/append-only) est **content-addressée** : `id` = `version` = hash SHA-256 du JSONB canonique, contrainte `CHECK (version = id)` en base ; `superseded_by` déplace la tête sans `UPDATE` destructif. Le rôle agent y a **SELECT seul** (`REVOKE INSERT, UPDATE, DELETE, TRUNCATE`) ; seul le rôle écrivain `aidos` insère, via un ChangeSet approuvé.

## Méta

Le comportement de S08 est prouvé par **deux formes de mirror** (la nature N2 fixture + l'invariant ∀), plus la reproductibilité front et l'e2e Playwright.

<Steps>
  <Step title="Mirror fixture (N2 : state → command → events, interprété en Go)">
    `reflects=kernel.expr.Eval`, `test_kind=fixture`, `cert_language=operation-dsl/go`, `liveness=live`, `authority=above`. Source matérialisée : `tests/kernel/expr_eval.fixture.md`. Chaque cas est une ligne : un `Env` (state), un AST depuis son JSONB canonique (command), le `Value` attendu ou un rejet `Parse` (events). Couvre : `$.cart.items.length > 0` ⇒ **true** pour un panier plein, **false** pour un panier vide (le critère `visible_when`) ; `lowercase($.auth.user.name) == "ada"` (un appel se compose) ; `&&` + `!` (enabled_when) ; `exec` **rejeté à l'analyse**, jamais évalué. C'est un **means-test vers le rouge humain** (« visible_when doit s'évaluer »), pas une vérité auto-graduée.
  </Step>
  <Step title="Mirror invariant (property / rapid, ∀, sous la ligne)">
    `test_kind=property`, `cert_language=rapid`, `liveness=live`, `authority=below`. Quatre invariants de *type-soundness* : (1) `Parse(Canonicalize(ast))` round-trip (encode∘decode = identité sur un AST valide) ; (2) `Eval` **déterministe** — même `(ast, env)` ⇒ même `Value` (now/uuid/randomToken via fournisseurs fixes) ; (3) toute `kind ∈ {lit,ref,call,obj,arr}` et tout nom de call `∈` le catalogue clos, sinon `Parse` erre ; (4) `Eval` ne **panique jamais** — ref pendante / type mismatch ⇒ erreur typée.
  </Step>
  <Step title="Mirror de reproductibilité (Vitest + fast-check, front)">
    `front/web/lib/expr.test.ts` (12 tests) épingle le registre statique de `lib/expr.ts` contre l'invariant Go : l'ensemble des cinq sortes de nœuds, le catalogue clos field-for-field avec `catalogue.go`, et les verdicts des samples (`$.cart.items.length > 0` ⇒ true panier plein / false panier vide ; fonction inconnue rejetée, jamais évaluée).
  </Step>
  <Step title="e2e Playwright (route /expr)">
    `tests/e2e/expr.spec.ts` (6 tests) — la page liste les cinq sortes + le catalogue, rend l'AST `visible_when` en arbre typé, montre son résultat évalué (true panier plein, false panier vide), et affiche la fonction non-catalogue comme rejetée.
  </Step>
</Steps>

**Déterminisme-first (CLAUDE.md §6/§8).** Tout ici est une **fonction pure** — `Parse`, `Canonicalize`, `Eval` — donc tout est code, jamais un agent. L'évaluateur n'a ni horloge ni RNG dans la boucle : les fonctions impures (`now`/`uuid`/`randomToken`) sortent par des `Providers` injectés, exactement pour que l'évaluation reste reproductible. Le property rapid (invariant 2) **est** le mirror de reproductibilité côté Go ; `lib/expr.test.ts` l'est côté front. Un évaluateur qui déléguerait sa décision à un LLM serait un *determinism gap* qui bloque l'étape — l'AST clos l'exclut par construction.

**Complétude (CLAUDE.md §6, pas de monstre).** La vérité `kernel.expr` (l'AST Expr) a son miroir vivant (fixture + property) ; le miroir reflète une vérité réelle (`Eval`). Aucun orphelin, aucune vérité sans miroir.

## Méta-méta

**Place dans le noyau.** S08 est la brique **comportement-comme-artefact** de KRD §24.5 : la condition d'un contrôle est une *donnée* typée du noyau, au même titre qu'une entité (S02) ou une politique. Il consomme S02 (le schéma de canonicalisation / content-address des `records` — réutilisé, **non réinventé**) et la ligne de flottaison + les GRANTs de S04 (le mur). Il laisse une phase stable que les étapes suivantes consomment : le **control-spec** (`visible_when`/`enabled_when` qui *consomme* un Expr) et la projection `Expr → handler TS` (codegen ultérieur).

**Le mur (appliqué à S08).** Le paquet `expr` est **pur** : il n'écrit aucune vérité, ne touche ni `kernel` ni `mirrors` ni `fitness` en écriture. La table `kernel.expr` est de la **vérité au-dessus de la ligne** : le rôle agent a `SELECT` seul (`REVOKE INSERT/UPDATE/DELETE/TRUNCATE`), seul `aidos` insère via ChangeSet. Le GRANT n'est **pas inventé** : il suit le précédent S02 (kernel records) et S04 (les REVOKE sur les schémas de vérité). La route `/expr` est strictement **lecture seule** : elle projette `kernel.expr`, elle ne la réencode pas. La clause *action-capable* de `ui-completeness` est satisfaite **par le vide** — il n'y a aucune capacité backend à lier (l'évaluation est une bibliothèque pure, pas une op appelable ; un MCP `evaluator` serait une étape ultérieure), donc aucune capacité headless cachée.

**Choix de conception (réutiliser sans réinventer, ADR 0007).** Le noyau stocke le comportement comme AST, mais l'éval réutilise d'ordinaire une lib mûre (CEL / expr-lang). Ici on **hand-roll délibérément** un interpréteur minuscule sur un catalogue **clos** plutôt que d'embarquer un moteur d'expression général : un moteur général *est* une évasion vers du code libre (son propre espace de fonctions, accès membres…) — exactement ce que §24.5 interdit. Le catalogue clos + la réutilisation du hash (`records.Canonicalize/Hash`) est plus simple **et** plus sûr ici. Aucun nouvel ADR : S08 gèle un artefact nouveau (l'AST + le catalogue), il ne décale aucun contrat antérieur.

**Pas de nouvel artefact superflu (CLAUDE.md §5).** **Pas de serveur MCP** — l'évaluation est une bibliothèque pure, pas une op exposant une capacité (un MCP `evaluator` est une OpenQuestion ultérieure, pas inventée maintenant). **Pas de hook** — aucune nouvelle règle non-bypassable au-delà du mur S04 existant. **Pas de Skill** — aucun geste rejouable encore. Un nouvel artefact ne fait qu'**ajouter** une garde, jamais en retirer une.

**Anti-écrasement (CLAUDE.md §9).** S08 n'édite que ses propres fichiers : `back/kernel/expr/**`, la migration `back/migrations/kernel_expr_baseline.sql`, ses mirrors `tests/kernel/`, `front/web/app/expr/**`, `front/web/lib/expr.ts(.test.ts)`, `tests/e2e/expr.spec.ts`. La migration est **expand-only/append-only** — elle ne touche ni table ni GRANT antérieurs (S01 archive, S02 records, S04 wall, S05/S07 runs intacts). Tout changement d'un contrat gelé ici (l'ensemble des sortes de nœuds, une fonction du catalogue, l'invariant de content-address) passerait par un **ChangeSet** + un **SemanticDiff** — jamais une réécriture furtive.

**Forward-dependencies (OpenQuestions, pas des `residual_issues`).**

- **OQ-S08-1** — la persistance Postgres réelle du mirror de fixture (le schéma `mirrors` arrive à S06 ; ici le fixture est matérialisé en `tests/kernel/expr_eval.fixture.md` + test Go exécutable, qui *est* la preuve red→green).
- **OQ-S08-2** — le câblage `visible_when`/`enabled_when` (control-spec) qui *consomme* un Expr ; hors périmètre ici.
- **OQ-S08-3** — la projection `Expr → handler TS` (codegen) et un éventuel MCP `evaluator` pour l'évaluation à la demande ; étapes ultérieures.
