## Implémentation

S106 ajoute la **boucle de réalité project-scopée** : `back/runtime/realityingest` (sous-système Runtime, KRD §53/§67/§117/§1099, ROADMAP-app-builder §S106). Elle **réutilise verbatim** le moteur de réalité S43 (`back/runtime/reality` — l'`Incident`, le content-addressing S01/S02, la porte `ToKernel` toujours refusée) et lui **ajoute** trois choses que S106 exige : le **scope projet**, la **détection de divergence par comparaison**, et la **projection template du texte d'idée**. Elle **n'écrit rien** (le mur) : chaque fonction rend une VALEUR.

**La détection est une comparaison déterministe — `DetectDivergence(projectID, TelemetryReport, MirrorExpectation) → (*Divergence, error)`**. Le `TelemetryReport` est l'agrégat par opération que le `telemetry-reader` (S43/E12) débarque (operation, calls, errors, p99Ms) ; la `MirrorExpectation` est la **promesse** du miroir (max_error_rate, max_p99_ms). La comparaison est numérique, ordre fixe (taux d'erreur d'abord, puis p99), et rend le **premier** seuil franchi ou `nil` si la prod est dans la promesse. Le `Divergence` est **content-adressé** — et le `project_id` est **dans l'adresse**, donc deux projets aux divergences identiques ne collapsent jamais (isolation multi-tenant, S55).

**Le RealityMirror est project-scopé — `ToRealityMirror(Divergence) → RealityMirrorRecord`**. Il **réutilise** `reality.Observe` (la forme `Incident`, la taint `incident_derived`, le hash) : `Ref` = l'id de divergence, `Signal.Error` = l'« observé vs attendu » verbatim, `CauseSketch` = le texte template. Le record porte le `ProjectID` et la `Divergence` source. Pas de version, pas de miroir — c'est de la **réalité, pas de la vérité**.

**Le texte d'idée est une projection template — `RenderIdeaText(Divergence) → string`**. C'est le geste central de S106 (ROADMAP §S106 : « la rédaction du texte de l'Idea est une projection déterministe (template), jamais un résumé LLM »). Un `switch` sur le `DivergenceKind` (error_rate | latency) remplit un template fixe nommant le miroir, le projet, l'opération, l'observé (`formatRate`/`formatMs` à précision fixe → byte-stable), l'attendu, le trafic. **Même record ⇒ texte byte-identique.** Aucune sommation, aucune génération.

**L'idée draft — `ToDraftIdea(RealityMirrorRecord) → DraftFromDivergence`**. provenance=incident (Detail = l'id de divergence verbatim), Intent = `RenderIdeaText`, proposes inféré **seulement** quand le signal le fixe (`reality.InferProposes` réutilisé ; sinon unset + OpenQuestion, jamais deviné, §8). `WroteKernel == false` ; `ToKernelRefusal` = la porte `reality.ToKernel` ré-asserrée (`REALITY_CANNOT_DECLARE_TRUTH`, toujours non-nil). `Ingest` enchaîne les trois ; `IngestBatch` trie par id d'idée (byte-stable).

**Le MCP `aidos-reality-ingest`** (`back/mcp/reality-ingest`, ADR 0009) expose `detect_divergence`, `ingest_divergence`, `render_idea_text`. Read-only sur le Kernel (le mur) ; stdio ; pur, déterministe.

**Le twin TS `lib/reality-ingest.ts`** reproduit la détection + la rédaction + l'ingestion pour l'écran — le Go est l'autorité. La route **action-capable** `/reality-ingest` (`RealityIngestPanel.tsx` + Server Actions) porte UN contrôle « ingérer » avec un toggle « rapport sain » lié au twin pur ; elle rend le record de divergence, le scope projet, la provenance=incident, le statut du mur, et le texte template de l'idée. Thème ADR 0010, bilingue fr/en ADR 0011 ; ajoutée à la nav `WorkbenchHeader`.

**Les miroirs.** `realityingest_fixture_test.go` (5 scénarios : le done-criterion divergence→RealityMirror provenance=incident ; le texte = template déterministe ; rapport sain → aucune idée ; la réalité n'écrit jamais de vérité ; le scope projet fait partie de l'adresse) + `realityingest_property_test.go` (rapid, 3 props : détection déterministe ; rédaction template déterministe ; le mur tient pour toute entrée) ; côté front `lib/reality-ingest.test.ts` (fast-check, 4/4) + `tests/e2e/reality-ingest.spec.ts` (Playwright, 4/4 — dont le done-criterion exécuté depuis l'écran). `go build ./...` + `go test` verts.

## Méta

**Pourquoi réutiliser S43 plutôt que réécrire ?** S43 a déjà rendu autoritaires l'`Incident` (réalité sans version ni miroir), le content-addressing, et la porte `ToKernel` toujours refusée. S106 n'a pas à réinventer ces invariants — c'est l'**accrétion additive** (§9). Il ajoute strictement ce qui manquait pour des **apps déployées réelles** : le scope projet (E12 est multi-tenant), la détection de divergence **contre un miroir** (S43 partait d'un signal déjà observé), et — surtout — la **projection template du texte**.

**Pourquoi le texte est-il du code et pas un LLM ?** C'est le mandat déterminisme-first (§6/§8) appliqué à la rédaction. Un résumé LLM serait non reproductible (même incident, deux textes) et pourrait **halluciner** une cause absente des faits. La rédaction template est : (a) reproductible — le miroir fast-check/rapid épingle « même record → même texte » ; (b) honnête — elle ne nomme que ce qui est dans le record (miroir, opération, chiffres, trafic), jamais une cause inventée. Le `CauseSketch` reste une **hypothèse** explicite, pas une assertion. Un agent qui « rédige l'idée » serait un **gap de déterminisme** — exactement comme un agent qui ferait un diff au lieu d'un algorithme de diff.

**Le scope projet est dans l'adresse, pas à côté.** Mettre le `project_id` dans le corps content-adressé (et pas seulement dans une colonne) garantit que l'isolation est **structurelle** : deux apps qui hittent la même rupture de stock produisent deux records distincts, par construction. C'est la même discipline que partout dans AIDOS — l'identité est calculée, jamais déclarée.

## Méta-méta

**S106 ferme la boucle externe (boucle ③) sans jamais franchir le mur.** AIDOS a trois boucles : la boucle interne (red→green→stable), la boucle médiane (/evolve+QD), et la **boucle externe** — le monde réenseigne le Kernel. S106 est l'**on-ramp légal** de cette boucle : la prod sent, AIDOS détecte et rapporte (déterministe), mais **personne d'autre que l'humain** ne déclare que le monde a raison. La réalité **propose** un miroir ; elle n'en **est** pas un. C'est la généralisation du §1099 (« juger que le monde diverge du Kernel est une décision de vérité ») rendue exécutable et project-scopée.

**« Le monde enseigne, jamais l'agent lui-même » (§8, anti-circularité).** S106 incarne la règle anti-Goodhart : l'agent ne **fabrique** pas la vérité qu'il satisfera ensuite. La détection ne fait que **constater** un écart contre une promesse **déjà écrite** par l'humain (le miroir) ; la rédaction ne fait que **rapporter** cet écart. Le jugement — « faut-il une nouvelle dent ? » — est explicitement renvoyé au grilling humain (S107). AIDOS sépare net **constater** (code, déterministe) de **juger** (humain, au-dessus du mur), et S106 est la couche où cette séparation devient la plus tentante à violer — et où elle tient.

**La reproductibilité du texte est une garantie de confiance.** Si demain vous relancez l'ingestion du même incident, vous obtenez **le même texte** — pas une variation de phrasé d'un LLM. Cette stabilité byte-à-byte n'est pas cosmétique : elle rend l'idée **content-adressable** (le même incident → la même idée → la même adresse), donc **idempotente** (ré-ingérer ne duplique pas), et **auditable** (le texte est une fonction des faits, traçable). Le déterminisme de la rédaction est ce qui permet à la boucle externe d'être **fiable** plutôt que bavarde.
