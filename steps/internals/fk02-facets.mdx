## Implémentation

**Le paquet `back/kernel/facets`.** Le cœur de FK02 est une fonction pure totale et son ensemble clos.

- **`Facet`** est l'ensemble CLOS des huit lentilles canoniques (FKE-1.3) : `F` fonctionnel, `I` invariants ∀, `S` sécurité, `B` budgets/perf, `R` fiabilité/résilience, `V` évolutivité/migration, `M` maintenabilité & architecture, `X` expérience (soft). `facetOrder` fige l'énumération canonique F→X (l'octuor) ; le content-adressage en dépend. `Facets()` rend cette liste ; `Name()`, `IsCanonical()`, `IsSoft()` (seul X est soft, §13.6).
- **`Instance{Facet, HasIntent, HasProofPair}`** est UNE facette qu'un kernel déclare instancier : la lentille, si son **intention** (s1) est déclarée, si sa **paire de preuve** (s4↔s5/s6) est présente. L'incompressible d'une facette instanciée = `HasIntent ∧ HasProofPair` (FKE-1.3 décision (b)).
- **`FacetSet{KernelID, Instances}`** est l'ensemble EFFONDRABLE des facettes d'un kernel — il ne porte que les lentilles de sa nature de vérité.
- **`Validate(FacetSet) → Result`** est le validateur, **PUR et TOTAL** (pas de DB, horloge, rng, I/O, LLM). Trois règles :
  1. la facette **fonctionnelle (F)** est présente (incompressible) — sinon `ErrNoFunctionalFacet` ;
  2. aucune facette déclarée n'est **vide** (ni intention ni paire) — sinon `ErrEmptyFacet` ;
  3. toute facette déclarée porte sa **paire de preuve** — sinon `ErrMissingProofPair` (un MONSTRE ; `Advisory: true` seulement pour le X soft).
  Plus le rejet d'une facette **hors ensemble clos** (`ErrUnknownFacet`) et d'un **doublon** (`ErrDuplicateFacet`). Les `Issue` sortent en ordre canonique (issues de set d'abord). `Valid` est vrai ssi **aucune issue dure** (l'advisory X ne le fait jamais basculer).
- **`Canonicalize(FacetSet) → []Instance`** trie sur l'Instance ENTIÈRE (rang de facette, puis lettre, puis flags) — totalement indépendant de l'ordre **même avec doublons**. **`Hash(FacetSet)`** est la SHA-256 des instances canonicalisées (KernelID exclu) : la signature **content-adressée**, indépendante de l'ordre et du kernel (le critère « round-trip content-adressé »).

**La migration `back/migrations/kernel_facet_baseline.sql`.** Ajoute une colonne NULLable `facet` à `kernel.truth` ET `mirrors.mirror`, CHECK-pinnée aux huit lettres exactes (hors-énum = erreur DB, pas une string silencieuse). **Expand-only** : aucun backfill, aucun NOT NULL, aucune colonne antérieure touchée — c'est le **SemanticDiff `add`** (une coordonnée posée en espace libre). **Le mur** : aucun GRANT changé ; le rôle agent reste SELECT-only. La colonne mono-lettre marque la lentille **primaire** ; la facet-set complète vit dans le corps JSONB, validée par `Validate`.

**Le MCP `back/mcp/facet`** (ADR 0009, transport stdio) — trois outils, tous purs, qui n'écrivent rien (le mur) : `validate` (le validateur), `hash` (la signature content-adressée), `facets` (les huit lentilles, X soft).

**Le twin TS + la route.** `front/web/lib/facets.ts` reproduit `Validate`/`Hash`/`Canonicalize` pour l'écran (le Go reste l'autorité). La route **action-capable** `/facets` (ui-completeness, §7) : un contrôle **FILTRE PAR FACETTE** (Server Action) lié au validateur pur ; l'octuor des huit lentilles ; par kernel un badge de validité 🟢/🔴 + sa signature. Thème ADR 0010, bilingue ADR 0011. Ajoutée à la nav (groupe meta).

**Les miroirs (BDD-first, red→green).**

- `facets_property_test.go` (**rapid**, 5 propriétés) : Validate/Hash totaux & déterministes ; pas de F ⇒ invalide ; F + facettes prouvées ⇒ valide ; Hash indépendant de l'ordre/kernel ; X soft ne bloque jamais.
- `facets_fixture_test.go` (**fixture**, 10 cas) : les critères de done — pas de F refusé, paire manquante = monstre, facette vide refusée, F+I+M / les 8 / F+X légaux, X advisory, hors-énum + doublon rejetés, ensemble vide total.
- `migration_roundtrip_test.go` (**Testcontainers**, vrai Postgres, 4 cas) : colonne expand-only, les 8 lettres acceptées, hors-énum rejeté par CHECK, SemanticDiff `add`.
- `lib/facets.test.ts` (**fast-check**, 8/8) : le miroir de reproductibilité du twin.
- `tests/e2e/facets.spec.ts` (**Playwright**, 4/4) : la route action-capable.

## Méta

**Pourquoi un validateur pur et pas un agent ?** (déterminisme-first, §6/§8). Décider « ce kernel est-il un monstre ? » est un **calcul total** sur des booléens déclarés (intention/preuve par facette) : un agent y serait un *determinism gap*. `Validate` est donc code, **autoritaire**, avec son miroir de reproductibilité. Aucun LLM n'entre — ni dans le paquet, ni dans le MCP, ni dans l'écran.

**Pourquoi F toujours présente, et X soft ?** L'incompressible (FKE-1.3 décision (b)) interdit la vérité sans preuve **et** la taxe ×10 sur une fonction de trois lignes : F (intention + paire) est le plancher. X est l'exception molle (§13.6, ExperienceClaim) : son monstre est `Advisory`, il informe sans cliqueter dur — l'erreur symétrique serait de sur-contraindre l'UX comme un invariant.

**Pourquoi le hash exclut l'ordre, le kernelId ET supporte les doublons ?** La propriété rapid a révélé qu'un tri stable seul casse l'indépendance d'ordre quand une facette est dupliquée. Le tri sur l'Instance entière (rang, lettre, flags) rend le content-adressage **vraiment** invariant — la signature est sur la *déclaration*, pas sur l'ordre de saisie.

**La symétrie avec FK01.** FK02 est l'axe **orthogonal** (la facette, qui sépare) ; FK01 est l'axe **latéral** (le niveau, qui couple). Les deux colonnes — `truth_level` (FK01) et `facet` (FK02) — vivent côte à côte sur `kernel.truth`/`mirrors.mirror`, posant les **deux coordonnées** de FKE-1.4 que FK03 croisera en grille.

## Méta-méta

**FK02 est un cliquet qui n'enlève rien (§5, §9).** Il **ajoute** une coordonnée (la facet-set) et un validateur ; il ne modifie aucun record existant (colonne NULLable, expand-only), n'invalide aucun kernel conforme (additif), ne change aucun GRANT (le mur tient). C'est une garde-fou de plus, jamais une garde-fou de moins.

**FK02 garde le pouvoir d'écriture hors de l'agent.** Le validateur **juge** ; il n'écrit pas la facette sur un record. La pose passe par la transition privilégiée à la porte légale (idea → mirror → /goal → approbation). L'écran calcule et affiche, il n'écrit aucune vérité — la verticale se fait par écran sans jamais percer le mur.

**FK02 est la fondation facet-aware du reste de la piste FKE.** La complétude (FK04) chassera le monstre de **toutes** les facettes instanciées ; les colonnes parallèles (FK08) câbleront S/R/V/M/X sur des senseurs existants ; la conscience (FK09) comparera **toutes les paires instanciées** une à une. FK02 fige l'ensemble clos et le minimum incompressible dont tout cela dépend — il gate le reste de la piste.
