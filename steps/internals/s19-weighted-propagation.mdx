<Info>Côté détail. Pour le concept, voir [Pour les futurs utilisateurs → S19](/steps/concept/s19-weighted-propagation).</Info>

S19 livre le **moteur de propagation rouge pondérée et seuillée** (KRD §112, §114) : le **poids typé** comme valeur (`cosmetic | load-bearing | critical`), un **`FireParent` pur** `(graph, parent) → {GREEN | RED}` qui applique le tir §112 (`activation ← Σ poids(enfants changés)` ; ROUGE ssi `activation ≥ seuil_déclaré`), et un **`ValidateWeight`** qui refuse un lien `critical` sans **`weight_evidence`** par un `*BlockReason` actionnable (la discipline §2463). La **règle** « un changement cosmétique ne rougit pas le parent ; un poids critique sans preuve est refusé » est celle de l'humain (KRD §112 + ADR 0018) ; les **arêtes/poids/seuils** d'un vrai projet sont déclarés au-dessus de la ligne. Aucune vérité écrite (le mur).

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/kernel/propagation/propagation.go`** — le cœur **pur** (aucune I/O, aucune horloge, aucun rng). Le **poids** : `Weight` est un ensemble **fermé** de trois (`WeightCosmetic`, `WeightLoadBearing`, `WeightCritical`). `Activation(w) → float64` mappe le poids vers sa contribution déclarée — `cosmetic = 0 < load-bearing = 1 < critical = 2` (ADR 0018, **monotone, jamais apprise**). Le **lien** : `Link{ Parent Ref, Child Ref, Weight, WeightEvidence }` où `WeightEvidence` est requis ssi `Weight == critical`. Le **read-model** du composite : `Parent{ LayerID, Version, ActivationThreshold }`. `Graph{ Parents, Edges, Changed }` est l'entrée pure. `FireParent(g, parentID) Verdict` calcule `act ← Σ Activation(poids(arête))` sur les enfants **changés**, puis rend **ROUGE** ssi `act ≥ seuil` (un seuil ≤ 0 signifie « tout changement contribuant rouvre » ⇒ ROUGE ssi `act > 0` ; un parent absent reste **VERT** — le moteur n'invente aucun seuil). Il est **total** (toujours `GREEN | RED`), **déterministe**, **ne panique jamais**. `ValidateWeight(l) *BlockReason` rend `nil` si le lien est admissible, sinon un `BlockReason{ Code, Severity, Explanation, HowToFix }` : un `critical` sans `WeightEvidence` ⇒ `CRITICAL_WEIGHT_WITHOUT_EVIDENCE` + `how_to_fix: [attach_incident_evidence, downgrade_to_load_bearing]` ; un poids hors de l'ensemble fermé ⇒ `UNKNOWN_WEIGHT`. Il valide la **présence** d'une référence de preuve, pas sa vérité (la vérification de provenance est une étape ultérieure — OpenQuestion ADR 0018).
- **`back/migrations/kernel_propagation_baseline.sql`** — la migration **Atlas additive, expand-only**. Le poids + `weight_evidence` chevauchent **dans** le corps JSONB existant de `kernel.link` (la forme S17/S18 — aucun `ALTER`), exposés par une **vue** `kernel.composes_weight` (qui surface aussi `weight_evidence`, là où la vue S18 `composes_edge` ne surfaçait que le poids). La **règle d'admission** atterrit comme une **nouvelle table append-only** `kernel.composes_weight_admission` portant **deux CHECK** qui **sont** le mur au niveau base : `weight IN ('cosmetic','load-bearing','critical')` (l'enum fermé) et `weight <> 'critical' OR weight_evidence IS NOT NULL` (la discipline §2463). Le `activation_threshold` continue de vivre dans la table S18 `kernel.layer_activation` (aucun `ALTER` de `kernel.layer`). Le rôle agent reçoit **SELECT-only** et se voit **REVOKE** toute écriture (le mur). Elle **n'altère ni ne dépose** aucune table antérieure (S02 / S17 / S18 intacts).

Le comportement de S19 est prouvé par **deux miroirs** (chacun de la bonne nature), tous rouges avant le code (le rouge **est** le `/goal`).

## La route Workbench

`front/web/app/red-propagation/page.tsx` → **`/red-propagation`** : Server Component (intro + tutoriel + exemple) rendant `components/RedPropagation.tsx` qui joue `fireParent` / `validateWeight` **purs** par ligne — aucune I/O, aucune horloge, aucun rng. Il rend l'arbre `cart` avec chaque arête dessinée par l'**épaisseur de son poids** (§2362), le **seuil** du parent, une **table de tir** (les jeux de changements §114 → activation calculée + verdict d'agrégat) et une **table d'admission** (les verdicts `validateWeight` avec le `BlockReason` et `how_to_fix`). **Lecture seule** (le mur) : il rend les verdicts calculés, il n'écrit aucune vérité (poids/seuils via propose → ChangeSet → approbation). Thémée (ADR 0010), bilingue (ADR 0011). E2e `tests/e2e/red-propagation.spec.ts` : seuil 1, `help-link` cosmetic, `checkout-button` load-bearing, ligne cosmétique **VERTE**, ligne porteuse **ROUGE**, ligne `critical` sans preuve **refusée**/`CRITICAL_WEIGHT_WITHOUT_EVIDENCE`, ligne `critical` avec preuve **admise**.

## Méta-méta

Pourquoi **peser** et **seuiller** plutôt que cascader aveuglément ? Parce que tous les changements d'un enfant ne sont pas un **défaut** du tout : *« épingle un défaut, pas un changement »* (KRD §11/§112). Un agrégat qui rougit à chaque clignotement crie au loup et érode la confiance dans le rouge. Séparer le **verdict §109** (S18, la loi inconditionnelle) du **tir §112** (S19, le signal pondéré) garde deux questions distinctes : *« le tout est-il vert ? »* et *« ce changement doit-il rouvrir l'invariant émergent ? »*. Et **déclarer** poids et seuils — jamais les apprendre (§2465) — est la garde anti-Goodhart : on **emprunte la topologie** d'un réseau pondéré seuillé sans emprunter son **apprentissage** dans le jugement. Le tier `critical` pousse cette honnêteté plus loin : relever un poids est un **engagement** qui doit s'appuyer sur une **preuve enregistrée** (§2463, le sens *backprop* = un incident révèle qu'un lien cru cosmétique était porteur) — la `weight_evidence` rend cet engagement **traçable**, et le `BlockReason` rend son refus **actionnable** (un mur sans porte est une prison).

## La touche de contrat antérieur (ADR 0018)

S19 **n'édite aucun** fichier source antérieur. Il **réutilise** la substrate S18 `composes` (mêmes `Ref`/poids/seuil) et le content-hash de S02 sans les forker, et **étend** la paire de poids §112 `cosmetic | load-bearing` par le tier **`critical`** — une décision **above-the-line** enregistrée dans l'**ADR 0018** (un SemanticDiff `kind: add` sur l'enum de poids, pas un `refine` : le sur-ensemble n'affecte aucune arête/verdict S18 existant). La **re-pondération** d'un lien vivant (cosmetic → load-bearing/critical sur preuve d'incident, §2463) est exactement un `reweight` SemanticDiff (KRD §44.1) — son exécuteur est une étape **ultérieure**, pas celle-ci.

## La place dans le noyau

S19 est une couche **Kernel** (le poids typé + la règle d'admission + le moteur de tir). Elle **réutilise** S02 et la substrate `composes` de S18, **consomme** le seuil déclaré `kernel.layer_activation`, **prépare** le câblage de `FireParent` dans le tir de la vague rouge `PostKernelChange` (une étape runtime) et l'exécuteur `reweight` SemanticDiff. Le mur reste intact : `kernel.composes_weight_admission` est SELECT-only pour l'agent ; toute écriture passe par propose → ChangeSet → approbation.
