## Implémentation

**Le twin d'idée `lib/v2/idea.ts`** — la source unique de la LOGIQUE, PUR (aucun React/DOM, aucun LLM, aucune horloge) :

- Types & jeux clos : `Provenance` (`humain | incident` + `PROVENANCES`), `FACET_LETTERS` (réutilisé de `lib/facets`, les huit lentilles FKE-1.3), `Besoin` (intent, level, facet, scale, provenance bruts), `Coordinate` (level × facet × scale), `Idea`. **L'échelle (`scale`) est un CHEMIN dans l'arbre `composes`** (ex. `app/paiement/checkout`), validé **fail-closed** contre l'arbre vivant (`nodeByPath`) — l'ancien enum clos `FractalScale` (`cellule | kernel | feuille`) a **disparu** (ADR 0055 : il était conceptuellement faux).
- `selectableLevels()` / `verticaleOrder()` : les niveaux proposables — **réutilisés de la grammaire besoin** (`allLevels()` = 7 rungs SOURCE + 2 bands ; `SOURCE_ORDER` = la verticale §23), jamais un fork.
- `validateBesoin(b)` : la liste ordonnée & stable des `BesoinError` (`intent_too_short`, `level_unknown`, `facet_unknown`, `scale_unknown`, `provenance_unknown`) — l'oracle de validité, total.
- `ideaHash(intent, coord, provenance)` : FNV-1a 32 bits hex sur la sérialisation canonique `intent | level×facet×scale | provenance` — content-addressed, déterministe.
- `composeIdea(b)` : le cœur. Valide ; sinon `{ ok:false, errors }`. Sinon fige la `Coordinate`, **annexe la forme de miroir** via `levelMirrorForm(level)` (la table **EL10** de `lib/besoin-completeness`, réutilisée), content-adresse l'`id`, et pose les invariants du mur : `hasMirror: false`, `wroteKernel: false` (typés littéraux).

**Le twin de l'échelle vivante `lib/v2/composition.ts`** (ADR 0055) — PUR & TOTAL & DÉTERMINISTE (pas d'horloge, pas d'aléa, pas d'E/S, pas de LLM) :

- `slugify(label)` : le segment de chemin canonique (accents pliés NFD, minuscules, tirets) — idempotent ; `nodePath(nodes, id)` / `nodeByPath(nodes, path)` : la **bijection chemin ↔ nœud** (fail-closed : id inconnu → `[]`, chemin inconnu → `null`, remontée bornée même sur entrée cyclique).
- `roleOf(nodes, id)` : le **rôle DÉRIVÉ** de la position (`SCALE_ROLES = racine | cellule | kernel | feuille`) — profondeur 0 → racine, 1 → cellule, feuille profonde → feuille, intérieur profond → kernel. **Jamais stocké** : la même donnée change de rôle quand l'arbre pousse (une feuille greffée devient kernel).
- `growComposes(nodes, parentId, label)` : la **greffe** — append-only (le préfixe intact, §9), **idempotente** (même slug sous le même parent → arbre inchangé), **content-adressée** (id = FNV-1a du chemin canonique : même greffe → même id), fail-closed (parent inconnu / libellé vide → arbre inchangé) ; le niveau de l'enfant = le rang **suivant** de la verticale §23 (clampé à l'entité), la facette héritée.
- `placeIntent(nodes, intent)` : le **placement calculé** — un algorithme de score lexical (tokens ≥ 3 chars accents pliés ; +2 par token du libellé propre, +1 par token d'un ancêtre ; départage score ↓ puis profondeur ↓ puis id ↑), **jamais un prompt** (§6/§8). Score 0 → la **racine** (l'écran propose une nouvelle cellule). Retourne un `Placement` (`nodeId`, `path`, `role` dérivé, `score`) — toujours un nœud **membre**. L'humain **surcharge** le placement proposé (§49).
- `seedComposes()` : l'arbre seed canonique qui amorce l'écran tant que la relation `composes` vivante n'est pas servie depuis Postgres (S17/S18, OpenQuestion documentée) : `app` (racine) → `paiement`, `catalogue` (cellules) → `checkout` (kernel) → `débit du compte` (feuille).
- **Réutilisation** : la STRUCTURE (`KernelNode`, validation cycles/orphelins) vient de `lib/v2/kernel-tree` (WB2-04), les niveaux de `lib/besoin-grammar` — ce module ne tient que la logique de l'échelle vivante.

**La machine `app/v2/idee/IdeaWizardMachine.ts`** (XState v5, `setup().createMachine`) :

- États : `intention → coordonnee → provenance → revue → proposee` (`WIZARD_STEPS`).
- Événements : `PATCH` (met à jour un champ du `Besoin` via `assign`), `SUIVANT` / `PRECEDENT` (navigation), `PROPOSER`, `RECOMMENCER`.
- `PROPOSER` (depuis `revue`) : transition gardée `besoinValide` (= `validateBesoin().length === 0`) vers `proposee` avec l'action `compose` ; sinon reste sur `revue` et expose `context.errors`. **La machine ne juge rien** : `compose` délègue à `composeIdea` (le code), `besoinValide` à `validateBesoin`.
- `RECOMMENCER` (depuis `proposee`) : action `reset` → besoin vide, idée null.

**Le client `app/v2/idee/IdeaWizardClient.tsx`** (`"use client"`) : `useMachine(ideaWizardMachine)` ; le stepper rend `WIZARD_STEPS` (`data-state`, `data-active`) ; chaque étape rend ses champs (textarea intent ; `<select>` level/facet alimentés par `selectableLevels()`/`FACET_LETTERS` ; l'**échelle** : le placement **proposé** par `placeIntent` sur l'arbre vivant — `seedComposes()` + greffes `growComposes` — que l'humain **surcharge** en désignant un autre nœud, chaque option affichant son chemin et son rôle dérivé `roleOf` ; radios provenance depuis `PROVENANCES`) qui `send({type:'PATCH'})` ; l'étape `proposee` rend l'encart **amber** (id, coordonnée, `expectedMirrorForm`, `hasMirror`/`wroteKernel`). Les libellés viennent du namespace i18n `v2Idee` (passés en props depuis le serveur). `useId()` pour les `htmlFor`.

**La page `app/v2/idee/page.tsx`** (Server Component) : segment **statique** qui prime sur `/v2/[slug]`. Elle rend l'identité canonique du concept depuis le glossaire (`entry("idee")` → `v2-concept-title` = « Idée », `v2-concept-def`) — ce qui **préserve le contrat de navigation `/v2 → /v2/idee`** (le bloc « Idée » du schéma mène ici) — puis le titre du wizard, la note du mur, et `<IdeaWizardClient/>`. Nouveau namespace i18n `v2Idee` (FR + EN).

**Les miroirs** :

- Reproductibilité — `lib/v2/idea.test.ts` (Vitest + fast-check) : le mur (toute idée `hasMirror=false ∧ wroteKernel=false`) ; coordonnée totale (reprise exacte du besoin) ; forme de miroir = `levelMirrorForm(level)` (réutilisée) ; déterminisme (même besoin → même idée, empreinte byte-identique) ; validation totale (texte court / niveau hors grammaire / facette·provenance hors jeu clos refusés ; **échelle hors de l'arbre — chemin inconnu ou vide — refusée fail-closed**) ; `validateBesoin` oracle de `composeIdea`. ## Méta

- **Déterminisme-first.** Composer une idée est une **fonction pure** (`composeIdea`), jamais un agent : parse/validation/coordonnée/forme-de-miroir/hash sont du code. XState n'**orchestre** que l'état d'écran ; il **délègue** tout jugement au twin (la garde `besoinValide` appelle `validateBesoin`, l'action `compose` appelle `composeIdea`). Le LLM n'entre nulle part — pas même pour « comprendre » le besoin : le texte est repris verbatim.
- **Réutiliser, ne pas réinventer.** Les niveaux viennent de `besoin-grammar` (la verticale §23), les facettes de `lib/facets` (FKE-1.3), la **forme de miroir** de `levelMirrorForm` (l'EL10). Le step n'invente aucune table ; il **compose** des sources déjà prouvées. La lib de wizard (XState + RHF/Zod, slot gelé ADR 0053) est un **rendu**, pas une autorité.
- **Le mur, prouvé deux fois.** `hasMirror` et `wroteKernel` sont des **littéraux `false`** dans le type `Idea` (impossible à mettre à `true` sans changer le type) ; et l'e2e **surveille le réseau** — aucune écriture ne part. Le mur n'est pas une intention, c'est un invariant (property) + une garde (e2e).
- **Pré-hydratation & contrat de navigation.** Le segment statique `/v2/idee` prime sur `[slug]` (Next), mais la page **garde** `v2-concept-title`/`v2-concept-def` (depuis le glossaire) pour que l'e2e WB2-02 « chaque bloc navigue vers son écran » reste vert — anti-overwrite : on **enrichit** l'écran sans casser le contrat amont.
- **ui-completeness.** Le seul geste de cet étage (capturer → proposer une idée) a un contrôle exécutable (« Proposer »), et l'e2e prouve qu'il s'exécute. Aucune capacité headless.

## Méta-méta

- **Le geste EST une machine à états.** Un wizard KRD n'est pas un formulaire multi-pages : c'est une **machine** (XState) dont les états sont des altitudes du besoin (intention → coordonnée → provenance → revue → proposée). Modéliser le geste comme une machine rend ses transitions **testables comme des fixtures** (`état → commande → état`) — la même forme que les fixtures Operation DSL (S10) du runtime. L'outil qui code AIDOS et la méthode qu'il outille partagent la grammaire.
- **L'idée est un candidat-vérité, pas une vérité.** Tout l'écran matérialise §115 : `hasMirror=false`, pas de gel, amber. La frontière entre « déclarer » et « prouver » n'est pas un commentaire — c'est un **type** (`Idea` ne peut pas porter de miroir) et une **couleur** (amber ≠ vert). On voit le mur à l'œil nu.
- **L'échelle est une position, pas un attribut (ADR 0055).** La première version avait figé l'échelle fractale en enum clos — une erreur de **réification** : on avait stocké une *lecture* comme si c'était une *nature*. La correction inverse le rapport : la **structure** (l'arbre `composes`, qui pousse) est la vérité ; `racine/cellule/kernel/feuille` sont des **fonctions de lecture** (`roleOf`) recalculées à chaque consultation. C'est le même principe que « le rôle est dérivé, jamais stocké » appliqué partout dans KRD : ce qui peut être calculé d'une source ne doit jamais être dupliqué en donnée (sinon les deux divergent — un monstre en germe). Et le placement est un **algorithme** que l'humain surcharge, jamais l'inverse (§49, §6/§8).
- **Content-adresser un besoin.** `ideaHash` donne au candidat une **identité stable** (même besoin → même empreinte) **avant** tout gel. C'est la même discipline que le kernel (la version est l'empreinte) appliquée un cran plus haut, au-dessus du mur : un candidat est déjà référençable, donc déjà traçable jusqu'à sa promotion `/goal`.

## Place dans le cliquet KRD

WB2-03 se tient **avant la première dent** du cliquet : l'écran d'idée produit le candidat-vérité (amber, `hasMirror=false`), pas une dent gelée. Sa propre construction, elle, a cliqueté — les miroirs `lib/v2/idea.test.ts` (fast-check), `IdeaWizardMachine.test.ts` (fixtures XState) et `tests/e2e/v2-idee.spec.ts` étaient **rouges** d'abord, puis verts (red → green → refactor), laissant une **phase stable** que WB2-11 (`/goal`) consomme pour transformer l'idée en dent. L'écran **n'avance jamais le cliquet du kernel** lui-même (le mur) ; il alimente l'entrée du cliquet (idée → miroir → `/goal`). Anti-overwrite : il s'ajoute au shell V2 sans toucher `/v2` ni `[slug]`, le vert amont reste intact.
