## Implémentation

**Le twin ai-lab `lib/v2/ai-lab.ts`** — la source unique de la LOGIQUE, PUR (aucun React/DOM, aucun LLM, aucune horloge, aucun aléa), bâti par **réutilisation** de l'évaluateur v1 `lib/ai-lab.ts` (FK11) :

- **Réutilise & ré-exporte** (depuis `../ai-lab`) : `validatePlacements(raw)` (le **clamp** — ne garde que les placements dont `(level, facet, pairId)` sont dans l'espace déclaré, trim/cap du texte, tri stable), `placementsByLevel`, `placementKey`, `isTruthWriteRequest`/`WallRefusal` (le **mur**), `MIRROR_PAIRS`, `ALL_FACETS`, `VERTICAL_LEVELS`, les types `Placement`/`SpecStatus`/`Facet`. WB2-15 n'invente **aucune** règle métier ni sémantique de placement ; il réutilise le gate v1.
- `PLACEMENT_SPACE` : l'**espace déclaré et clos** des cellules — `VERTICAL_LEVELS × ALL_FACETS × MIRROR_PAIRS` = **7 × 8 × 6 = 336** cellules `{level, facet, pairId}`. `SPACE_COUNTS = {levels:7, facets:8, pairs:6, cells:336}`.
- `placementSlug(c)` (= `level-facet-pairId`, bijectif), `cellBySlug(slug)` (undefined pour un inconnu, totalité), `isDeclaredCell(c)` (le **prédicat du clamp** — la cellule est-elle dans l'espace ?).
- `placeNeed(message, raw)` : **le cœur neuf**, la porte unifiée du cerveau gauche. Si `isTruthWriteRequest(message)` → un `WallRefusal` (`code: AI_LAB_DIRECT_TRUTH_WRITE`, `howToFix` = idea-intake → write-bdd-scenario → /goal). Sinon → `{refused:false, placements: validatePlacements(raw)}` — la liste **clampée** (chaque placement gardé est dans l'espace, une cellule inventée jetée). PURE & TOTALE & DÉTERMINISTE.
- `fallbackPlacements(message)` : le **fallback déterministe** — un placement par défaut (`produit · F · spec`, message = intention), passé par `validatePlacements` (donc déclaré par construction). Message vide → `[]`. PURE, sans aléa/horloge/LLM.
- `levelsTouched(placements)` (les niveaux distincts touchés, dans l'ordre de la verticale), `countsByLevel` (le Σ par rung). Registre CLOS `NEED_SAMPLES` : `checkout-multi` (fan-out produit→entité + **une cellule inventée `galaxie`**) et `secret-field` (entité×S×model + **une facette inventée `Z`**) — chaque `raw` inclut **volontairement** une cellule inventée pour que le clamp soit **prouvable à l'écran**. `needSampleIds`/`needSampleById`. `STEP_SLUG = "wb2-15-ai-lab"`.

**Le client `app/v2/ai-lab/AiLabClient.tsx`** (`"use client"`) :

- État `message` (la zone de texte), `placements`, `refusal`, `usedFallback`, `rawForSample` (la sortie brute du cerveau gauche quand un exemple est choisi). `byLevel = placementsByLevel(placements)`, `levels = levelsTouched`, `counts = countsByLevel` (mémoïsés).
- **À gauche** : un `textarea` (`v2-ai-lab-input`), les boutons **Placer** (`onPlace` — utilise `rawForSample`, sinon retombe sur le fallback) et **Fallback** (`onFallback` — passe d'abord par `placeNeed(message, [])` pour que le **mur tienne même en fallback**), et les **besoins d'exemple** (`v2-ai-lab-sample-<id>` → `onPickSample` qui appelle `placeNeed`). Le **refus au mur** s'affiche en bandeau `--destructive` (`v2-ai-lab-refusal`, code + explanation + howToFix).
- **À droite** : le compteur (`v2-ai-lab-placed-count`, `data-count`/`data-levels`), la **verticale** (`v2-ai-lab-level-<level>` par rung non vide, chaque placement `v2-ai-lab-placement-<key>` avec `data-level/data-facet/data-pair`, tri facette puis paire), un état vide (`v2-ai-lab-empty`), la note fallback (`v2-ai-lab-fallback-note`), le bandeau du mur. Tokens CSS (ADR 0010), jamais de hex.

**La page** : `app/v2/ai-lab/page.tsx` (server — charge le namespace `v2AiLab`, passe `NEED_SAMPLES` + les strings i18n au client). Namespace bilingue `v2AiLab` (FR + EN), ADR 0011.

## Méta

- **Determinism-first (CLAUDE.md §6/§8).** Le **clamp est code, jamais LLM** : `placeNeed`/`validatePlacements`/`isDeclaredCell`/`fallbackPlacements`/`placementSlug` sont des fonctions pures. Le **seul** jugement irréductible est le placement NL→cellule — délégué à Claude **au runtime**, l'exception gated — et sa **structure** (la cellule, l'id) est **vérifiée** par ce code (le clamp), jamais acceptée telle quelle. Le miroir de reproductibilité (`lib/v2/ai-lab.test.ts`, fast-check, 15/15) épingle : déterminisme (`placeNeed` deux fois identique), **le clamp** (property : ∀ placement gardé `isDeclaredCell == true`, même avec des niveaux/facettes/paires inventés en entrée), **le mur** (∀ message d'écriture-vérité → `WallRefusal`, jamais un placement), un message ordinaire ne refuse jamais, le **fallback déterministe** (même message → même placement), la **bijection** slug↔cellule sur les 336 cellules, le **multi-niveaux** (le besoin checkout touche ≥ 3 niveaux), la conservation de `countsByLevel`.
- **Réutilisation, pas de fork (ADR 0007).** Le twin ne réimplémente PAS la sémantique de placement : `validatePlacements` (le clamp), `placementsByLevel`, `isTruthWriteRequest`/`WallRefusal`, `placementKey` viennent de `lib/ai-lab.ts` (FK11). WB2-15 n'ajoute QUE la **porte unifiée** (`placeNeed`), l'**espace explicite** (`PLACEMENT_SPACE` + le routage `placementSlug`/`cellBySlug`) et le **registre d'exemples** (`NEED_SAMPLES`, chacun avec sa cellule inventée). Une seule logique de gate, réexposée pour l'écran V2.
- **Le mur (§2).** Placer = PROPOSER. Les placements sont ambre ; aucune route d'écriture n'existe, aucun POST/PUT/PATCH/DELETE. L'e2e surveille le réseau et exige zéro écriture. Un message d'écriture-vérité directe est **refusé** (et le mur tient **même** sur le chemin fallback). La promotion d'un vrai truth reste idée → miroir → /goal.
- **WB2-14 vs WB2-15.** WB2-14 = la **règle** d'autorisation (l'arbre all/any/not, évalué). WB2-15 = le **cerveau gauche** qui place un besoin sur la verticale (gaté + clampé). Deux concepts distincts de la même verticale ; additif (anti-overwrite §9), aucune route V1 touchée, aucune règle inventée.

## Méta-méta

- **Pourquoi matérialiser `PLACEMENT_SPACE` (336 cellules) au lieu de valider chaque dimension à part ?** Parce que le clamp doit avoir un **référentiel unique et énumérable** contre lequel se mesurer. En matérialisant l'espace (un produit cartésien des trois jeux clos déclarés), `isDeclaredCell` devient un appartenance triviale, la **bijection** slug↔cellule est testable sur l'**intégralité** de l'espace (336/336), et l'écran peut afficher honnêtement « 7 × 8 × 6 = 336 cellules, le clamp ne garde que ce qui y tombe ». L'espace est une **donnée**, pas une suite de `if`.
- **Pourquoi chaque besoin d'exemple inclut-il une cellule INVENTÉE ?** Parce qu'un clamp qui n'a jamais rien à jeter est un clamp **mort** (on ne saurait pas s'il garde). En glissant une cellule hors-espace (`galaxie`, `Z`) dans chaque `raw`, le test « le nombre gardé < le nombre brut » et l'e2e « le niveau galaxie n'apparaît pas » **prouvent** que le gate écarte réellement — la fault-injection est dans la fixture même, pas seulement dans une assertion abstraite.
- **Pourquoi le fallback repasse-t-il par `placeNeed(message, [])` avant de poser son défaut ?** Pour que le **mur tienne sur les deux chemins**. Si le fallback contournait le refus, un utilisateur pourrait demander « écris la vérité » et obtenir quand même un placement par défaut — une fissure dans le mur. En faisant d'abord passer le message par le gate, le refus d'écriture-vérité s'applique **avant** tout placement, déterministe, qu'on ait Claude ou non.
- **Pourquoi le placement NL→cellule reste-t-il LLM (l'exception gated) et pas du code ?** Parce que décider *où* va « je veux un tunnel de paiement » — quel niveau, quelle facette, quelle paire — est un **jugement sémantique** irréductible : aucune fonction pure ne le dérive du texte sans réimplémenter une compréhension du langage. C'est précisément le cas que §6 autorise pour le LLM : génération/jugement irréductible, **isolé à la plus petite surface** (la sortie brute `raw`), et **revérifié déterministiquement** (le clamp). Le code n'invente jamais un placement ; il **vérifie** celui que le cerveau propose. La limite assumée (OpenQuestion) : l'écran exerce le clamp sur des **besoins d'exemple** déclarés ; le branchement du vrai Claude (et son schéma de sortie) est la même frontière que les autres écrans V2, par conception — le mur d'abord.

## Place dans le cliquet KRD

WB2-15 se tient **avant la première dent** : l'AI Lab place un besoin sur la verticale (gaté + clampé) pour **préparer** des idées, pas pour graver une vérité — `placeNeed` ne fait jamais d'écriture, l'écriture-vérité directe est refusée au mur (sur les deux chemins, fallback compris). C'est l'entrée du cliquet (placement → idée → miroir → /goal), pas le cliquet lui-même. Sa construction a cliqueté red → green — le miroir `lib/v2/ai-lab.ts` (fast-check : le clamp ∀ placement gardé déclaré, le DENY du mur, le fallback déterministe, la bijection slug sur 336 cellules) rouge d'abord, puis vert, plus l'e2e de placement. Il **réutilise** l'évaluateur v1 `lib/ai-lab.ts` (FK11) et **laisse** une phase stable où un besoin est placé, prêt à devenir une idée — la dent réelle restant le geste /goal (WB2-11).
