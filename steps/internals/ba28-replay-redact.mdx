## En une phrase

BA28 rend un `AgentRun` **rejouable à l'identique** (`Replay(run).ID == run.ID`, en réutilisant `records.Hash`) et son **transcript sûr à persister** : `Redact`/`RedactTranscript` caviardent un jeu **clos et déclaré** de motifs de secrets **avant** l'enregistrement (gap H1 : le ledger n'est pas un coffre à secrets). C'est la discipline replay-by-seed d'`evolve` descendue au grain d'un run d'agent, plus une rédaction déterministe.

## Implémentation

Le code vit dans `back/runtime/agentrun/replay.go` (les fonctions pures `Replay`/`Redact`) et `back/runtime/agentloop/replay.go` (le câblage `DriveReplayable` + le `RecordingGenerator`) ; le jumeau TS dans `front/web/lib/agentrun-redact.ts` ; le panneau dans `front/web/components/AgentsPanel.tsx` (sous-section `replay-redact`).

- **`Replay(run) → (AgentRun, error)`** (`agentrun/replay.go`) — re-dérive un run identique en reconstruisant le corps depuis ses champs déjà enregistrés (agent, goal, item, pack, seed, actions, result, timestamps, transcript-ref) et en re-stampillant l'id via le **même** recorder `Record` (donc `records.Hash ∘ Canonicalize`, RÉUTILISÉ, jamais forké). Pour tout run enregistré, `Replay(run).ID == run.ID`. Aucune horloge, aucun rng, aucun LLM — l'enregistrement porte déjà tout ce que l'adresse de contenu calcule. Un re-run vivant (re-injecter les réponses provider dans la boucle) est le terrain du `FakeGenerator` (BA17) ; `Replay` est la preuve bon marché, sans modèle, que l'enregistrement est interne-cohérent.
- **`ReplayMatches(run) → bool`** — le prédicat d'intégrité : le run re-dérive-t-il vers son propre id ? `true` ⇒ run fidèle ; `false` ⇒ un champ a été altéré après l'enregistrement (l'id n'adresse plus le corps) — le signal de falsification.
- **`Redact(s) → string`** — caviarde chaque motif de secret connu, chaque match → `REDACTED` (`"[REDACTED]"`). PURE, TOTALE, DÉTERMINISTE (même entrée ⇒ même sortie) et IDEMPOTENTE (`REDACTED` ne matche aucun motif, donc `Redact(Redact(s)) == Redact(s)`). Un texte propre ressort inchangé — seules les **formes de secret déclarées** sont touchées. Le jeu `secretPatterns` est **clos** : chaîne de connexion avec mot de passe (scrubée en premier, avant les motifs de jeton, pour ne pas matcher partiellement l'URL), en-tête PEM de clé privée, clés Anthropic (`sk-ant-…`/`sk-…`), jetons GitHub (`ghp_`/`gho_`/…), ids de clé d'accès AWS (`AKIA…`).
- **`RedactTranscript(tr) → Transcript`** — caviarde le prompt système ET chaque tour (toute la surface confinée) sans muter l'entrée. C'est la porte gap-H1 : elle tourne **avant** qu'un transcript ne soit persisté.
- **`SecretPatterns() → []string`** — les NOMS du jeu clos (pour l'audit / l'UI / le jumeau TS à single-sourcer).
- **`DriveReplayable(in) → (DriveReplayOutput, error)`** (`agentloop/replay.go`) — câble tout : lance la boucle BA27 (`DriveWithEconomics`), puis stampille sur le run l'**impl content-hash** (`agentimpl.Hash`, RÉUTILISÉ), le **seed résolu** (`agentrun.SeedFor` — déclaré-l'emporte, sinon dérivé `Hash(impl‖pack‖item)`), et un **ref content-adressé du transcript RÉDACTÉ** (`records.Hash ∘ Canonicalize` de `RedactTranscript(in.Transcript)`). Le run qui revient satisfait `Replay(run).ID == run.ID`. Pure, totale, déterministe ; aucun LLM vivant ; n'écrit aucune vérité.
- **`RecordingGenerator`** — enveloppe un `agentimpl.ActionGenerator` et **capture chaque réponse RÉDACTÉE** (au moment de la capture, donc le log ne porte jamais un secret en clair), pour qu'un replay re-injecte les réponses enregistrées plutôt qu'un modèle vivant. C'est le seul seam à état de la boucle — et il est sous la ligne, télémétrie.
- **Le jumeau TS** (`agentrun-redact.ts`) — `redact`/`redactTranscript` répliquent le **même** jeu clos de motifs ; `containsSecret` (le prédicat UI) ; `replayId(run)` (la re-dérivation via l'empreinte FNV-1a de `deriveSeed` — pas le SHA-256 Go, mais une empreinte stable côté UI) ; `replayMatches(run)` (re-dérive indépendamment de l'id stocké — l'id est le hash, pas une entrée).
- **Le panneau action-capable** (`replay-redact`) — bouton **Rédiger & rejouer** (`ba28-run`) : prend un transcript porteur de secrets (une URL `postgres://` avec mot de passe + une clé `sk-ant-…`), le caviarde, construit le run rejouable, le rejoue. L'écran rend le brut (`ba28-raw`), le rédacté (`ba28-redacted`, montrant `[REDACTED]`), le badge « aucun secret en clair » (`data-leaked=false`) et le badge « replay identique » (`data-matches=true`). Thémé (ADR 0010, tokens) + bilingue FR/EN (ADR 0011, next-intl).
- **Les miroirs** :
  - *Property replay + non-fuite* (`back/runtime/agentrun/replay_property_test.go`, N1, rapid) — (1) `Replay(run).ID == run.ID` pour tout run enregistré ; (2) replay idempotent (point fixe) ; (3) `Redact` ne laisse JAMAIS un secret connu en clair, pour tout texte environnant ; (4) `Redact` déterministe + idempotent ; (5) préserve le texte propre ; (6) `RedactTranscript` scrube système ET tours.
  - *Fixture agentloop* (`back/runtime/agentloop/replay_fixture_test.go`, N2) — (1) `DriveReplayable` stampille impl/seed/transcript-rédacté et le run rejoue (`Replay(run).ID == run.ID`) ; (2) le transcript enregistré est rédacté (aucun secret en clair) ; (3) déterministe (même entrée ⇒ même id + même rédaction) ; (4) `RecordingGenerator` capture des réponses rédactées.
  - *Reproductibilité fast-check* (`front/web/lib/agentrun-redact.test.ts`, N1) — secrets jamais en clair, rédaction déterministe + idempotente, texte propre préservé, jeu de noms clos, `redactTranscript` scrube toute la surface, `replayId` stable + id-indépendant, un champ replay change l'empreinte — 11 tests verts.
  - *E2e Playwright* (`tests/e2e/agents.spec.ts`, bloc BA28, N0) — contrôle présent ; un clic rédige + rejoue ; le brut contient `postgres://`, le rédacté montre `[REDACTED]` sans `hunter2`, `data-leaked=false`, `data-matches=true`.

## Méta

**Pourquoi ce pas existe, dans la logique KRD.** Le record existait (`agentrun.Record` content-adresse un run depuis S52, étendu par BA26 avec impl/seed/transcript), mais **rien ne le rejouait** et le transcript n'était pas protégé. BA28 ferme deux trous d'un coup :

- **Reproductibilité au grain du run (replay-by-seed, hérité d'`evolve`).** AIDOS exige « même entrée → même sortie » partout (determinism-first). `Replay` descend cette loi à l'`AgentRun` : il re-dérive l'adresse de contenu par la **même** fonction d'adressage que le recorder, donc un run fidèle re-dérive vers son propre id, et un run falsifié vers un autre. Le replay n'est pas un second algorithme « presque pareil » — c'est le **même** `records.Hash`, réutilisé, pour que la preuve soit exacte et non approximative.
- **Le ledger n'est pas un coffre à secrets (gap H1).** Un journal bit-reproductible de chaque run serait un **store de secrets durable** si le transcript (prompt système + ContextPack, donc potentiellement le code/env/secrets de l'app) y entrait tel quel. La rédaction tourne **avant** la persistance ; le replay ré-injecte depuis la **source confinée**, pas depuis le log. Le mur tient : un run reste sous la ligne, et même la trace qu'on en garde ne fuit aucune vérité confiée.

**Determinism-first appliqué à la rédaction.** Caviarder n'est PAS un jugement (« demande à un modèle de trouver les secrets »). C'est une **substitution déterministe** sur un jeu **clos et déclaré** de motifs structurels — donc du code, totalement reproductible, auditable (chaque motif a un nom), et idempotent. Un agent qui « déciderait » quoi rédiger serait un determinism gap. Le LLM n'a aucune place ici : la reconnaissance de motifs de secrets est une fonction pure.

**Le mur, encore.** `Replay` et `DriveReplayable` n'écrivent aucune vérité ; un `AgentRun` est de la télémétrie append-only sous la ligne, sans `version` ni `mirror` (la structure le rend irreprésentable en couche). La rédaction est une défense en profondeur ADDITIONNELLE : elle ne retire aucun garde-fou, elle en ajoute un (le journal ne porte pas de secret).

## Méta-méta

**Ce que BA28 dit du système qui se construit lui-même.** Un harnais qui code des apps doit pouvoir **se relire** : auditer un run passé, prouver qu'il s'est bien passé ce qui est enregistré, sans rejouer un modèle coûteux ni faire confiance à un log volumineux. `Replay` rend l'auditabilité **bon marché et exacte** — l'adresse de contenu EST la preuve d'intégrité. C'est la même idée que le content-addressing du kernel (un hash atteste un corps), portée à la télémétrie d'exécution.

**La rédaction est une frontière de confiance, pas une commodité.** En séparant ce qu'un run *fait* (reproductible, gardé) de ce qu'un run *a vu* (confiné, jamais gardé en clair), BA28 trace une ligne nette entre le **journal auditable** et le **secret confié**. Cette séparation est exactement ce qui distingue un OS gouverné d'un agent à qui « on fait confiance » : la confiance n'est jamais déclarée, elle est **structurellement empêchée de fuiter**. Le prochain pas (BA29, l'effect-log réconcilié à la frontière) s'appuie là-dessus : prouver que le run *réel* matche le record, pas seulement que le record re-dérive — la complémentarité d'un replay (le record est cohérent) et d'un effect-log (le réel correspond au record).

**Pourquoi le replay sans LLM compte.** Que le replay soit **model-free** est un choix de gouvernance : un audit qui dépendrait d'un appel modèle serait ni déterministe, ni gratuit, ni reproductible dans le temps (le modèle change). En re-dérivant depuis les inputs enregistrés (+ les réponses provider rédactées que le `RecordingGenerator` a capturées), AIDOS garantit qu'un run d'il y a six mois se rejoue **aujourd'hui, à l'identique, sans réseau** — la reproductibilité comme propriété durable, pas comme effet de bord d'une infra vivante.
