## Implémentation

**Le twin de liens `lib/v2/links.ts`** — la source unique de la LOGIQUE, PUR (aucun React/DOM, aucun LLM, aucune horloge, aucun aléa) :

- Le **jeu clos** `LINK_KINDS` : `composes`, `depends_on`, `supersedes`, `provenance`, `triggers_binds`, `mirrors` (les six familles §17/§41, libellés lisibles côté V2) + `isKnownKind`.
- `kindToCanon(kind)` : le **mapping vers le jeu canonique S17** (`lib/links.ts`, la source) : `composes→projects_to`, `depends_on→contracts_with`, `supersedes→derives_from`, `provenance→derives_from`, `triggers_binds→triggers+binds`, `mirrors→mirrors`. Une famille peut mapper plusieurs kinds canoniques (triggers_binds). Le jeu reste clos.
- Types : `Ref` (`id`, `version` — la **ref pinnée** `id@version`) ; `Link` (`kind`, `from`, `to`) ; `LinkGraph` (`nodes`, `links`).
- `isPinned(r)` : `id` ET `version` non vides (une **identité nue** n'est pas une cible valide §41). `refString(r)` : la forme canonique `id@version`.
- `validate(l)` : le garde de forme PUR (miroir de S17 `links.validate`) — renvoie une chaîne d'erreur si (`kind` hors jeu clos) ∨ (`from` non pinné) ∨ (`to` non pinné), `""` si valide. Un `to` non pinné est lui-même un **monstre** (§41).
- `allLinksPinned(graph)` : le graphe est-il TOTALEMENT pinné ? (tout lien pointe une version, jamais une identité).
- `filterByKind(graph, kind)` : le **filtre** — un sous-graphe avec UNIQUEMENT les liens de cette famille (tous les nœuds conservés, pour le repère). Total : un kind inconnu rend un graphe **sans lien** (jamais une erreur).
- `countByKind(graph)` : le compte par famille (clés = le jeu clos).
- `syntheticLinkGraph()` : le **graphe canonique** déterministe (huit kernels pinnés `@vN`, huit liens couvrant les six familles, chaque cible pinnée). Aucun aléa, aucune horloge ; ids lisibles pour l'écran et l'e2e. OpenQuestion documentée : synthétique tant que le store ne sert pas les liens live — ne bloque pas (forward-dependency).

**L'écran `app/v2/liens/LinksClient.tsx`** (`"use client"`) : `useMemo` appelle `syntheticLinkGraph()` + `countByKind`. État local `activeKind` (`null` = toutes les familles). Le sous-graphe affiché vient de `filterByKind(graph, activeKind)` — **le filtre est computé par le twin pur, jamais à l'écran**. Rendu en **React Flow** (`@xyflow/react`, ADR 0053) : un nœud custom `KernelNode` (`v2-liens-node-<id>-<version>`, l'`id` + sa `@version`), positionné déterministiquement (grille fixe par index). Les arêtes portent le libellé de famille, colorées par famille (tokens ADR 0010, jamais de hex en dur). Le canvas (`v2-liens-canvas`) a `panOnDrag`, `zoomOnScroll`, `zoomOnPinch` + les `<Controls/>`. La **barre de filtres** (`v2-liens-filter`, un `<fieldset>` pour l'a11y) : un bouton « toutes » (`v2-liens-filter-all`) + un bouton par famille (`v2-liens-filter-<kind>`, `aria-pressed`, le compte). `onEdgeClick` ouvre un détail (`v2-liens-edge-detail` : `v2-liens-detail-kind`, from, `v2-liens-detail-to` = la cible PINNÉE `id@version`, le kind canonique via `kindToCanon`, `v2-liens-detail-pinned`, `v2-liens-detail-readonly`). Le résumé (`v2-liens-summary`, `data-node-count`, `data-link-count`).

**La page `app/v2/liens/page.tsx`** (Server Component) : assemble les chaînes du namespace i18n `v2Liens` (FR + EN) + les libellés localisés de chaque famille (le jeu clos `LINK_KINDS`), rend titre / sous-titre / note-du-mur (`v2-liens-wall-note`), puis `<LinksClient/>`. Nouvelle route — aucune route existante touchée.

**La correction de routage `[slug]`** : `liens` est le **seul slug du glossaire** qui reçoit un écran dédié (les autres écrans — dag, grille, anatomie — ne sont pas des slugs de glossaire). Le catch-all `app/v2/[slug]/page.tsx` générait statiquement `liens` via `generateStaticParams`, créant une ambiguïté avec la route dédiée. Correction additive, non-régressante : `DEDICATED_SLUGS = {"liens"}` est **exclu** de `generateStaticParams` ∧ un accès au catch-all sur un slug dédié → `notFound()`. La route statique `liens/` prime ainsi sans ambiguïté.

**Les miroirs** :

- Reproductibilité — `lib/v2/links.test.ts` (Vitest + fast-check) : **pinning §41** (`validate` accepte ssi `kind ∈ jeu clos ∧ from,to pinnés`) ; **un `to` nu est toujours refusé** (jamais évalué comme valide) ; le **graphe canonique est totalement pinné** (`allLinksPinned`, chaque lien valide, les six familles présentes) ; **filtre = sous-ensemble exact** (tous les liens du filtre, eux seuls ; nœuds conservés ; la somme des filtres = tous les liens, partition exacte) ; **jeu clos** (filtrer un kind inconnu rend zéro lien, jamais une erreur) ; **déterminisme** (même graphe → même sérialisation, même filtre, même compte) ; **kindToCanon** (chaque famille mappe ≥1 kind canonique ; triggers_binds → triggers+binds) ; `refString`. GREEN (8 tests).
- e2e — `tests/e2e/v2-liens.spec.ts` (Playwright) : **filtre par type d'arête** (le critère de done — « composes » → 3 arêtes, « mirrors » → 1 arête, retour « toutes » → 8 ; `.react-flow__edge` compté) ; les **six familles** présentes comme filtres ; **action-capable** (clic d'un lien → détail avec la cible pinnée `@`) ; **pan/zoom** (`.react-flow__controls`, clic zoom-in) ; **bas read-only** (aucune requête POST/PUT/PATCH/DELETE) ; **déterministe** (mêmes comptes nœuds/liens au rechargement). GREEN (2 tests). Non-régression WB2-05/06/07 (`v2-grille`, `v2-anatomie`, `v2-dag`) GREEN (6 tests).

## Méta

- **Déterminisme-first.** Aucun agent ne valide un lien, ne filtre le graphe, ni ne mappe une famille : `validate`, `filterByKind`, `kindToCanon` sont des fonctions **pures et autoritatives**, et le miroir fast-check épingle leurs invariants. Le filtre par famille — l'action centrale de l'écran — est `filterByKind`, un `Array.filter` pur ; l'écran ne fait que **rendre** le sous-graphe qu'il reçoit.
- **Le pinning, prouvé comme un invariant.** « Tout lien pointe une version, jamais une identité nue » (§41) n'est pas une intention : c'est une **property** (`validate` refuse tout `to` non pinné, sur l'ensemble du domaine généré ; le graphe canonique est totalement pinné). C'est ce pinning qui rend la vague de rouge (§42) **calculable** — un lien sait vers quelle version il pointait, donc sait quand elle n'est plus la tête.
- **Le filtre est une partition exacte.** Le miroir vérifie que la somme des sous-graphes filtrés = tous les liens (aucune perte, aucune duplication), et qu'un kind inconnu rend zéro lien sans jamais lever d'erreur. Le filtre est **total** et **réversible** — une propriété, pas une espérance.
- **Le bas read-only, prouvé.** L'e2e surveille le réseau : naviguer, filtrer, zoomer, cliquer un lien, lire sa cible — **aucune écriture ne part**. Le mur (§2) est un invariant vérifié.

## Méta-méta

- **Le réseau typé est la grammaire des relations.** Réduire toute relation entre kernels à **six familles closes** (et pas une de plus) est un acte de discipline : c'est refuser le lien fourre-tout. Chaque famille a une **sémantique** (composition ≠ dépendance ≠ généalogie ≠ provenance ≠ déclenchement ≠ miroir) qui dit **comment** la propagation traverse. Le jeu clos est ce qui rend le graphe **analysable** — on peut raisonner sur « tous les `composes » sans craindre un septième type caché.
- **Le pinning fait du changement une onde.** Sans `@version`, un changement est un événement local invisible en aval. Avec le pinning, chaque changement de tête **propage** une vague qui s'allume en rouge là où un consommateur pointait l'ancienne version (§42). WB2-08 ne calcule pas encore la vague — il pose son **substrat** : le lien typé et pinné. Voir les liens, c'est voir **où une onde pourra passer**.
- **Une seule source, deux vocabulaires.** Le twin V2 (`lib/v2/links.ts`) porte les libellés lisibles (composes, depends_on…) mais `kindToCanon` les rattache au jeu canonique S17 (projects_to, contracts_with…). Le concept reste **un**, exprimé en deux vocabulaires alignés par une table pure — jamais deux vérités divergentes. Le jour où le store sert les liens live, seule change *l'origine* du graphe (`syntheticLinkGraph` → le store), pas *comment* il se valide, se filtre ou se compte.

## Place dans le cliquet KRD

WB2-08 est une **dent du cliquet de l'outil** : il **lit** les liens entre vérités gelées (les six familles §17/§41) et n'en écrit aucun. Sa construction a cliqueté red → green — le miroir `lib/v2/links.ts` (fast-check : tout lien pointe une **version**, jamais une identité nue §41 ; filtre = sous-ensemble exact ; déterminisme) rouge d'abord, puis vert, plus l'e2e du filtre par type. Le pinning qu'il prouve est **ce qui rend le cliquet sûr** : parce que chaque lien pointe une version précise, la vague de rouge (§42, WB2-17) est calculable — un lien sait quand sa cible n'est plus la tête. Il **consomme** le DAG de WB2-07 et **laisse** un graphe de liens totalement pinné, substrat de la propagation d'impact.
