## Implémentation

**Le twin de policy `lib/v2/policy.ts`** — la source unique de la LOGIQUE, PUR (aucun React/DOM, aucun LLM, aucune horloge, aucun aléa), bâti par **réutilisation** de l'évaluateur S09 `lib/policy.ts` (lui-même miroir du Go `back/kernel/policy`) :

- **Réutilise & ré-exporte** (depuis `../policy`, S09) : les types `Rule`, `RuleKind` (les huit kinds `all/any/not/eq/gt/lt/exists/matches`), `Scope` (`RESOURCE/OPERATION/ENTITY/FIELD`), `Effect`, `Decision`, `Operand`, `Policy`, `CtxData`, `PolicySample` ; les valeurs `RULE_KINDS`, `SCOPES`, `SAMPLES`, l'ancrage `CAN_PLACE_ORDER` (§93, verbatim) ; et les fonctions `holds(rule, ctx)` / `evaluate(policy, ctx)` — la **sémantique de vérité**. WB2-14 n'invente AUCUNE règle ni sémantique ; il réutilise l'évaluateur déterministe existant.
- `ruleLabel(r)` : le libellé une-ligne d'une règle (le combinateur, ou la feuille « gauche op droite », `exists(sel)`, `matches(sel, motif)`).
- `evalTree(rule, ctx)` : **le cœur neuf**. Renvoie un `TracedNode` (`id`, `kind`, `label`, `held`, `children`) — un arbre PARALLÈLE à la règle où chaque nœud porte son verdict `held = holds(n, ctx)` (donc la trace est COHÉRENTE avec l'évaluateur de vérité, jamais une sémantique parallèle). Les ids sont content-adressés par position : racine `p0`, enfants `p0.0`, `p0.1`, … → uniques, stables, déterministes. PURE & TOTALE.
- `arboristTree(rule, ctx?)` : projette vers la forêt `ArboristNode[]` (`{id, name, kind, held?, children?}`) que React Arborist consomme. **Sans `ctx`** : la structure seule (pas de `held`, déplier l'arbre). **Avec `ctx`** : dérivée de `evalTree`, chaque nœud porte son `held`. `children` est OMIS pour une feuille (convention React Arborist). PURE & déterministe.
- `nodeCounts(rule)` : `{combinators, leaves, total}` — combinateurs vs feuilles.
- Registre CLOS `POLICIES` : `canPlaceOrder` (= `CAN_PLACE_ORDER`, l'ancrage §93 — un `all` de trois feuilles, scope OPERATION, effet ALLOW) + `denySecretField` (`DENY_SECRET_FIELD` — un `any` de deux feuilles `matches`/`eq`, scope **FIELD**, effet **DENY** — couvre any + un autre scope sans rien inventer hors grammaire). Routage : `policySlug(name)` (slug = nom, pas de `/`), `policyBySlug(slug)` (undefined pour un inconnu → 404, totalité), `policySlugs()`.
- `samplesFor(name)` : les contextes d'exemple — réutilise les `SAMPLES` S09 pour `canPlaceOrder` (les lignes-miroir de la fixture Go : ALLOW connecté/panier non vide, DENY pas connecté, DENY panier vide) ; deux contextes FIELD pour `denySecretField` (champ secret → DENY, champ ordinaire → ALLOW). `decisionFor(name, ctx)` : la décision via `evaluate`. `STEP_SLUG = "wb2-14-policy"`.

**Le client `app/v2/policy/PolicyClient.tsx`** (`"use client"`) :

- État `selectedId` (l'échantillon choisi, `null` = structure seule). L'arbre `forest = arboristTree(policy.rule, selected?.ctx)` ; la décision `decision = selected ? evaluate(policy, selected.ctx) : null`.
- L'**en-tête** : `scope`, `target`, `effect` (badge ALLOW `--primary` / DENY `--destructive`), `nodeCounts`. Tokens CSS (ADR 0010), jamais de hex.
- L'**évaluation** (l'action) : un bouton par échantillon (`v2-policy-sample-<id>`) qui `setSelectedId` → l'arbre est tracé et la décision (`v2-policy-decision`, `data-decision`) s'affiche.
- L'**arbre** : `<Tree<ArboristNode>>` de `react-arborist` (`idAccessor="id"`, `childrenAccessor="children"`, `openByDefault`). Chaque ligne `PolicyRow` : caret déplier/replier (`node.toggle()`), un badge `kind`, le `name`, et — quand évalué — le verdict (`data-held` true/false, classe `--primary` HOLD / `--destructive` FAIL, libellé TIENT/ÉCHOUE). `data-testid` par nœud (`v2-policy-node-<id>`, `v2-policy-toggle-<id>`).
- Une **légende** (all/any/not/feuille).

**Les pages** : `app/v2/policy/page.tsx` (l'index — liste `POLICIES`, badge ALLOW/DENY, `nodeCounts`, lien vers `[policy]`), `app/v2/policy/[policy]/page.tsx` (résout `policyBySlug`, `notFound()` sur slug inconnu, `generateStaticParams` = `policySlugs()`, charge `samplesFor`, passe les strings i18n au client + l'en-tête scope/target/effet/wall-note). Namespace bilingue `v2Policy` (FR + EN), ADR 0011.

## Méta

- **Determinism-first (CLAUDE.md §6/§8).** Tout est fonction pure : l'évaluation tracée (`evalTree`), la projection (`arboristTree`), le décompte (`nodeCounts`), le routage (`policySlug`/`policyBySlug`), la décision (`evaluate`) — code, jamais LLM. React Arborist n'est que du **rendu** ; il ne juge rien. Le miroir de reproductibilité (`lib/v2/policy.test.ts`, fast-check + fixtures, 19/19) épingle : déterminisme (deux évaluations identiques), trace cohérente avec `holds` (racine ET récursivement), ids content-adressés uniques, la **loi §93 — DENY DOMINE** (property : effet DENY ⇒ décision == DENY ⇔ règle tient), les combinateurs (property : `all.held == ∧` des enfants, `any.held == ∨`), `not` **involution** (property : `not(not(r)).held == r.held`), bijection slug↔nom, ensembles clos des scopes/règles.
- **Réutilisation, pas de fork (ADR 0007).** Le twin ne réimplémente PAS la sémantique : `holds`/`evaluate`/les sélecteurs $-enracinés/la loi de combinaison viennent de `lib/policy.ts` (S09 → Go `back/kernel/policy`). WB2-14 n'ajoute QUE la **trace** (`evalTree`, le `held` par nœud) et la **projection** (`arboristTree`). Une seule vérité d'autorisation, deux étapes de présentation.
- **Le mur (§2).** Afficher + évaluer = LECTURE. L'évaluation est une fonction pure d'un échantillon ; aucune route d'écriture n'existe, aucun POST/PUT/PATCH/DELETE. L'e2e surveille le réseau et exige zéro écriture. La policy (l'AST) reste écrite seulement par le CLI via un ChangeSet approuvé.
- **WB2-13 vs WB2-14.** WB2-13 = le **flux** d'un scénario (le pipeline branché étape/gate/décision). WB2-14 = la **règle** d'autorisation (l'arbre récursif all/any/not). Le `gate` de WB2-13 est précisément le point où une policy WB2-14 décide. Additif (anti-overwrite §9), deux concepts distincts de la verticale.

## Méta-méta

- **Pourquoi un arbre tracé séparé (`evalTree`) plutôt qu'évaluer à la volée dans le rendu ?** Parce que l'évaluation est une **donnée**, pas un effet de bord du rendu. En matérialisant l'arbre tracé (un `TracedNode` par règle, avec son `held`), on le rend **testable seul** (sans DOM, fast-check), **déterministe** (ids content-adressés), et **cohérent par construction** avec `holds`. React Arborist n'a plus qu'à colorier une donnée déjà jugée — le verdict ne dépend jamais de l'ordre de rendu.
- **Pourquoi réutiliser `holds` au lieu de réécrire la récursion dans `evalTree` ?** Pour qu'il n'existe **qu'une** définition de « la règle tient ». Si `evalTree` réimplémentait la combinaison, on aurait deux sémantiques à garder synchrones — une porte ouverte aux divergences (le piège exact que la loi §8 « le juge est déterministe, une seule vérité » interdit). Le test « la racine tracée == `holds(rule, ctx)` » verrouille cette unicité, à chaque nœud.
- **Pourquoi `denySecretField` en plus de l'ancrage §93 ?** Parce que `canPlaceOrder` ne couvre qu'un `all`/effet ALLOW/scope OPERATION. Pour montrer **l'autre sens de la loi** (le DENY qui domine) et **un autre combinateur** (`any`) sur **un autre scope** (FIELD) avec `matches`, il fallait une seconde policy — mais STRICTEMENT dans la grammaire close existante (aucune règle inventée). C'est l'illustration minimale qui rend la propriété « DENY domine » lisible à l'écran, pas seulement dans le test.
- **La limite assumée (OpenQuestion).** Les policies de l'écran sont un **registre statique** (l'ancrage §93 + un exemple), pas encore une lecture live de `kernel.policy`. C'est la même frontière que les autres écrans V2 : la projection réelle arrivera quand le store de policies exposera son SELECT (rôle lecture seule) ; les contextes d'évaluation restent des échantillons déclarés, jamais des données de production. Par conception (le mur) — l'écran évalue, il n'écrit ni ne lit la vérité de prod.

## Place dans le cliquet KRD

WB2-14 est une **dent du cliquet de l'outil** : il **évalue** une policy gelée (la grammaire close all/any/not, §93) sur un contexte échantillon et trace le verdict, sans écrire aucune vérité. Sa construction a cliqueté red → green — le miroir `lib/v2/policy.ts` (fast-check : DENY domine, `not` involution, combinateurs ∧/∨, la racine tracée == `holds(rule, ctx)`) rouge d'abord, puis vert, plus l'e2e d'évaluation. Il **réutilise sans forker** l'évaluateur S09 `lib/policy.ts` (`holds`/`evaluate`) — une seule définition de « la règle tient », exactement ce que §8 (« le juge est déterministe ») exige — et **laisse** une phase stable où une policy est inspectable nœud par nœud, colorée HOLD/FAIL. La projection des vraies policies du kernel reste, par conception, derrière le SELECT lecture-seule à venir.
