## Implémentation

### Deux paquets, additifs (le mur §9)

La généralisation ajoute **deux** plans, **strictement additifs** (anti-overwrite §9 — aucun fichier existant cassé) :

- **(A) l'ÉMETTEUR** — `back/runtime/honoemit/pulumi_stack.go` (nouveau, ~360 lignes, écrit **après** le miroir) + `back/runtime/honoemit/pulumi_stack_test.go` (le miroir, **7** tests `TestStack_*`). `back/runtime/honoemit/honoemit.go` est **édité** de façon purement additive : `const TargetPulumiScaffold = "pulumi-scaffold"`, `var ErrNoEnv`, et `targetOrder` grossi.
- **(B) l'EXÉCUTEUR** — `back/cmd/aidospulumi/main.go` (nouveau, ~330 lignes) + `back/cmd/aidospulumi/main_test.go` (le miroir de matérialisation, **8** tests, `pulumi` **non** exécuté).

### `EmitPulumiStack` — la projection pure (l'émetteur)

```go
func EmitPulumiStack(project, env string, m StackManifest) ([]Artifact, *blockreason.BlockReason)
```

Elle retourne **3 Artifacts** en ordre **path-trié FIXE** (donc le slice lui-même est byte-stable), tous sous `gen/<project>/infra/` :

- **`Pulumi.yaml`** (`TargetPulumiScaffold`) — `name: <project>-<env>`, `runtime: nodejs` ;
- **`index.ts`** (`TargetPulumiProgram`) — le programme gold-form : `export function program(){…}` + `export const resources = program();` + `export const url` ;
- **`package.json`** (`TargetPulumiScaffold`) — deps `@pulumi/docker` + `@pulumi/pulumi` épinglées.

Les trois sont **content-adressés** par `stackSourceHash(project, env, manifest)`, qui **réutilise** `records.Hash` + `records.Canonicalize` (S02, **non forké**) sur le corps canonique du manifest préfixé par l'identité du stack. Une entrée malformée est un **`BlockReason` typé** (`ErrNoProject`, `ErrNoEnv`, manifest invalide), **jamais** un rendu partiel.

### La forme GOLD produite (fidèle à la preuve manuelle)

L'`index.ts` émis reproduit **exactement** la mécanique du GOLD `.deploy-pulumi/demoshop-dev/index.ts` (validé syntaxiquement TS via `node --experimental-strip-types --check`), généralisée par projet×env :

```text
RemoteImage{keepLocally:true}   par image DISTINCTE (canonical sorted) — ne purge jamais les bases partagées
réseau EXTERNE                  networksAdvanced:[{name:"traefik_default"}] inline — JAMAIS new docker.Network
                                (un réseau NON-externe, lui, EST créé : new docker.Network)
docker.Volume                   <project>-<env>-<vol> + le mount sur le datastore
datastore                       POSTGRES_DB/USER/PASSWORD + healthcheck pg_isready (interval/timeout/retries)
serveur (env)                   DATABASE_URL=postgres://app:<proj>@<stack>-db:5432/<proj>?sslmode=disable
serveur (labels Traefik COMPLETS)
   traefik.enable=true
   traefik.http.routers.<stack>.rule         = Host(`<stack>.sagedesk.fr`)
   traefik.http.routers.<stack>.priority     = 1000   ← SUPERSEDE le placeholder wildcard *-dev
   traefik.http.routers.<stack>.entrypoints  = websecure
   traefik.http.routers.<stack>.tls          = true
   traefik.http.routers.<stack>.tls.certresolver = le
   traefik.http.services.<stack>.loadbalancer.server.port = <internal_port>
nommage                         conteneurs <project>-<env>-<service> ; volume <project>-<env>-<vol> ; stack <project>-<env>
```

Les constantes gelées (`stackDomainSuffix = "sagedesk.fr"`, `certResolver = "le"`, `serverRouterPriority = "1000"`, `pgUser = "app"`) sont celles que la preuve a établies — la convention `/data/dockers` + Traefik.

### `aidospulumi` — l'exécuteur gaté

```text
aidospulumi up   --project <p> --env <e> [--root <repo>]
aidospulumi down --project <p> --env <e>
```

`up` fait, dans l'ordre : (a) **matérialise** `index.ts` / `Pulumi.yaml` / `package.json` dans `<root>/.deploy-pulumi/<project>-<env>/`, **byte-identiques** à `EmitPulumiStack` ; (b) `npm install` si `node_modules` absent ; (c) `pulumi login file://$HOME/.pulumi-aidos-state` ; (d) `pulumi stack select --create <project>-<env>` ; (e) `pulumi up --yes`. Il imprime un `UpResult{status, stack, dir, url, containers}` **JSON sur stdout** (le bruit pulumi/npm part sur stderr, stdout reste du JSON propre). `down` fait `login` + `stack select` + `pulumi destroy --yes`.

`PULUMI_CONFIG_PASSPHRASE=aidos` est forcé, le `PATH` est augmenté de `~/.pulumi/bin`, et un binaire `pulumi` **manquant** est une **erreur actionnable** (indice install/PATH), **jamais** un panic. `AIDOS_REPO` surcharge la racine par défaut `/data/dev/aidos`.

L'API Go testable (effets isolés) : `Materialise(root, project, env) → (Materialised, error)` [écriture disque **PURE**, **pas** de pulumi] ; `PulumiUp(Materialised) → (UpResult, error)` ; `PulumiDown` ; `urlFromProgram([]byte) → string` (lit l'`export const url` du programme émis).

### `defaultManifest` — la topologie GOLD par défaut

`up`/`down` lisent `defaultManifest(project)` : la topologie GOLD-prouvée (app `aidos-app:latest` serveur `:8080` + db `postgres:16-alpine` `:5432`, volume pgdata, réseau **EXTERNE** `traefik_default`) paramétrée par projet — **un stack par projet×env**. Quand le read-path `stack_manifest` du kernel (DP02) existera, l'exécuteur lira le manifest du projet depuis la **vérité** (forward dep documentée inline).

## Méta

- **Le miroir émetteur est l'épreuve « même manifest+env ⇒ programme byte-identique », ∀.** `TestStack_ByteIdentical` épingle le cœur déterministe : deux émissions du même `(project, env, Canonicalize(manifest))` produisent des octets **identiques**, et l'ordre des services dans le manifest n'y change rien (canonical sorted). `TestStack_FN02Pure` épingle que le programme émis n'a **aucun** `let`/`var` module-scope (le mandat FN02 / `EMITTED_NO_GLOBAL_MUTABLE` gouverne l'infra émise comme l'app). `TestStack_GoldForm` pin les **exigences découvertes** par la preuve : `priority=1000`, `tls.certresolver=le`, `Host(<stack>.sagedesk.fr)`, l'attache au réseau externe **sans** création, les envs/healthcheck/volume/naming, les `RemoteImage`. Que l'émetteur soit une fonction pure plutôt qu'un agent qui « génère » du Pulumi n'est pas une promesse — c'est une propriété **prouvée**.

- **Les exigences découvertes — `priority=1000` vs le wildcard dev-preview.** La preuve manuelle a révélé ce que l'émetteur DP03/DP05 d'origine ne produisait pas : (1) un placeholder wildcard (`aidos-dev-preview`, `HostRegexp *-dev.sagedesk.fr`) capte la requête **avant** le routeur du projet — d'où `traefik.http.routers.<stack>.priority=1000` qui le **prime** ; (2) `Network.External=true` ⇒ on **attache** (`networksAdvanced name=traefik_default`), on ne **crée** pas ; (3) le jeu de labels Traefik **complet** ; (4) env `DATABASE_URL` pointant le datastore par son nom de conteneur + volume + healthcheck ; (5) le nommage par projet×env ; (6) `RemoteImage{keepLocally:true}` par image. Chacune est désormais **codée + pinnée** par le miroir.

- **Déterminisme-first (§6/§8) : émettre est une fonction, exécuter est un geste.** La frontière est tracée à la ligne. L'**émetteur** (`EmitPulumiStack`) est du **code pur** — aucun LLM n'écrit le programme Pulumi, jamais. L'**exécuteur** (`aidospulumi`) **n'invente rien** : il matérialise les octets de l'émetteur puis pilote `pulumi`, exactement comme `docker compose up -d` dans `ai-lab/actions.ts:deployStack`. Le miroir de l'exécuteur ne teste que `Materialise` (l'écriture disque pure) — le `pulumi up` side-effectant est le geste gaté, hors du jugement. L'agent écrit le code d'infra **au build** ; il n'est **jamais** dans la boucle runtime.

## Méta-méta

- **Une seule SOURCE, N cibles — le compose reste une projection dérivable (le mur §2/§9).** Le `StackManifest` AST (au-dessus du mur, content-adressé) reste la **seule vérité**. Le programme **Pulumi/TS** (cette cible) **et** le **`docker-compose`-emit** (DP03/DP05) sont **deux projections déterministes** de cette même source — aucune n'écrit de vérité (`gen/<project>/infra/` est du below-the-line), aucune ne supplante l'autre. C'est l'anti-overwrite (§9) tenu : on **ajoute** deux paquets, on **n'altère** ni `pulumi.go` (`EmitPulumiProgram` reste **byte-stable** pour le preview/DP25), ni un fichier front (vitest 2309 + e2e **inchangés**). L'agent n'a aucun GRANT pour graver une vérité, et la seule porte vers le kernel reste idée → mirror → `/goal` → approbation humaine.

- **ADR 0043 amendé à deux têtes — réconcilié avec SPEC-stack-2026.** L'addendum 2026-06-13 confirme la décision sans rien effacer : la cible self-hosted **actuelle** est Pulumi + `@pulumi/docker` **par projet** (preuve `demoshop-dev` live), le `docker-compose`-emit reste une **projection dérivable** de la même source, et `future_cloud` (DP33) est Pulumi avec un provider **cloud** — le **même** programme.
