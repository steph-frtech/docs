## En une phrase

BA29 prouve la **fidélité-à-la-réalité** d'un run (gap H2) : un **effect-log indépendant** (`runtime.agent_effect`) capture chaque écrit FS et chaque appel MCP **à la frontière** (pas par l'auto-rapport de la boucle), et `Reconcile` le diffe contre les actions enregistrées. Un run est **auditable** ssi il **se re-dérive** (replay BA28) **et** **réconcilie** (effets BA29) — `replay-equality + réconciliation-effets ensemble = auditable`.

## Implémentation

Le moteur pur vit dans `back/runtime/agentloop/ledger.go` ; la persistance dans `back/migrations/agent_effect_log_baseline.sql` ; l'outil MCP dans `back/mcp/agentloop/ledger.go` ; le jumeau TS dans `front/web/lib/agentloop-ledger.ts` ; le panneau dans `front/web/components/AgentsPanel.tsx` (sous-section `ledger`).

- **`Effect{Run, Kind, Target}`** — un effet de bord **témoigné à la frontière**, indépendamment du self-report de la boucle. `Kind` est clos : `fs_write` (le FS a vu une écriture) | `mcp_call` (le transport MCP a vu un appel sortant). Un *read* ne produit aucun effet observable ; seules les mutations et les appels sortants en sont.
- **`Reconcile(run, effects) → Reconciliation`** — diffe PUREMENT les actions du run contre l'effect-log de ce run : apparie chaque action **mutante autorisée** (`mutatesBoundary` : `write` ∧ `autorisee`) à un effet `(kind,target)` correspondant, via un **multiset** de `(kind,target)` restants. Toute action non appariée ⇒ `Drift{unrealised_action}` ; tout effet restant ⇒ `Drift{unrecorded_effect}` (émis en ordre stable : target puis kind). `Reconciled` ssi zéro dérive. Une action **refusée** (`autorisee=false`) n'a jamais atteint la frontière, donc n'attend **aucun** effet — c'est essentiel : le mur stoppe avant l'effet.
- **`QueryLedger(runs, effects, filter) → Ledger`** — filtre les runs (`LedgerFilter{Agent, Goal, Result}`, champ vide = wildcard), calcule pour chacun `ReplayMatches` (BA28, réutilisé), `Reconcile`, et `RefusalsByCode` (somme des actions `autorisee=false` portant une `BlockReason`, par code S13) ; `Auditable = ReplayMatches ∧ Reconciled` ; agrège `TotalRefusals`. Entrées triées en ordre **stable** (`StartedAt` puis id). PURE, TOTALE — aucune horloge, aucun I/O, aucun LLM.
- **`runtime.agent_effect`** (migration) — `(id, run, kind, target)`, `kind` contraint à `{fs_write, mcp_call}`, index sur `run`. `run` n'est **pas** une FK : un effet peut être témoigné pour un run que l'agent n'a jamais inséré (exactement le cas de fidélité — un effet attribué à un run qui n'a rien déclaré). Sous la ligne (aucun `version`, aucun `mirror`). GRANTs : `aidos_agent` et `aidos` ont `SELECT, INSERT` ; `UPDATE/DELETE/TRUNCATE` REVOQUÉS (append-only : un effet, une fois témoigné, n'est jamais altéré — l'audit est tamper-evident).
- **L'outil MCP `agentloop_ledger`** (`back/mcp/agentloop/ledger.go`, ADR 0009 — un tool = un op) — ajouté au serveur agentloop existant (BA19). Dérive des runs déclarés (faithful / refused / betrayed) + un effect-log fixture déclaré, appelle `QueryLedger` (l'autorité), et rend le ledger. `wrote_truth` toujours `false` (le mur : lecture seule).
- **Le jumeau TS** (`agentloop-ledger.ts`) — `reconcile`/`queryLedger`/`refusalsOf` répliquent le même diff déterministe ; réutilise `replayMatches` (BA28) et le code `AGENT_WRITE_ABOVE_WATERLINE`. Le multiset est une `Map<"kind target", n>` ; les dérives restantes sont triées (target puis kind).
- **Le panneau action-capable** (`ledger`) — bouton **Interroger le ledger** (`ledger-run`) : construit trois runs (un *faithful* auditable, un *refused* compté/réconcilié, un *betrayed* avec un effet `/tmp/exfil.sh` non enregistré) + l'effect-log, appelle `queryLedger`, rend une table une ligne/run (`ledger-row-<id>`, attributs `data-auditable` / `data-reconciled`), la dérive (`ledger-drift-<id>`), le verdict (`ledger-verdict-<id>`), et les refus par code (`ledger-refusal-<code>`). Thémé (ADR 0010, tokens) + bilingue FR/EN (ADR 0011, next-intl).
- **Les miroirs** :
  - *Persistance Testcontainers* (`back/runtime/agentloop/effect_log_roundtrip_test.go`, N5, vrai Postgres) — roundtrip lossless d'un effet ; le CHECK refuse un `kind` hors enum ; **réconciliation sur des lignes réelles** (un run fidèle réconcilie, un effet `/tmp/exfil.sh` lu depuis Postgres casse la réconciliation) ; le mur append-only (`SET ROLE aidos_agent` : INSERT OK, UPDATE/DELETE refusés).
  - *Fixture ledger* (`ledger_fixture_test.go`, N2) — run fidèle auditable ; effet non enregistré ⇒ non auditable alors que `ReplayMatches` reste vrai (le replay seul rate la brèche) ; action non réalisée ⇒ drift ; écriture refusée comptée mais pas attendue ; filtre + ordre stable.
  - *Property rapid* (`ledger_property_test.go`, N1) — Reconcile/Query reproductibles ; faithful ⇒ réconcilié ; un effet extra casse TOUJOURS ; refus jamais attendus ; auditable ⇒ réconcilié.
  - *Reproductibilité fast-check* (`agentloop-ledger.test.ts`, N1) — 10 tests verts (mêmes invariants côté UI).
  - *E2e Playwright* (`tests/e2e/agents.spec.ts`, bloc BA29, N0) — un clic rend la table ; le faithful `data-auditable=true`, le betrayed `data-auditable=false` + drift `/tmp/exfil.sh` + verdict « non auditable » ; le refus `AGENT_WRITE_ABOVE_WATERLINE` rendu avec sa marche à suivre.

## Méta

**Pourquoi ce pas existe, dans la logique KRD.** BA28 a donné le replay : `Replay(run).ID == run.ID` prouve que l'**enregistrement** se re-dérive. Mais c'est une preuve d'**intégrité interne**, pas de **fidélité au réel**. L'adresse de contenu n'est calculée que sur ce que le run a **noté** ; un effet de bord qu'il n'a pas noté (un `bash` qui écrit un fichier hors self-report) **ne déplace pas le hash**. Le run paraît parfait et ment. BA29 ferme ce trou (gap H2) avec une source de vérité **orthogonale** au self-report : un effect-log capturé **à la frontière**. La réconciliation est alors la confrontation des deux — et l'auditabilité exige les **deux** preuves (`replay ∧ réconcilié`), pas une.

**Le choix « à la frontière, pas auto-rapporté » est le cœur du pas.** Si l'effect-log venait de l'agent, un agent infidèle le falsifierait aussi facilement que son journal. La frontière (le harness edge) est hors de portée de l'agent : c'est elle qui voit le FS muter et le transport MCP appeler. C'est la même logique que le mur (S04) : la garantie ne vient jamais de la bonne foi de l'agent, mais d'un point de contrôle qu'il ne contrôle pas.

**Le mur tient, en lecture seule.** Le ledger n'écrit aucune vérité (`wrote_truth=false`). Une brèche de fidélité est une **observation** ; la traiter passe par idée → miroir → /goal → approbation humaine (la porte S27), jamais par une écriture du noyau depuis l'écran. L'effect-log lui-même est append-only (REVOKE UPDATE/DELETE) pour que l'audit soit tamper-evident.

**Determinism-first.** `Reconcile` est un **diff** (appariement d'ensembles avec ordre stable), le compte de refus une **somme**, le filtre une **égalité de chaînes**. Aucun « LLM compare les logs ». Même entrée → même verdict ; les miroirs property (rapid + fast-check) le scellent. Un agent qui ferait ce diff serait un determinism gap qui bloquerait le pas.

## Méta-méta

**Ce que BA29 prouve sur AIDOS lui-même.** La complétude de KRD interdit les *monstres* — une capacité sans miroir, une vérité sans preuve. BA29 généralise cette exigence à l'**exécution de l'agent** : un run sans réconciliation serait un monstre d'un nouveau genre — une trace qui *prétend* être fidèle sans jamais l'avoir prouvé. En posant `auditable = replay ∧ réconcilié`, AIDOS refuse de croire un agent sur parole, exactement comme il refuse de croire une vérité sans son miroir. La preuve de fidélité est **computée, jamais déclarée** (anti-Goodhart, §8) : l'agent ne peut pas se déclarer auditable, le ledger le calcule depuis deux sources qu'il ne maîtrise pas.

**La forme du pas est elle-même la doctrine.** Trois sources de vérité orthogonales — le record (ce que l'agent dit), la frontière (ce que le monde voit), le replay (la re-dérivation déterministe) — convergent vers un verdict booléen non gameable. C'est le motif KRD partout : ne jamais faire reposer une garantie sur un seul point qu'un acteur intéressé pourrait fausser. Le ledger en lecture seule, l'effect-log append-only, la réconciliation déterministe : chacun ajoute une garde, aucun n'en retire (la meta-loop n'AJOUTE que des gardes, §5).
