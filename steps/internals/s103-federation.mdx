## Implémentation

S103 ajoute la **couche de composition fédération** : `back/runtime/federation` (sous-système Runtime — c'est le câblage des invariants transverses sur de vraies cellules + la vague de rouge, KRD §51). Tout est **pur, total, déterministe** et **n'écrit aucune vérité** (le mur) : `FanOut` rend les lignes de RedWorkQueue comme VALEUR ; l'INSERT réel dans `runtime.red_work_queue` est le job du hook PostKernelChange S22, sous la ligne d'eau.

**Le principe : composer, jamais forker.** S103 **n'invente aucun primitif d'invariant**. Il **compose** verbatim quatre contrats des étapes précédentes — aucun n'est ré-implémenté :
- `sagas.Evaluate` / `sagas.RunCompensation` (S49) — juger une trace, dérouler la compensation ;
- `globalinvariant.RedWave` (S48) — calculer la portée cross-cell d'une policy ;
- `redwave.Impact` / `redwave.Enqueue` (S22) — matérialiser la file rouge d'une cellule ;
- `cell.CheckCrossCellAccess` (S100) — le mur de la fédération (pas de contrat → pas de canal).

**`SagaOverCells(saga sagas.SagaInvariant, fed cell.Federation, trace sagas.Trace) → SagaRun`** — la saga canonique sur deux **vraies cellules** :
1. les deux cellules participantes doivent être une **paire contractée** : `cell.CheckCrossCellAccess(part[0].Cell, part[1].Cell, fed)`. Sans contrat honoré → `AccessBlock{Code: CROSS_CELL_NO_CONTRACT}`, `Leg = violated`, **aucune** évaluation (une saga n'a aucun canal implicite) ;
2. `sagas.Evaluate(saga, trace)`. Si déjà satisfaite (chemin heureux : `payment_captured`, `order_confirmed`) → `Leg = happy`, aucune compensation ;
3. sinon (une jambe a cassé : `payment_captured` sans `order_confirmed`), `sagas.RunCompensation(saga, trace)` puis **ré-évaluer** la trace post-compensation. Satisfaite → `Leg = compensated` (le cas done de §51 : « casser une jambe déclenche compensation ») ; toujours violée → `Leg = violated`.

`SagaRun{Leg, FinalTrace, Outcome, Compensation, AccessBlock}` — `Leg ∈ {happy, compensated, violated}` est **dérivé**, jamais déclaré.

**`FanOut(policy gi.GlobalInvariant, violatedCell gi.CellRef, policyWaveID string, cells []CellViolation) → []CellRedWave`** — le fan-out de policy globale, le cœur de §51 :
1. `gi.RedWave(policy, violatedCell)` calcule **quelles** cellules la policy rougit (la portée cross-cell — pour une `federation_policy`, toute la portée déclarée, la cellule violante en graine) ;
2. pour chaque cellule fournie : si elle est **dans la portée** ET qu'elle **viole** réellement la policy (`CellViolation.Violates`), `redwave.Impact(cv.Bumped, cv.Edges, cv.Heads)` + `redwave.Enqueue(wave, policyWaveID)` matérialisent sa **propre** RedWorkQueue (chaque ligne estampillée du `policyWaveID`) — la cellule réconcilie **localement** ;
3. une cellule dans la portée mais qui **ne viole pas** → `Reddened = false`, `Queue = nil` — **elle reste VERTE** (l'invariant §51 : « les cellules non affectées restent vertes »).

`CellViolation{Cell, Violates, Edges, Bumped, Heads}` est fourni par l'appelant (un capteur S22) — `federation` n'invente **jamais** une violation. `CellRedWave{Cell, Reddened, Queue}` est trié par cellule (déterminisme). `AffectedCells(waves)` projette les cellules réellement rougies (ordre canonique) — la même projection pour l'écran et la CLI.

**`TemporalOverCells(inv temporal.TemporalInvariant, antecedentCell, consequentCell cell.Ref, fed, obs) → TemporalRun`** — câble S50 : un deadline `within` transverse (ex. `payment_captured ⇒ order_confirmed within 5m`) entre deux cellules. Même garde de contrat (`CheckCrossCellAccess`), puis `temporal.Evaluate` verbatim. Aucune horloge murale lue (l'`Elapsed` est passé en argument).

**Le MCP `federation`** (`back/mcp/federation`, ADR 0009 : un outil = une op) expose `saga_over_cells`, `fan_out`, `temporal_over_cells` — porte de capacité au-dessus du paquet pur, stdio, lecture-seule (rend les lignes de file comme valeurs, n'écrit rien).

**Le twin TS + l'UI.** `front/web/lib/federation.ts` est le jumeau déterministe de `back/runtime/federation` (mêmes `sagaOverCells`/`fanOut`/`affectedCells`, la propriété de saga encodée exactement comme `sagas.Evaluate`, le Go autoritatif). La route **/federation** est *action-capable* (ui-completeness) : DEUX Server Actions sur le twin pur — (1) lancer la saga avec un toggle « casser une jambe » (rend `saga-leg` + `saga-compensation`), (2) tirer la policy globale (rend un tableau par cellule avec `cell-status-<cell>` rouge/verte + `fanout-affected`). Thème ADR 0010, bilingue ADR 0011. N'écrit aucune vérité.

**Les miroirs (red → vert).**
- **fixture** (`federation_fixture_test.go`) — 4 scénarios : (1a) chemin heureux sur deux cellules contractées → `happy`/satisfied ; (1b) **casser une jambe** → `compensated`, compensation contient `refundPayment@v3` et se termine par `compensation_executed` ; (1c) paire non contractée → `CROSS_CELL_NO_CONTRACT` ; (2) fan-out : `order`+`payment` rougies avec leur file estampillée `policy-bump-abc123`, `shipping` **verte** avec file vide, `AffectedCells = [order payment]` ; (3) temporal `within` transverse tenu + paire non contractée refusée.
- **rapid** (`federation_property_test.go`) — 3 propriétés : (1) `SagaOverCells` déterministe sur traces aléatoires ; (2) une jambe cassée se règle **toujours** `compensated`/satisfied ; (3) une cellule non violante n'est **jamais** rougie + `FanOut` déterministe, quel que soit le nombre d'autres cellules violantes.
- **fast-check** (`lib/federation.test.ts`) — 7/7, le miroir de reproductibilité TS : chemin heureux, compensation, refus non contracté, déterminisme saga ; non-affectée reste verte (cas + propriété), déterminisme fan-out.
- **Playwright** (`tests/e2e/federation.spec.ts`) — 4/4, chaque contrôle exécutable depuis l'écran : panneau + deux contrôles, saga happy, casser une jambe → compensé, fan-out (order/payment rouges, shipping verte, affected = order+payment).

## Méta

**Pourquoi une couche de composition et non un nouveau kind ?** Parce que la *complétude* (le mur anti-monstre) exige qu'on n'invente pas un invariant transverse de plus quand S48/S49/S50 en portent déjà la forme. S103 est une étape de **câblage** : sa valeur n'est pas un nouveau primitif mais la **preuve que les primitifs existants tiennent ensemble sur de vraies cellules**. Le code de `federation` est presque entièrement des appels aux fonctions des étapes amont — c'est délibéré. Une étape de composition qui forkerait la logique d'évaluation serait un **monstre de duplication** : deux vérités du même comportement qui peuvent diverger.

**La vague de rouge globale vs local.** La tension de §51 est résolue par la séparation `gi.RedWave` (qui décide *quelles* cellules) / `redwave.Impact` (qui décide *quel travail* dans une cellule). Le global ne descend jamais dans les internals d'une cellule ; le local ne déborde jamais sa frontière. `FanOut` est exactement la couture entre les deux : il appelle le global pour la portée, puis délègue à chaque cellule son propre `Impact`. La cellule non violante n'a **rien à faire** — c'est l'invariant qui fait que la fédération **scale** : une policy ne réveille que ceux qui la violent.

**L'honnêteté du `CellViolation` fourni.** `federation` n'invente jamais une violation : l'appelant (un capteur) dit quelles cellules violent et avec quelles arêtes. C'est la règle anti-Goodhart de §8 portée à la composition : le juge (ici la composition) ne fabrique pas le fait qu'il juge. Une cellule n'est rougie que sur une violation **réelle**, jamais sur une supposition.

## Méta-méta

**La composition est le test du déterminisme-first à grande échelle.** Si chaque primitif est une fonction pure et que la composition est aussi pure, alors **toute la fédération est rejouable** : même fédération + même trace + mêmes violations → même vague de rouge, byte-identique. C'est ce que les miroirs rapid/fast-check épinglent. Le jour où un agent voudrait « deviner » quelles cellules rougir avec un LLM, ce serait un **trou de déterminisme** : `gi.RedWave` est un algorithme sur la portée déclarée, pas un prompt. S103 démontre que la mise à l'échelle (la fédération) **n'introduit aucune nouvelle non-déterminisme** — elle compose des fonctions déjà pures.

**Pourquoi ça prépare S116 (RGPD).** La policy « tout PII oubliable » de S103 n'est pas un exemple jetable : S116 la rendra concrète (export + suppression, crypto-shredding réconcilié avec l'append-only). En la livrant ici comme `GlobalInvariant` fan-outée, S103 prouve d'abord le **mécanisme** (qui rougit, qui reste vert) avant que S116 n'attache la **sémantique** (qu'est-ce qu'effacer du PII). C'est le pattern KRD : poser le mécanisme transverse, déterministe et prouvé, **avant** la règle métier qui s'y branche — pour que la règle métier n'ait jamais à réinventer le câblage.
