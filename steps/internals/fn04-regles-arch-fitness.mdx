## En une phrase

FN04 ajoute, dans `back/runtime/agentloop/emittedfitness.go`, une fonction **pure et totale** `CheckEmittedFunctional` (+ `ScanEmittedTree` pour `back/gen/`) qui rend les trois invariants du mandat fonctionnel **exécutables** comme règles arch-fitness **fail-closed**, prouvées par un miroir de **fault-injection** rouge-d'abord, dans l'esprit exact de `CheckLLMIsolation` (BA14).

## Implémentation

<Steps>
  <Step title="Le miroir de fault-injection écrit en PREMIER (rouge)">
    `emittedfitness_fixture_test.go` porte les preuves rouge-d'abord : la source émise propre passe (aucune violation), puis **injecter** une globale mutable (`var leaked = …`), un `func init()`, une récursion directe (`func loop() { loop() }`) ou mutuelle (`a→b→a`) fait passer la règle correspondante **rouge** avec un `BlockReason` actionnable nommant le symbole fautif. Avant l'implémentation, le fichier ne compile pas (symboles indéfinis) — le vrai rouge.
  </Step>
  <Step title="La porte de portée — IsEmittedProjection">
    `IsEmittedProjection(src)` est le discriminant **déterministe** de portée (ADR 0036 §3) : seuls les fichiers dont la source contient le marqueur `CODE GENERATED BY AIDOS` sont des projections émises contraintes. La **logique** des émetteurs sous `gen/` (ex. `gen/db`'s `EmitMigration`, sans marqueur) et la sortie **sqlc** (`Code generated by sqlc`) sont hors portée.
  </Step>
  <Step title="La règle pure CheckEmittedFunctional">
    Sur une source émise, `CheckEmittedFunctional(filename, src)` parse (`go/parser`, `SkipObjectResolution`) et renvoie les violations en **ordre déterministe** : (1) `token.VAR` au scope paquet → `EMITTED_NO_GLOBAL_MUTABLE` (un nom `_` est exempté — assertion de compilation) ; (2) `FuncDecl` sans receiver nommé `init` → `EMITTED_FUNCTION_PURE` ; (3) un cycle dans le graphe d'appel → `EMITTED_CALL_GRAPH_ACYCLIC`. **Fail-closed** : si le parse échoue, une unique violation `EMITTED_UNPARSEABLE`.
  </Step>
  <Step title="L'acyclicité — DFS trois-couleurs">
    `firstCallCycleNode(file)` construit le graphe d'appel **intra-fichier** (caller → callees restreints aux fonctions **définies dans ce fichier** — l'ensemble fermé de nœuds de la couche émise) via `ast.Inspect` sur les `CallExpr`, puis fait un **DFS trois-couleurs** (blanc/gris/noir) sur les nœuds **triés** : une arête vers un nœud **gris** est un cycle. Pur et déterministe (itération triée).
  </Step>
  <Step title="Le scan de l'arbre + la config + la parité">
    `ScanEmittedTree(dir)` marche `back/gen/`, lit chaque `.go` (hors `_test.go`/`vendor`/`testdata`), applique la règle et renvoie toutes les violations en **ordre stable** (fichiers triés). `arch-fitness.json` gagne un bloc `emitted_functional` (`scope_path: "back/gen"`, `marker`, les 3 `invariants`) ; `config_test.go` épingle la **parité** entre cette liste et `EmittedInvariantCodes()` (ADR 0036 §5 : la liste déclarée et la config ne dérivent jamais).
  </Step>
  <Step title="Le miroir property + l'outil MCP">
    `emittedfitness_property_test.go` (rapid) épingle **reproductibilité** (mêmes (nom, src) → mêmes violations), **totalité** (jamais de panic sur des octets arbitraires), et que les **seuls** codes possibles sont les quatre déclarés (severity `blocking`, `how_to_fix` non vide — jamais une prison). Le serveur MCP `agentloop` gagne l'outil `agentloop_emitted_fitness` (ADR 0009 : tout op backend = un outil MCP), lecture seule.
  </Step>
  <Step title="Le jumeau TS + l'écran action-capable">
    `front/web/lib/emitters.ts` gagne `checkEmittedFunctional(goSource)` (jumeau déterministe : scan source — `var` au scope, `func init()`, DFS de cycle — fail-closed, hors-portée si pas de marqueur) + un test vitest (property + cas de fault-injection). Le panneau `/emitters` (`EmittersPanel.tsx`) gagne un bouton **« Vérifier arch-fitness »** sur la carte go-sqlc (`data-testid="arch-fitness-go-sqlc"`) et un verdict `data-archfitness="true|false"` ; un e2e Playwright prouve que le contrôle **s'exécute** et rend `true`. i18n FR/EN ajoutée.
  </Step>
</Steps>

## Méta — pourquoi c'est construit ainsi

- **Pourquoi `agentloop` et pas un nouveau package.** L'objectif FN04 demande d'**étendre** `agentloop/archfitness.go` + `arch-fitness.json`. C'est le foyer existant des règles arch-fitness d'AIDOS (la règle BA14 `CheckLLMIsolation`) : `Violation`, `BlockReason`, le patron `Scan*` + `Check*` y vivent déjà. FN04 réutilise ce moule au lieu d'inventer un nouveau slot.
- **Pourquoi le marqueur comme porte de portée, et pas un chemin.** L'ADR scope le mandat aux *sorties* émises, pas à la *logique* qui les émet — or les deux cohabitent sous `gen/` (`gen/db/datatruthscope.go` est de la logique d'émetteur, avec des `var` d'énumération légitimes). Un filtre par chemin les confondrait. Le marqueur `CODE GENERATED BY AIDOS` est le discriminant **honnête et déterministe** : il distingue exactement ce que l'ADR vise (les projections émises) de ce qu'il exclut (la logique, le code sqlc).
- **Pourquoi exempter `var _`.** Une assertion `var _ Querier = (*Queries)(nil)` (idiome sqlc/Go) est une **vérification de compilation**, pas un état mutable. La règle est fail-closed mais pas une machine à faux positifs : elle exempte le seul cas universellement non-mutable, et signale tout `var` nommé.
- **Pourquoi prouver l'acyclicité, alors que la pureté (FN03) suffit au déterminisme.** L'acyclicité sert l'intention amont (Understand-Anything : chaque fonction = un nœud d'un graphe acyclique) et **prépare FN05** : l'index call-graph fourni en contexte d'agent n'a de sens que si le graphe est garanti sans cycle. C'est le troisième invariant de l'ADR, pas un bonus.

## Méta-méta — la garde sur la garde

- **FN04 n'AJOUTE qu'une garde (§5).** Les trois règles s'ajoutent à la règle BA14 et aux sept propriétés S34 ; elles n'en retirent ni n'en assouplissent aucune. Le miroir de fault-injection garantit qu'elles **firent** (une règle qui ne se déclenche jamais est morte — §5 honnêteté des hooks).
- **Le verdict est calculé, jamais déclaré (§8).** Ni `CheckEmittedFunctional`, ni le bouton « Vérifier arch-fitness », ni l'outil MCP ne lisent une confiance d'agent : la violation est le résultat d'une marche d'AST. Un « LLM qui juge si c'est fonctionnel » serait une fracture de déterminisme qui bloquerait le step (CLAUDE.md §6/§8).
- **Le mur tient (§2).** Les règles sont du code sous la ligne ; elles certifient `gen/` sans écrire `kernel`/`mirrors`/`fitness`. Élargir la portée ou assouplir un invariant passe par idée → miroir → /goal (comme l'`allowed_importers` de la règle LLM) ; `config_test.go` interdit la dérive silencieuse entre la config et le code.
- **Le live `gen/` tient sur disque, pas qu'en fixture.** `TestScanEmittedTree_LiveGen_Holds` scanne l'arbre émis réel et exige zéro violation : la garde tient là où elle compte. Un futur émetteur qui glisserait une globale/un init/un cycle dans un fichier marqué AIDOS la ferait passer rouge au build.
