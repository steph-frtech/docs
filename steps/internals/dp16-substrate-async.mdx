## Implémentation

### Le paquet — `back/runtime/asyncfragments/` (NEW, additif)

DP16 grave les services **asynchrones** de la palette mesurée (DP14) en fragments StackManifest. Le paquet est **NEW et additif** : `back/runtime/asyncfragments/` — rien d'existant n'est touché ni cassé. C'est le **jumeau asynchrone** de DP15 : il **réutilise** le type `ServiceFragment` de `datafragments` au lieu d'en forger un parallèle.

```go
type ServiceFragment = datafragments.ServiceFragment // alias, JAMAIS forké

func SubstrateAsyncFragments(projectID string, env scope.Environment) ([]ServiceFragment, error)
func Keys() []string // palette close [windmill nats]

func RealizeScheduled(
  op operation.Operation, async operation.Async,
  clock operation.Clock, outbox operation.Outbox, sink operation.Sink,
) ([]DispatchEvent, error)

type DispatchEvent struct {
  Operation string
  EffectID  string
  Kind      operation.TriggerKind
  Target    string
}

type OutboxWriter interface { Write(operation.OutboxEntry) } // facet write du seam outbox S73
var ErrOutboxNotWritable error

var CanonicalFragment = datafragments.CanonicalFragment // S02 réutilisé via DP15
var HashFragment      = datafragments.HashFragment
```

Pour que la réutilisation du token de DP15 soit propre, `datafragments.isolationToken` a été **exporté** en `IsolationToken` — un changement **additif** (§9), les appelants internes de DP15 mis à jour, ses tests toujours verts. DP16 réutilise donc l'**exact** token par projet de DP15, sans schéma forké.

### Le jeu clos — deux fragments, images = mesure DP14

Deux fragments ASYNCHRONES déterministes, jeu **clos**, dont les images sont **exactement la mesure DP14** :

- `windmill` — role=workflow, profile=`core`, port interne 8000, `ghcr.io/windmill-labs/windmill:main`, healthcheck `GET /api/health`, `depends_on` postgres — **JAMAIS Temporal**.
- `nats` — role=bus, profile=`core`, port interne 4222, `nats:2.10-alpine`.

Chaque fragment porte : image + port interne + **volume bind** (device = env-var, **jamais un chemin en dur**) + healthcheck + `depends_on` + profile + `project_id`.

### Pas d'env-gating — fermeture sur l'inconnu

Contrairement à DP15 (Doltgres opt-in hors prod), DP16 **n'a aucun env-gating** : la palette asynchrone est `core` dans **tous** les environnements. Il n'y a donc **aucune porte de gate** à déléguer. La seule défense : un environnement **hors du jeu déclaré** échoue **fermé** avec `UNKNOWN_ENVIRONMENT`. Pour `(projectID, env)` valide, l'émission est **byte-identique** d'un appel à l'autre.

### L'isolation par projet — `datafragments.IsolationToken` réutilisé

L'isolation par projet réutilise **le même** token que DP15 (`provision.isolation`, jamais forké) : `records.Hash("datafragments/v1:" + projectID)[:12]`, désormais exposé via `datafragments.IsolationToken`. Ce token marque le **nom du volume** et la **variable d'environnement** du device. Conséquence : pour deux projets A et B, les fragments asynchrones sont **byte-distincts** (A ≠ B) — aucun croisement de volume possible. Un seul schéma d'isolation pour toute la substrate.

### Le scheduler pur sur horloge injectée — `RealizeScheduled`

`RealizeScheduled` réutilise le **scheduler de S73 verbatim** (`operation.Tick`, `operation.Clock`/`FixedClock`, `operation.Due`, `operation.Effect`/`EffectID`, `operation.OutboxEntry`/`Outbox`/`Sink`/`Dispatch`, `ValidateAsync`, l'ancre `SendReminder`) — **rien n'est forké**.

- Le scheduler tique sur l'**horloge INJECTÉE** (`operation.Tick`) — **jamais `time.Now`**, jamais d'aléa.
- **Avant l'échéance** : ni écriture ni événement.
- **À l'échéance** : chaque effet est d'abord **écrit dans l'outbox**, puis **dispatché** via `operation.Dispatch` (S73, réutilisé pas forké).
- **Exactly-once relatif** : le `EffectID` est **adressé au contenu** ; un replay après crash retrouve l'`EffectID` dans l'outbox et **supprime** le doublon — le dispatch ne part qu'une fois.

`OutboxWriter` est la **facet write** du seam outbox de S73 (**ajoutée**, pas une mutation de S73) ; un outbox non inscriptible rend `ErrOutboxNotWritable` (erreur **typée**, pas un panic).

### Les workers restent TS — pas un worker de runtime

DP16 émet des **FRAGMENTS DE SERVICE** (topologie compose) + le **planificateur au build**, **pas** les workers de l'app émise. Les **workers asynchrones de l'application émise restent en TypeScript** (ADR 0040), rendus par l'émetteur S74 (`relemit.EmitWorker`). Ce paquet Go est la **réalisation au build** et le **scheduler**, jamais un worker dans la boucle de runtime — le re-coder en Go **dupliquerait S74** (interdit).

## Méta

- **Le scheduler est pur sur une horloge injectée — donc il se rejoue à l'identique.** `RealizeScheduled` ne consulte **ni `time.Now`, ni aléa, ni LLM** : elle reçoit son `Clock` en paramètre et tique dessus. C'est le déterminisme-first (§6) appliqué au temps : planifier est une transformation pure des seams injectés, donc c'est du code, jamais un agent. `TestL6DeterministicScheduling` le prouve. Et l'émission de fragments est elle aussi pure : `SubstrateAsyncFragments` dérive ses deux briques d'une table close et du hash de DP15 — `TestL1ByteIdentique` asserte que deux appels rendent des octets identiques.

- **L'exactly-once n'est pas affirmé, il est mesuré au replay.** La garantie dure de l'asynchrone — un effet planifié part une seule fois même après un crash — ne se déclare pas, elle se **prouve** : `TestFixture_ReplayAfterCrashNeverDuplicates` rejoue la réalisation et vérifie qu'aucun doublon ne sort. Le mécanisme est l'`EffectID` **adressé au contenu** : l'outbox connaît déjà l'effet, le dispatch est supprimé. C'est l'outbox transactionnel canonique — écrire avant de dispatcher, dédupliquer par identité de contenu — et il est **réutilisé de S73**, jamais reforgé.

- **Réutiliser un type plutôt qu'en jumeler un.** DP16 ne forge pas son propre `ServiceFragment` : il **alias** celui de DP15 (`type ServiceFragment = datafragments.ServiceFragment`) et réutilise son token d'isolation, ses oracles `CanonicalFragment`/`HashFragment` (S02). Le bon réflexe : deux couches qui décrivent la même forme (un fragment de service) doivent partager **le** type, pas en maintenir deux qui finiront par diverger. `TestL5SharedIsolationToken` asserte que le token est bien celui de DP15, pas une copie locale.

## Méta-méta

- **Windmill, jamais Temporal — une contrainte dure assertée par le miroir.** La spec grave un choix d'orchestrateur : l'asynchrone des apps émises passe par **Windmill**, et **Temporal est refusé**. DP16 ne se contente pas de l'écrire en commentaire : le miroir `TestFixture_WindmillNeverTemporal` **asserte** que la palette ne contient jamais Temporal — émettre un fragment Temporal ferait virer le miroir au rouge. Une contrainte dure n'est réelle que si un test la garde ; sinon c'est un vœu (un monstre). Le jeu clos `[windmill nats]` est la forme exécutable de ce choix.

- **Sous la ligne — aucun worker n'écrit la vérité.** DP16 pose les services asynchrones et planifie leurs effets, mais il vit **entièrement sous la ligne** : il n'écrit **jamais** le noyau, les miroirs ni la fitness. Le scheduler et le dispatcher sont **purs** au-dessus de seams injectés (clock, outbox, sink) ; aucun effet planifié ne remonte écrire une vérité. Le mur reste intact : un worker peut envoyer un rappel, jamais graver un invariant. Bouger la vérité reste une décision enregistrée (idée → miroir → /goal → ChangeSet), gardée par le mur.

- **Réutiliser S73 et S74, ne pas les dupliquer (ADR 0007, ADR 0040).** DP16 n'ajoute qu'une chose neuve : l'**assemblage** des fragments asynchrones en jeu clos et leur **réalisation** au build. Tout le reste est réutilisé : le scheduler/outbox/dispatch de **S73** (verbatim, l'`OutboxWriter` n'est qu'une facet *ajoutée* au seam, pas une mutation), le type et l'isolation de **DP15**, les oracles d'adresse de contenu de **S02**. Et la frontière des plans est nette : DP16 fige *quels* services asynchrones tournent et *comment ils sont isolés* (mandatory, déterministe, Go au build) ; les **workers** de l'app émise — *comment le code de l'app exécute son async* — restent **TS** (ADR 0040, S74 `relemit.EmitWorker`), un slot que DP16 ne touche pas. Réutiliser plutôt que réinventer, sur les deux plans.
