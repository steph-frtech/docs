## Couche 1 — Implémentation

### Le package Go `back/runtime/generators`

Deux fonctions pures sont le cœur :

```go
func Emit(s EntitySource, t Target) (Artifact, *blockreason.BlockReason)
func Project(sources []EntitySource, targets []Target) ([]Artifact, *blockreason.BlockReason)
```

- `Target` est un jeu **fermé** : `go-sqlc | pg-ddl | ts-types` (grandit additivement, jamais inventé).
- `Artifact` porte `path`, `target`, `kind`, `bytes`, `source_hash`, `output_hash`, `protected: true`.
- `source_hash = records.Hash(records.Canonicalize(body))` — le **schéma de hash de S02, réutilisé, jamais reforké**. `SourceBody` trie les champs par nom avant de hasher, donc l'ordre d'écriture des champs **n'est pas sémantique** : reréordonner donne le **même** `source_hash`.
- `output_hash = records.Hash(bytes)` — preuve de ré-émission byte-identique.

Le **déterminisme** est garanti par construction : ordre de champs trié, pas d'horloge/hasard/map-order/chemin absolu, sauts de ligne `\n`. Le rendu Go passe par **`go/format.Source`** (le gofmt canonique, pur) pour produire du Go déjà aligné ; la DDL et le TS sont rendus depuis le **même AST** que le Go.

### Le slot `go-sqlc` honoré de bout en bout

sqlc est le slot gelé (CLAUDE.md §3, jamais substitué). La projection **`pg-ddl`** (un `CREATE TABLE` avec identifiants quotés) **EST** l'entrée du schéma sqlc : un `sqlc generate` par-dessus reproduit le struct Go que le twin `renderGoSqlc` émet. Le test `sqlc_slot_test.go` le prouve (et **skippe** proprement si le binaire sqlc est absent), de sorte que les trois projections ne peuvent pas dériver — une source, jamais double-typé.

### Le geste `/project` et le matérialiseur

Le geste `/project` (skill) matérialise les artefacts sur disque (`back/gen/<entité>/`, `front/web/gen/<entité>/`) via la commande `cmd/materialize`, écrit le **header protégé** dans chaque fichier, et enregistre le **ledger** par le rôle writer `aidos`. `Drifted(ledgerOutputHash, onDisk)` calcule un fichier `gen/` édité à la main ; `Stale(artifactSourceHash, headSourceHash)` calcule un artefact dont la source a bougé.

### La migration Atlas `runtime.generated_artifacts`

Expand-only / append-only. Le ledger : `path`, `target CHECK (go-sqlc|pg-ddl|ts-types)`, `kind`, `source_hash`, `output_hash`, `emitted_at`, **PK `(path, source_hash)`**. Ré-émettre la même source vers le même chemin est idempotent ; une source **changée** (nouveau `source_hash`) **ajoute** une ligne, laissant l'antérieure (désormais stale) en place — jamais un UPDATE in-place.

**Les GRANTs (le mur, défense en profondeur) :** le rôle `aidos_agent` obtient **SELECT only** sur `runtime.generated_artifacts` (il lit son historique d'émissions pour le panneau) et garde **SELECT only** sur `kernel.*` (il lit l'AST d'entité, ne l'écrit jamais) ; seul le rôle writer `aidos` insère. Le round-trip + les GRANTs sont prouvés sur un vrai Postgres (**Testcontainers**, `migration_roundtrip_test.go`), sans Atlas en CI.

### Les miroirs (rouge d'abord)

- **Fixture N2** (`tests/runtime/emitters.fixture.md` → `emitters_fixture_test.go`) : émission sur les trois cibles, byte-identique, source changée → stale, hand-edit ne survit pas, champ non épinglé jamais inventé, AST malformé → BlockReason.
- **Propriété `rapid`** (`emitters_property_test.go`) : déterminisme, source content-addressée, header protégé, order-independence, pas de dérive inter-cible, pas de hash stale silencieux, totalité (jamais de panic).
- **Twin TS** (`front/web/lib/emitters.ts`) + **fast-check** (`emitters.test.ts`, 11/11), **byte-identique** au Go (vérifié sur les 6 artefacts exemple).

### La route Workbench `/emitters`

Server Component qui calcule les projections (le `node:crypto` côté serveur reproduit le hash de S02) + le panneau client action-capable (`EmittersPanel`) : sélecteur d'entité, **RÉ-ÉMETTRE** (même `output_hash` visible), **BOUGER LA TÊTE** (bascule en stale), badges déterministe/stale. Thème ADR 0010, bilingue ADR 0011 (FR/EN) avec tutoriel + exemple travaillé. e2e Playwright `tests/e2e/emitters.spec.ts` (3/3).

## Couche 2 — Méta (la décision sur la décision)

- **Pourquoi un twin Go + TS byte-identique ?** Le mandat *déterminisme-first* (CLAUDE.md §6/§8) : l'émission est une fonction pure, jamais un LLM. Le twin TS rend le panneau **action-capable** sans réimplémenter — et la parité byte-pour-byte (vérifiée) prouve qu'il n'y a **pas de dérive** entre les deux plans (le coder d'AIDOS et la projection émise).
- **Pourquoi `go/format` plutôt qu'un aligneur maison ?** Réutiliser, ne pas réinventer (ADR 0007) : gofmt est l'aligneur canonique et déterministe. Le twin TS reproduit son alignement par espaces (vérifié) — la byte-stabilité tient sur les deux plans.
- **Pourquoi pas de MCP, pas de hook ?** `Emit`/`Project` sont une **lib pure** et `/project` un geste harnais ; la protection `gen/` est déjà couverte par le mur (S04) + la byte-égalité au re-emit. §5 hook-honnêteté interdit un hook qui ne se déclenche jamais. Une OpenQuestion est posée si un op callable `project_emit` émerge.
- **OpenQuestion OQ-S34-entity-kind :** S02 fige sept kinds KRDCore ; il n'existe **pas encore** de kind `entity` first-class. L'AST d'entité dont S34 émet est donc modélisé comme le **corps JSON que l'emitter consomme** (`EntitySource` : nom + champs épinglés), content-addressé via le hash de S02. Quand le DSL d'entité atterrira comme kind kernel, le décodeur s'y branchera ; l'emitter reste inchangé. L'agent ne crée aucun kind d'entité (le mur).

## Couche 3 — Méta-méta (la loi sur la loi)

- **« Le code généré n'est jamais la vérité »** (ADR 0004, CLAUDE.md §4/§9). Une projection est un **miroir d'implémentation régénérable** : le header protégé + la byte-égalité au re-emit rendent l'interdiction d'édition manuelle **mécanique**, pas seulement déclarative. Changer une projection se fait en changeant la **source** (un ChangeSet kernel), jamais le fichier.
- **« Une source, N projections, jamais double-typé »** (CONTEXT-MAP : *Kernel → projections : constrains, never generates*). Le kernel **contraint** ; les emitters **projettent**. Les trois cibles depuis un seul AST sont la matérialisation de cette loi.
- **La staleness alimente la vague de rouge, elle ne la possède pas.** Un `source_hash` qui ne correspond plus à la tête est une **inégalité calculée** que S22 consomme — S34 ne réimplémente pas le cascade (anti-chevauchement §9). Le déterminisme rend cette inégalité fiable : sans byte-stabilité, « stale » serait du bruit.
- **Le mur est asymétrique par conception.** L'agent **lit** la vérité (l'AST) et **écrit** des projections ; il n'écrit **jamais** la vérité ni le ledger. Cette asymétrie — SELECT-only sur kernel, ledger écrit par `aidos` — **est** le contrat (CLAUDE.md §2).
