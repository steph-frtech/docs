## En une phrase

BA19 ouvre la **porte de capacité** sur la boucle `agentloop.Drive` (le shell runnable de BA15) sous forme de serveur MCP (ADR 0009 : chaque op backend est un outil MCP), **gaté à la frontière transport** (identité BA18 + capacité `ToolAllowed`), prouvé par un **miroir journey Godog** mono-agent (gap J3) et un **miroir d'intégration transport** qui asserte que l'enforcer est SUR le chemin d'appel (gap C2) — et le run **n'écrit jamais de vérité**.

## Implémentation

Le serveur vit dans `back/mcp/agentloop` ; il pilote la boucle pure `back/runtime/agentloop`.

- **Trois outils, un par op** (`main.go`) — `agentloop_drive` (piloter un run gouverné sur un item rouge, gaté à la frontière, retourne l'AgentRun), `agentloop_watch` (rejouer un run enregistré : sa timeline ordonnée + le résultat calculé, lecture seule), `agentloop_list` (énumération lecture-seule des scénarios déclarés).
- **`gate(layerRef, targetServer, targetTool, contextPack)`** — le check de frontière transport PARTAGÉ par `drive` ET `watch`, exécuté AVANT `Drive` : (1) la couche gouvernée demandée doit exister + projeter (sinon not-bound, fail-closed) ; (2) le token présenté par la boucle doit la lier à EXACTEMENT cette `CoucheAgent@version` (BA18 `ActAsIdentity`, `AGENT_IDENTITY_UNVERIFIED` au mismatch) ; (3) la projection doit LIER l'outil MCP visé (`agentimpl.ToolAllowed`, axe capacité) — l'assertion « est-ce réel ? » : l'enforcer est sur le chemin, pas un retour faux d'unit-test.
- **La source d'action est un scénario scripté DÉCLARÉ** (`scenario.go`) — un `ScriptedGenerator`, pas un LLM. Trois scénarios fermés : `happy` (écrire la projection autorisée puis fermer le goal au vert), `kernel-write` (la première tentative écrit le noyau → refusée en place par `GateAction`, `Autorisee:false`, `AGENT_WRITE_ABOVE_WATERLINE`, l'effet n'atterrit jamais, le run continue), `over-budget` (un tour cher que le `tightBudget` casse → abandon). BA17 swappe le `ScriptedGenerator` pour un générateur backed-provider ; ici le LLM N'EST PAS là — on prouve le SHELL + le mur sur le vrai chemin, pas la génération.
- **La vue lecture-seule** (`view.go`) — le même snapshot déterministe mocké de la vue SELECT `kernel.agent_layer` que sert le serveur agentimpl : la couche `agent:builder@v1` LIE l'outil cible (`mirror-runner/run_mirror`), autorise les écritures dans `app/` (sous la ligne), déclare le hook PreToolUse obligatoire (le mur), et porte les deux droits structurels toujours-faux (jamais de proposition de vérité ni de modif de miroir depuis sous la ligne).
- **Les miroirs** — `journey_bdd_test.go` (le miroir journey N0 Godog : 4 scénarios — happy run gouverné réclame un item rouge, gate chaque action, ferme le goal au vert ; un run dont le modèle tente une écriture noyau a cette action refusée en place ; un run abandonne quand il épuise son budget déclaré ; observer un run enregistré rejoue sa timeline déterministiquement) ; `transport_integration_test.go` (le miroir d'intégration gap C2 : monter le serveur sur une vue qui projette une impl qui NE LIE PAS l'outil cible, piloter `drive`, asserter le refus à la frontière transport — `TestTransport_BoundToolDrivesGreen` + `TestTransport_UnboundToolRefusedAtBoundary`) ; `repro_property_test.go` (le miroir de reproductibilité : même `(layer_ref, scenario, work item, timestamps)` ⇒ même AgentRun).
- **Le jumeau front** (`front/web/lib/agentrun.ts`) — `driveAgentloop(impl, scenario, redWorkItem, target)` reflète `agentloop_drive` : il gate à la frontière transport (`toolAllowed`), puis pilote le scénario ; `agentloopWroteNoTruth(run)` est l'assertion de mur (aucune action AUTORISÉE ne vise une zone au-dessus de la ligne). Prouvé par 6 tests Vitest + fast-check (126 au total).
- **L'UI action-capable** (`front/web/components/AgentsPanel.tsx`, section `agentloop-run`) — « Lancer un run » bound à `driveAgentloop` : sélecteur de scénario + case « outil non lié » (fault-injection), timeline live des actions avec verdict par action, étiquette « n'écrit aucune vérité », `BlockReason` + `how_to_fix` au refus. Thémé (ADR 0010), bilingue FR/EN (ADR 0011). L'e2e Playwright (`tests/e2e/agents.spec.ts`) prouve les 4 cas : contrôles présents ; happy run rend la timeline + n'écrit aucune vérité ; kernel-write refusé en place (`AGENT_WRITE_ABOVE_WATERLINE`) + toujours aucune vérité ; outil non lié refusé à la frontière (`AGENT_TOOL_NOT_BOUND`), aucun run.

## Méta — pourquoi c'est construit ainsi

Le choix structurant est que le serveur MCP est une **porte de capacité fine** sur `Drive`, et non un nouveau moteur. `Drive` (BA15) est déjà le shell pur et déterministe ; BA19 n'ajoute que l'enforcement de frontière (identité + capacité) et la sérialisation MCP. Le `gate` est partagé entre `drive` et `watch` exprès : observer un run, c'est le **re-piloter** sur les mêmes entrées pures (idempotent), donc la même garde s'applique — pas de chemin de lecture privilégié qui contournerait le mur.

L'usage d'un `ScriptedGenerator` plutôt qu'un LLM ici est délibéré et determinism-first : ce qu'on prouve à BA19, c'est le SHELL + le mur sur le vrai chemin transport, pas la génération. Mettre un LLM dans ce miroir le rendrait non-reproductible et masquerait la propriété qu'on veut tenir. La génération irréductible est confinée à BA17 (la seule exception LLM), gated et re-checkée. Le serveur ne porte volontairement **aucun outil** qui écrirait le noyau/miroirs/fitness : toute vérité qu'un run proposerait passe par `propose → ChangeSet → approbation` (BA20+).

## Méta-méta — l'invariant que ça garde vivant

> **L'enforcer du mur est sur le chemin d'appel réel, pas un retour faux d'unit-test.**

C'est le gap C2 — « est-ce réel ? » — rendu vérifiable : le miroir d'intégration transport monte le vrai serveur, pilote `drive` avec une impl qui ne lie pas l'outil cible, et asserte que l'appel est refusé **à la frontière** avant qu'aucune action ne tourne. Un refus qui ne serait qu'un `if` au fond d'un test serait un mur en carton ; ici la garde est sur le chemin que tout appel réel emprunte. `determinism-first` est tenu au sens fort : `gate`, l'assemblage du `DriveInput` et la sélection de scénario sont des fonctions pures, totales, sans horloge ni rng (les timestamps sont SUPPLIÉS) ; le check de capacité est une appartenance ensembliste (`ToolAllowed`), jamais un jugement. Un agent qui ferait ce qu'une fonction pure peut faire serait un trou de déterminisme qui **bloque le pas**, au même titre qu'un monstre ou une capacité headless. Et la propriété de mur — `agentloopWroteNoTruth` — est rejouée par le miroir sur chaque run : même au milieu d'une tentative d'écriture noyau, aucune vérité n'atterrit au-dessus de la ligne.
