<Info>Côté détail. Pour le concept, voir [Pour les futurs utilisateurs → S23](/steps/concept/s23-phase-stable).</Info>

S23 livre la **décision de coupe cohérente** (KRD §43) : la fonction **pure** de l'Archive qui répond « est-ce une phase stable ? » = « tous les liens résolvent + tout est vert ? » ; la table **`dag.stable_phase`** qui enregistre le nœud content-addressed avec son arête `parent` (§44) ; et la commande `aidos stable` qui imprime le verdict en **lecture seule** (§82.1). La **règle** — « stable = tout lien resout (S17 vert) ∧ tout senseur vert ; la coupe vide est stable par vacuité ; un seul miroir rouge la rend instable » — est celle de l'humain (KRD §43). Aucune vérité écrite par l'agent (le mur) ; `aidos stable` n'écrit rien ; `dag` est au-dessus de la ligne (agent SELECT-only).

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/archive/phases/phases.go`** — le cœur **pur** (aucune I/O, aucune horloge, aucun rng, **aucune écriture**). **`IsStable(cut Cut, heads links.Heads, ls []links.Link, sensors []SensorStatus) → StablePhase`** est total et déterministe : il collecte les **reasons** en deux passes — chaque **senseur** dont `Pass==false` est nommé par son id ; chaque **lien** dont `links.Resolve(l, heads) != green` est nommé `from->to (stale|absent)` — puis trie les reasons (verdict octet-à-octet stable). `stable == (len(reasons) == 0)`. La coupe **vide** (aucun lien, aucun senseur) a `reasons` vide ⇒ **stable par vacuité** (le cas de base). N'importe quel miroir rouge la fait basculer. Le type **`StablePhase`** porte `Cut` (la sélection `contrainte → version`), `SensorStatus` (l'instantané S07), le `Stable` **dérivé** et les `Reasons` ordonnés.
- **Réutilisation, pas réinvention** — la staleness d'un lien est décidée **uniquement** par `links.Resolve` de **S17** (réutilisé, jamais forké : un lien est rouge ssi `Resolve` rend `stale|absent`) ; le vert d'un senseur est la forme de résultat **S07** (`CheckResult.Pass`) réduite à `{id, pass}` ; l'**adresse de contenu** de la phase est `records.Canonicalize` + `records.Hash` de **S02** — `StablePhase.Record()` produit un `records.KindPhase` body dont `id == version == Hash(Canonicalize(body))`. La coupe / l'instantané / le verdict / les reasons vivent **à l'intérieur** du body JSONB (des refs version-pinnées, **pas** des clés étrangères) pour qu'une phase enregistrée reste **inspectable** après que la tête a bougé.
- **`back/migrations/dag_stable_phase_baseline.sql`** — la table **`dag.stable_phase`** : **expand-only / append-only**, un nœud immuable content-addressed par phase (`id` = hash du body, `body jsonb` = `{cut, sensor_status, stable, reasons}`, `version` = id avec un CHECK `version = id`, **`parent text NULL`** = l'**arête DAG** vers le nœud précédent (§44 ; NULL pour une racine), `created_at`). S02 avait déjà créé un `dag.phase` générique ; S23 ajoute la table **nommée** que la spec demande, portant l'arête `parent` que `dag.phase` n'a pas, **sans ALTER** de la table antérieure (anti-écrasement, §9). `dag` est un schéma de **vérité au-dessus de la ligne de flottaison** : l'agent obtient **SELECT seulement** (jamais INSERT/UPDATE/DELETE) ; seul le rôle **writer `aidos`** `INSERT`e un nœud, via un ChangeSet approuvé. Une phase étant content-addressed est **immuable** — une coupe changée est un **nouveau** nœud (un nouveau hash), jamais une édition en place. Les GRANTs S02/S04 antérieurs restent inchangés.
- **`back/cmd/aidos/stable.go`** — la commande `aidos stable <id>`, surface **en lecture seule** (KRD §43/§82.1). Elle lit la coupe courante et calcule le verdict via `phases.IsStable` — le **même** moteur que la route — puis l'imprime en **langage humain** (la lecture, le verdict STABLE/UNSTABLE, les reasons quand instable, et l'adresse de contenu de la phase). Aucune écriture, aucun enregistrement (le nœud est enregistré par le rôle writer dans un ChangeSet). La **source de la coupe** est un catalogue déterministe des coupes canoniques §43 (les mêmes que la fixture : vide / verte / senseur-rouge / lien-périmé) ; brancher la lecture store réelle « donne-moi la coupe + têtes + liens + derniers résultats de senseurs » est une dent ultérieure (**OQ-S23-1**) qui ne change pas cette surface.

## Méta

Le comportement de S23 est prouvé par **trois miroirs** (chacun de la bonne nature) plus un roundtrip de persistance, tous rouges avant le code (le rouge **est** le `/goal`). La décision de coupe est un **algorithme déterministe**, jamais un « agent qui juge si c'est stable » (CLAUDE.md §6/§8 determinism-first — « le juge est déterministe »).

<Steps>
  <Step title="Fixture de coupe (le miroir canonique, N2, authority: above)">
    `back/archive/phases/phases_fixture_test.go` — `reflects=archive.phases.IsStable`, `test_kind=fixture`. `state` = une coupe `{contraintes, liens, senseurs}` + une map de têtes · `command` = `IsStable` · `events` = le verdict `{stable, reasons}`. Les cas : une **coupe vide** est **STABLE** (`reasons` vide — *le critère de base*) ; une coupe où tout lien resout et tout senseur est vert est **STABLE** ; **un senseur rouge** ⇒ **UNSTABLE** et `reasons` le nomme (*le critère de fait*) ; un **lien périmé** (épinglé hors-tête) ⇒ **UNSTABLE** nommé `checkout-submit@v1->createOrder@v2 (stale)` ; un **lien absent** (cible sans tête) ⇒ **UNSTABLE** ; l'id de phase enregistré == `Hash(Canonicalize(body))` (content-addressed, S02). Les artefacts exemples (createOrder, checkout-submit, createOrder.fixture) sont **réutilisés** de S11/S17 ; aucun n'est inventé.
  </Step>
  <Step title="Propriété rapid (l'invariant ∀, N1, authority: below)">
    `back/archive/phases/phases_property_test.go` — `reflects=phases.IsStable`, `test_kind=property`, `cert_language=rapid`. Sur **tout** `(cut, heads, links, sensors)` : `IsStable` est **déterministe** (mêmes entrées ⇒ même `(stable, reasons)`) ; la coupe **vide** est **toujours** stable (vacuité) ; **stable ⇔** tout lien resout vert ∧ tout senseur vert (les **deux** sens du §43) ; **≥1** senseur rouge **OU ≥1** lien non-vert ⇒ **UNSTABLE** ; `reasons` vide **ssi** stable, et chaque reason nomme un offenseur **réel** ; `IsStable` **ne panique jamais** (une coupe/liens malformés rendent un verdict, pas un crash).
  </Step>
  <Step title="Roundtrip de persistance (Testcontainers, intégration)">
    `back/archive/phases/migration_roundtrip_test.go` — applique le baseline S02 (qui crée le schéma `dag` + `dag.phase`) puis la migration S23 contre un vrai Postgres jetable : `dag.stable_phase` existe avec le CHECK content-address (une ligne `version ≠ id` est **refusée**) ; le `parent` (l'arête DAG §44) est enregistré (NULL pour une racine) ; **expand-only** (le `dag.phase` S02 est intact) ; **le mur** — l'agent a **SELECT-only**, ses `INSERT/UPDATE/DELETE` sont **refusés** ; le rôle writer `aidos` peut `INSERT`er (l'unique porte, via un ChangeSet).
  </Step>
  <Step title="Jumeau front fast-check (l'invariant côté Workbench)">
    `front/web/lib/phase-stable.test.ts` épingle les **mêmes** invariants côté Workbench (déterminisme, vide⇒stable, tout-rouge⇒instable, stable⇔tout-vert, reasons⇔¬stable), donc l'écran /phase-stable calcule exactement comme le Go `phases.IsStable`.
  </Step>
</Steps>

La **complétude** tient : `dag.stable_phase` / la décision de coupe ont leur miroir vivant (fixture + propriété + roundtrip) ; pas de monstre (pas de vérité sans miroir, pas de miroir orphelin, **aucune** coupe admise stable pendant qu'un lien pend ou qu'un senseur est rouge).

## Méta-méta

Pourquoi **calculer** la stabilité plutôt que la **déclarer** ? Parce qu'une phase stable déclarée est le piège de Goodhart au niveau le plus haut : si « stable » est une affirmation humaine, on l'optimise — on dit « c'est bon » sous pression, et le lockfile ment. KRD §43 pose l'identité dure : une phase stable **EST** « tout lien resout ∧ tout senseur vert », décidée par `Resolve` (S17) et la forme de résultat des senseurs (S07), pas par une heuristique ni un agent. C'est l'application directe de « le juge est déterministe » (§8) : le verdict est une **fonction pure**, rejouable, identique hier et demain. La coupe **vide stable par vacuité** n'est pas un détail : c'est le **cas de base** qui ancre la récursion — le premier point sur lequel on peut s'appuyer, dont toute phase ultérieure descend par une arête ChangeSet. Et le caractère **content-addressed** ferme la boucle anti-écrasement : une coupe **est** son hash, donc on ne peut pas « modifier » une phase stable — on en crée une **nouvelle**, et le DAG garde les deux. L'agent **écrit** ce calcul au build ; il ne **s'assoit pas** dans la boucle à juger ce qu'une fonction juge.

## La place dans le noyau

S23 est une couche **Archive** (l'axe des nœuds du DAG de versions). Elle **réutilise** le `Resolve`/graphe de liens de **S17** sans le forker, la forme de résultat de senseur de **S07**, et le schéma de hash de **S02** sans les éditer ; elle **expose** le verdict par `aidos stable` (la surface CLI S03, pas un nouveau MCP). Elle **ajoute** la table de **nœud** `dag.stable_phase` (au-dessus de la ligne — une vérité, agent SELECT-only) avec son arête `parent`. Elle **prépare** : le **ChangeSet** comme arête temporelle qui déplace d'une phase stable à la suivante (S20, déjà posé) ; le **merge sémantique** (§122/§130, S25) qui rejoue les miroirs sur la coupe fusionnée ; la **curation / quality-diversity** (§44.4, S26) ; et le MCP **`dag`** qui parcourt branches/reverts/merges. Le mur reste intact : `aidos stable` et /phase-stable sont en lecture seule ; enregistrer un nœud passe par le rôle writer `aidos` dans un ChangeSet (propose → approbation).
