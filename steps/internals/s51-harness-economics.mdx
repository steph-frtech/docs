## En une phrase

S51 ajoute `back/runtime/economics` — un **diagnostic pur, en lecture seule**, qui compare le coût de harnais **mesuré** d'une cellule à son `HarnessCostBudget` **déclaré** et rend un `EconomicsDecision` (`within_budget | over_budget_justified | over_budget_flagged`), signalant par un `BlockReason` advisory toute vérité coûteuse non justifiée (KRD §66.3).

## Couche 1 — Implémentation

**Le package Go `back/runtime/economics/economics.go`.** Trois types déclarés et un évaluateur pur :

- `HarnessCostBudget` (`cell_ref`, `max_ci_minutes`, `max_llm_tokens_per_goal`, `max_mutation_runtime_seconds`, `max_human_review_minutes`, `expected_risk_reduction`) — le cap **déclaré** par cellule.
- `MeasuredCost` (`ci_minutes`, `llm_tokens`, `mutation_runtime_seconds`, `human_review_minutes`) — le coût **consommé** (jamais produit ici).
- `ValueCase` (`truth`, `risk_if_broken`, `expected_impact`, `harness_cost`, `decision`) — la justification d'une vérité coûteuse.
- `Evaluate(budget, cost, *valueCase) EconomicsDecision` — **pure et totale**, sans DB, sans I/O, sans `time.Now()`. Règle **per-axis OR** (ADR 0035) : dépasser **un seul** cap est « hors budget » (un coût **égal** au cap est dans le budget — le cap est le plafond inclusif). Dans tous les caps ⇒ `within_budget` (quelle que soit la ValueCase). Hors d'un cap + `ValueCase{justified}` ⇒ `over_budget_justified`. Hors d'un cap sans justified ⇒ `over_budget_flagged` + un `BlockReason` `HARNESS_COST_EXCEEDS_BUDGET` dont le `how_to_fix` est `[open_value_case, reduce_harness_cost, raise_budget_via_goal]`.
- `ValidateBudget` / `ValidateValueCase` — caps non négatifs, `risk_if_broken` ∈ `{low,medium,high,critical}`, `decision` ∈ `{justified,too_expensive,revisit}`, `truth` non vide.
- `SnapshotID` — `Hash(Canonicalize(body))` sur le schéma content-hash **S01/S02** (réutilisé, jamais forké).

**La migration `back/migrations/harness_economics_baseline.sql`** (expand-only / append-only). `fitness.harness_cost_budget` — le cap **déclaré au-dessus de la ligne** : l'agent y est **SELECT-only** (il lit la barre, ne l'écrit jamais), seul le rôle writer `aidos` y INSÈRE (via un ChangeSet S20) ; CHECKs sur l'enum risque et la non-négativité. `runtime.harness_economics_snapshot` — le diagnostic **sous la ligne**, content-addressed (`id = Hash(Canonicalize(body))`), **append-only** (INSERT+SELECT, jamais UPDATE/DELETE) ; CHECKs sur les enums `risk_if_broken` / `decision` / `verdict`. Aucune table, GRANT ou posture lecture-seule de `fitness` antérieure n'est altérée.

**Les miroirs.** Fixture (`economics_fixture_test.go`) : les quatre lignes canoniques `{budget, cost, valueCase} → verdict` — dont **le cas done** (`ci_minutes 18 > 10`, aucune ValueCase ⇒ `over_budget_flagged` + `HARNESS_COST_EXCEEDS_BUDGET`, `how_to_fix ∋ open_value_case`). Property rapid (`economics_property_test.go`) : `Evaluate` déterministe + totale, dans-les-caps ⇒ `within_budget`, hors-d'un-cap-sans-justified ⇒ toujours `over_budget_flagged`, même-coût-justified ⇒ `over_budget_justified`, Validate rejette les mauvaises formes, `SnapshotID` content-addressed. Roundtrip Testcontainers (`migration_roundtrip_test.go`) : les CHECKs d'enum, **le mur** (agent SELECT-only sur le budget déclaré), l'append-only sur le snapshot. Source matérialisée : `tests/runtime/checkout-harness-economics.fixture.md`.

**Le front.** `front/web/lib/economics.ts` — le **twin pur** de l'évaluateur Go (même verdict pour même entrée), couvert par `lib/economics.test.ts` (fast-check, le miroir de reproductibilité). Le panneau `/harness-economics` (`app/harness-economics/page.tsx` + `components/HarnessEconomicsPanel.tsx`) **affiche les cinq caps déclarés** à côté du coût mesuré (dépassement = rouge), la table économique avec verdicts **calculés** par l'évaluateur pur, et la carte ValueCase. Action-capable mais wall-safe : `Proposer un ChangeSet` (stub S20), `ré-évaluer` en lecture seule, **aucun** bouton modifier/supprimer le budget. E2e `tests/e2e/harness-economics.spec.ts` (8 scénarios).

## Couche 2 — Méta

**Pourquoi un diagnostic advisory, pas un nouveau hook.** L'économie du harnais **détecte et conseille** — elle ne bloque rien de non contournable. Le mur **S04** garde déjà `kernel`/`mirrors`/`fitness` au niveau du schéma, et le gate de mutation **S40** + le Stop de complétude détiennent déjà le prédicat d'arrêt non-gameable. Un hook ici serait **mort** tant qu'il n'aurait pas échoué sur un vrai run (§5 honnêteté des hooks). Le code `HARNESS_COST_EXCEEDS_BUDGET` réutilise la **forme** du `BlockReason` S13 (`code`, `severity`, `explanation`, `how_to_fix[]`) sans étendre l'enum-mur fermé : c'est un advisory économique local, pas un refus du mur.

**La même famille que S41.** Un dépassement de budget est une **dette économique** — exactement la même famille advisory que les fixtures périmées, les miroirs orphelins et les mutants survivants de `KernelDebt` (S41). Comme S41, le diagnostic est **pur** (fonction de `(budget, cost, valueCase)`, horloge passée pour l'estampille du snapshot, jamais lue dans la classification), **content-addressed** (S01/S02) et **ne supprime rien** — agir sur la dette est un `idea → mirror → /goal` séparé.

**Le coût est consommé.** S51 ne mesure rien : la télémétrie, les changesets, le run de mutation **S40** et la dépense du `/goal` produisent le coût ; l'économie le **lit**. Construire un compteur ici serait dupliquer une capacité existante (un monstre d'altitude).

## Couche 3 — Méta-méta

**Le budget est la barre déclarée, jamais réglée par la boucle (§8 anti-Goodhart).** C'est le cœur méta-méta de S51 : la cellule **déclare** combien son harnais peut coûter, au-dessus de la ligne, dans `fitness` en lecture seule. L'agent **mesure contre** cette barre ; il ne peut **ni l'écrire ni la relever** (la migration le prouve : agent SELECT-only, REVOKE INSERT/UPDATE/DELETE). Si l'agent pouvait relever le cap pour passer le diagnostic, l'économie serait **Goodhartée** — la barre deviendrait ce que la boucle veut bien tolérer. Relever un cap est donc un `/goal` (un `reweight`/`refine` de la fitness déclarée), une **décision humaine enregistrée**, jamais une édition.

**Déterminisme-first, sans exception LLM.** Tout dans S51 est une fonction pure : la comparaison per-axis est de l'arithmétique, la sélection de verdict est un switch, le hash est un hash, le `BlockReason` est une construction déterministe. Il n'y a **aucune** place pour un agent/LLM dans l'évaluateur — un agent qui ferait ce qu'un comparateur fait serait une **faille de déterminisme** qui bloque le pas. Le seul texte libre est l'`expected_impact` qu'un humain écrit dans une ValueCase : c'est une **donnée**, jamais un jugement dont l'évaluateur dépend. Le miroir de reproductibilité (rapid côté Go, fast-check côté front) pin que même entrée → même verdict, sur les deux plans.
