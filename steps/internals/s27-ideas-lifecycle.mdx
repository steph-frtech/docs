S27 livre l'**idée** comme **seule porte** vers le noyau (KRD §115/§116/§118) : un record `Idea` **sans gel ni miroir**, ses gestes de cycle de vie **purs** (`Capture` / `Grill` / `Spike` / `Harvest` / `Reject`), et la **barrière** `Promote(idea, mirrorRef)` qui **refuse** toute promotion sans miroir avec `NO_MIRROR_NO_KERNEL`. La **règle** — « une idée n'a ni version ni miroir ; on ne peut pas écrire une idée dans le noyau directement ; la promotion exige un miroir » — est celle de l'humain (KRD §116/§118). Aucune vérité écrite par l'agent (le mur) ; les gestes sont **purs**, et la barrière **délègue** au seul prédicat autoritatif `ideas.Promote`.

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/kernel/ideas/ideas.go`** — le record `Idea` et le contenu-adressage. Les types : **`Status`** = l'ensemble **fermé** `draft | grilled | spiking | harvested | rejected` (pas de sixième statut ; « promote » n'est délibérément **pas** un statut) ; **`Proposes`** = l'ensemble fermé `control | policy | operation | action | entity | product` ; **`Provenance`** (`source ∈ {human, incident}`, `detail` verbatim — l'utterance ou `#NNNN`). **`Idea`** porte `ID` / `Proposes` / `Intent` / `Provenance` / `Status` (+ `RejectReason` quand rejetée) — et **AUCUN** champ `Version` ni `Mirror` : la double absence est rendue **inreprésentable par le type** (il n'y a simplement pas de champ). `Canonicalize` / `Hashed` calculent l'`ID` = hash de contenu du **corps esquissé** `{proposes, intent, provenance}` (le statut est métadonnée de cycle de vie, **hors** adresse) en **réutilisant** `records.Canonicalize` / `records.Hash` (le schéma S01/S02 — jamais un hash forké).
- **`back/kernel/ideas/lifecycle.go`** — les gestes §75 comme transitions **pures** : `Capture(proposes, intent, prov) → Idea{draft}` ; `Grill(draft) → grilled` ; `Spike(grilled) → spiking` (la branche « floue », cliquet OFF) ; `Harvest(grilled | spiking) → harvested` (les deux voies aboutissent au même harvested — indistinguables pour la promotion) ; `Reject(idea, reason) → rejected` (append-only, l'idée est **conservée**). Une transition illégale (ex. spike depuis draft) rend `ErrIllegalTransition` — le mouvement illégal est **bloqué**, jamais effectué en silence. La **barrière** `Promote(i, mirrorRef) → (*Promotion, *BlockReason)` : refuse si l'idée n'est pas harvested **ou** si `mirrorRef == ""` (renvoie `NO_MIRROR_NO_KERNEL`, l'idée **reste harvested**, aucune écriture noyau) ; sinon rend une `Promotion` dont la `ProvenanceIdeaID` pointe **en arrière** vers l'idée (KRD §119). `Promote` ne **mute** jamais l'idée, ne **panique** jamais ; le gel noyau aval est le rôle CLI `aidos` via `/goal`, **pas ici**.
- **`back/migrations/ideas_lifecycle_baseline.sql`** — la migration **expand-only / append-only**, **additive** : elle **réutilise** la table content-adressée S02 `ideas.idea` (elle ne la redéclare ni ne l'altère), ajoute le `CHECK (body ->> 'status' IN ('draft','grilled','spiking','harvested','rejected'))` (les cinq fermés — pas de sixième), et pose les **GRANT** de cycle de vie : l'agent reçoit `INSERT / SELECT / UPDATE` sur `ideas.idea` (le staging **au-dessus** du mur — capturer/avancer), mais `DELETE / TRUNCATE` lui sont **REVOKE** (une idée rejetée est conservée, jamais effacée). Le mur est **inchangé** : la migration **ré-affirme** le `REVOKE INSERT/UPDATE/DELETE` de l'agent sur `kernel.*` et `mirrors.mirror` — il ne peut **jamais** écrire le noyau ni les miroirs ici.
- **`back/hooks/promotion-gate/main.go`** — le hook PreToolUse **promotion-gate** (la règle non-contournable, CLAUDE.md §5). Il **refuse** tout write dans le schéma `kernel` dont la provenance est une idée **sans miroir**, renvoyant `NO_MIRROR_NO_KERNEL` (exit 2). Il **DÉLÈGUE** au seul prédicat autoritatif `ideas.Promote` — il ne **réimplémente** pas la règle (determinism-first). Il utilise un signal `mirror_ref` **injecté** (fourni par le flux `/goal`) — il ne **plonge pas** dans le schéma `mirrors` pour y chercher/écrire un miroir (ce serait un write de vérité que l'agent n'a pas le droit de faire ; le mur tient). **Fail-closed** : un événement non décodable est refusé (une promotion illisible ne doit pas glisser une idée sans miroir dans le noyau).
- **`back/mcp/idea-intake/`** — le serveur MCP (Go MCP SDK, un outil = une op backend) : `idea_capture` / `idea_grill` / `idea_spike` / `idea_harvest` / `idea_reject` / `idea_status` / `idea_list`. Il porte le write-grant `ideas` ; il n'a **délibérément AUCUN** `idea_promote_to_kernel` qui contournerait le miroir — la promotion est le flux `/goal`, et la barrière refuse toute autre porte.
- **Pas de nouveau Skill** (CLAUDE.md §5, choix explicite) : `/grill`, `/spike`, `/harvest`, `/goal` existent déjà comme gestes §75 ; le cycle de vie roule par le MCP `idea-intake` + la boucle standard. **Pas d'écriture noyau / gel** (la mutation `/goal` est ultérieure), **pas de MemoryFirewall / ContextPack** (§119.1, ultérieur), **pas de codegen** (une idée est un candidat, rien à émettre). Un nouvel artefact AJOUTE un garde-fou, jamais ne le retire.

## Méta

Le comportement de S27 est prouvé par **deux miroirs** (chacun de la bonne nature) + le test d'injection de faute du hook + le jumeau front, tous rouges avant le code (le rouge **est** le `/goal`). Le cycle de vie et la barrière sont des **fonctions pures déterministes**, jamais un « agent qui décide si une idée peut entrer dans le noyau » (CLAUDE.md §6/§8 — determinism-first) : le code gagne, et le hook **délègue** au prédicat `ideas.Promote`.

<Steps>
  <Step title="Fixture du cycle de vie (le miroir canonique, N2, authority: above)">
    `back/kernel/ideas/ideas_fixture_test.go` (`reflects=ideas.idea "order-discount-idea"`), comme `state → command → events` : `TestFixture_Capture_Draft_NoFreezeNoMirror` (capture humaine ⇒ Captured, statut draft, **pas de version, pas de miroir** par type) ; `TestFixture_Grill` / `TestFixture_Spike` / `TestFixture_Harvest_FromSpiking` (les transitions) ; `TestFixture_PromoteWithoutMirror_Blocked` (**LE critère done** — promote `mirror:none` ⇒ Blocked, `NO_MIRROR_NO_KERNEL`, `how_to_fix` contient l'écriture-du-miroir, l'idée **reste harvested**, aucune écriture noyau) ; `TestFixture_PromoteWithMirror_Promoted` (promote avec un vrai miroir ⇒ Promoted, provenance pointant **en arrière** vers l'idée) ; `TestFixture_HarvestDirect_StillNeedsMirror` (harvested-direct et harvested-via-spike exigent **tous deux** le miroir) ; `TestFixture_Reject_Traced` (rejected, l'idée **reste présente**) ; `TestFixture_IllegalTransitions_Blocked` (les mouvements illégaux refusés).
  </Step>
  <Step title="Propriété rapid (les invariants ∀, N1, authority: below)">
    `back/kernel/ideas/ideas_property_test.go` — sur **toute** séquence de `capture/grill/spike/harvest/reject/promote` : `TestProperty_LifecycleInvariants` (les statuts atteignables sont **exactement** les cinq ; une `Idea` ne porte **jamais** de version/miroir — le type l'interdit ; `Promote` réussit **uniquement si** un miroir non-vide est fourni — sinon `BlockReason`, aucune écriture noyau, le mur tient pour **chaque** idée ; `Reject` est **append-only** ; `id == hash` du corps canonique) et `TestProperty_Deterministic` (même entrée ⇒ même sortie — la **reproducibilité**).
  </Step>
  <Step title="Hook fault-injection + MCP + roundtrip + jumeau front + e2e">
    `back/hooks/promotion-gate/main_test.go` **casse ce qu'il surveille** : `TestGateBlocksMirrorlessPromotion` (une promotion sans miroir ⇒ le hook rouge, `NO_MIRROR_NO_KERNEL`), `TestGateAllowsPromotionWithMirror`, `TestGateBlocksNonHarvested`, `TestGateIgnoresNonKernelTarget`, `TestGateFailsClosedOnGarbage` (un événement illisible ⇒ deny). `back/mcp/idea-intake/main_test.go` (`TestIdeaIntakeLifecycleEndToEnd`) parcourt capture→grill→spike→harvest→reject par les outils. `back/kernel/ideas/migration_roundtrip_test.go` (Testcontainers) prouve sur un vrai Postgres : `TestIdeaRoundTripsAsJSONB`, `TestLifecycleStatusCheckRefusesSixthStatus` (le CHECK refuse un statut inventé), `TestAgentRoleCanCaptureAndAdvanceButNotDelete` (INSERT/SELECT/UPDATE OK, DELETE refusé — append-only), `TestAgentRoleStillCannotWriteKernelOrMirrors` (le mur tient). Le jumeau front `front/web/lib/ideas.test.ts` (fast-check) épingle les **mêmes** invariants sur `lib/ideas.ts`, et l'e2e Playwright `tests/e2e/ideas.spec.ts` prouve le critère done **à l'écran** : draft avec intent+provenance et le marqueur « pas de miroir » ; le badge avance jusqu'à harvested ; promote sans miroir rend **rouge** `NO_MIRROR_NO_KERNEL` et l'idée **reste harvested** ; promote avec miroir montre le chemin Promoted + le lien de provenance ; une idée rejetée **reste visible** dans la voie rejected.
  </Step>
</Steps>

La **complétude** tient : `ideas.idea` (la zone de staging) a son miroir vivant (fixture + propriété + roundtrip migration Testcontainers + test d'injection de faute du hook + jumeau front + e2e) ; pas de monstre (aucune branche de statut sans ligne de fixture ; la barrière de promotion est le **point unique** qui force « sans miroir ⇒ pas de noyau » ; une idée rejetée est conservée, jamais détruite en silence).

## Méta-méta

Pourquoi une **zone de staging** entre le désir et le noyau, et pourquoi la **double absence** (ni version, ni miroir) plutôt qu'un simple « brouillon de vérité » ? Parce que le danger fondamental est d'aller **du prompt au code directement** (CLAUDE.md, règle cardinale). Si l'on pouvait graver une intention dans le noyau sans **preuve**, on accumulerait des **vœux** — des vérités sans miroir, des **monstres**. L'idée résout ça en **donnant la forme d'une vérité sans en avoir le pouvoir** : elle a un corps (proposes/intent/provenance) mais ni tête-preuve ni gel, et le **type lui-même** rend ces deux champs inreprésentables — on ne peut donc **structurellement pas** confondre une idée avec une vérité. La conséquence profonde, c'est que la **seule porte** vers le noyau devient « écris le miroir » — et écrire le miroir, **c'est** le `/goal`, **c'est** le gel (KRD §116). Il n'y a pas deux chemins : il y en a **un**, et il passe par la preuve. Le `NO_MIRROR_NO_KERNEL` n'est donc pas une vérification de plus — c'est l'**incarnation runtime** d'une asymétrie : l'agent peut **proposer** (capturer/avancer des idées au-dessus du mur) mais ne peut **figer** (le mur refuse l'écriture noyau ; seul le rôle `aidos` via `/goal` le fait). Enfin, que tout le cycle de vie soit **pur** — `Capture`/`Grill`/`Spike`/`Harvest`/`Reject`/`Promote` sans horloge, sans rng, sans I/O, ne mutant jamais leur entrée — et que le hook **délègue** au prédicat `ideas.Promote` plutôt que de le réimplémenter, c'est ce qui rend la barrière **rejouable et infalsifiable** : la même idée et la même référence de miroir rendent toujours le même verdict, et il n'existe **aucun** chemin où un agent « jugerait » qu'une idée mérite le noyau. Le Juge, ici aussi, est le **miroir**.
