S25 livre le **décideur de fusion sémantique** (KRD §122/§130) : la fonction **pure** `MergeSemantic(base, gauche, droite, heads) → MergeResult`, le geste **`/merge-semantic`** et la route Workbench **/semantic-merge**. La **règle** — « fusionner deux branches de vérité est sémantique, pas textuel ; le miroir décide le conflit (rouge sur la coupe fusionnée, §109) ; une fusion git-propre avec un miroir rouge est bloquée ; résoudre un conflit est un override humain » — est celle de l'humain (KRD §122/§130 + la loi `no_merge_without_semantic_green`, §82.2). Aucune vérité écrite par l'agent (le mur) ; `MergeSemantic` et `/merge-semantic` sont des **décideurs en lecture seule**.

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/archive/merge/merge.go`** — le cœur **pur** (aucune I/O, aucune horloge, aucun rng, **aucune écriture**). Les types : **`Base`** (l'ancêtre commun, S23 : `id`, `cut`, `links`, `sensors`, `heads`), **`Branch`** (un côté : `ancestor` = l'id dont la branche descend, `deltas` = sa sélection vs base, `links`, `added_sensors`), **`MergeResult`** (`status`, `conflicting_mirrors[]`, `merged_cut_hash`, `requires_authority`, `open_question`). Le **status** est un ensemble **fermé** : `clean` | `conflict` | `unresolvable` (pas de quatrième statut — la propriété rapid l'épingle). **`MergeSemantic(base, gauche, droite, heads)`** : (1) vérifie la **mappabilité** — `gauche.ancestor == droite.ancestor == base.id` (§120) ; sinon **`unresolvable` + OpenQuestion**, jamais un `clean` deviné ; (2) **assemble la coupe fusionnée** — l'union `base.cut + gauche.deltas + droite.deltas` (ordre déclaré : base, puis gauche, puis droite), les liens concaténés, les senseurs dé-dupliqués par id (dernier écrivain en ordre base/gauche/droite — une branche qui rouvre un invariant émergent rougit le senseur) ; (3) **demande l'oracle** `phases.IsStable` sur cette coupe ; (4) VERT ⇒ `clean`, `conflicting_mirrors == []` ; au moins un rouge ⇒ `conflict`, `conflicting_mirrors` = les `reasons` de IsStable, `requires_authority == true`. Le `merged_cut@hash` est l'adresse de contenu (S02) de la coupe proposée. Total, déterministe, **ne panique jamais**.
- **Réutilisation, pas réinvention** — la décision VERT/ROUGE de la coupe fusionnée est rendue **uniquement** par `phases.IsStable` de **S23** (l'oracle de coupe cohérente, qui réutilise lui-même `links.Resolve` de S17 + le verdict senseur de S07 + l'agrégat récursif référencé de S18/§109). `MergeSemantic` ne ré-implémente **jamais** l'agrégat (S18), la propagation pondérée (S19) ni la vague de rouge (S22) — il **assemble** la coupe et **lit** le verdict. L'adresse de contenu réutilise `records.Canonicalize` + `records.Hash` de **S02** (via `phases.StablePhase.Version()`, un body `records.KindPhase`), jamais un schéma de hash forké. La **seule** logique propre à ce paquet est l'**assemblage de la coupe** (l'union de sélection).
- **`.claude/skills/merge-semantic/SKILL.md`** — le geste **rejouable** « fusionner deux branches sémantiquement » : charger `base`/`gauche`/`droite` (via le rôle SELECT-only / les refs de nœud DAG de S23/S24), construire la coupe fusionnée, rejouer l'agrégat (S18) + la vague de rouge (S22) dessus, et router par `MergeResult` — un `clean` peut être enregistré comme phase stable (S23) via un ChangeSet (S20) ; un `conflict` est **bloqué** et surface les `conflicting_mirrors[]` à un humain comme décision d'override (`requires_authority`, S16). Un geste, rejoué à l'identique.
- **Pas de migration, pas de hook, pas de MCP, pas de verbe CLI** (CLAUDE.md §5, choix explicite) : la coupe fusionnée est content-addressed via S02 (pas de nouvelle table de vérité) ; la règle `no_stable_phase_with_red_mirror` est déjà tenue par le gate de phase S23 (une coupe en conflit n'est pas une phase stable) — on **réutilise** ce gate ; `/merge-semantic` lit par le rôle SELECT-only et décide, enregistrer un `clean` roule sur le chemin ChangeSet S20 ; `aidos merge` est une dent ultérieure. Un nouvel artefact AJOUTE un garde-fou, jamais ne le duplique.

## Méta

Le comportement de S25 est prouvé par **deux miroirs** (chacun de la bonne nature) plus le jumeau front, tous rouges avant le code (le rouge **est** le `/goal`). La décision est un **algorithme déterministe**, jamais un « agent qui décide si la fusion est propre » (CLAUDE.md §6/§8 — determinism-first) : le code gagne, l'oracle est `phases.IsStable`.

<Steps>
  <Step title="Fixture de fusion (le miroir canonique, N2, authority: above)">
    `back/archive/merge/merge_fixture_test.go` — `reflects=archive.merge.MergeSemantic`, `test_kind=fixture`. `state` = la base + les verdicts de miroir pertinents · `command` = les têtes gauche/droite à fusionner · `events` = le `MergeResult`. Les rangées : **fusion refund EU/US textuellement propre** (déltas disjoints, git auto-fusionnerait) **avec** un miroir refund rouge sur la coupe ⇒ **`conflict`**, `refund ∈ conflicting_mirrors`, **BLOQUÉ → requires_authority** (*LE critère done*) ; **deux changements de lignes disjointes** (pay-button / amount-field) cassant le **même** invariant émergent `cart.own_mirror` ⇒ **`conflict`** (le rouge que git ne voit jamais) ; **paire en espace libre** (promo-banner / help-link) ⇒ **`clean`**, `conflicting_mirrors == []` (phase stable candidate) ; **paire sans ancêtre commun** ⇒ **`unresolvable` → OpenQuestion** (jamais un `clean` fabriqué, jamais une auto-fusion) ; **fusion de la base avec elle-même** ⇒ **`clean`** (identité, no-op sans conflit fantôme).
  </Step>
  <Step title="Propriété rapid (l'invariant ∀, N1, authority: below)">
    `back/archive/merge/merge_property_test.go` — `reflects=archive.merge.MergeSemantic`, `test_kind=property`, `cert_language=rapid`. Sur **tout** `(base, gauche, droite)` : **déterministe** (même entrée ⇒ même `MergeResult`) et **total** (`status ∈ {clean, conflict, unresolvable}`) ; **tout miroir rouge** sur la coupe fusionnée ⇒ `conflict` (jamais `clean` — le miroir décide) ; un agrégat **entièrement vert** ⇒ `clean ∧ conflicting_mirrors == []` ; `MergeSemantic(base, base, base)` d'une base verte ⇒ `clean` no-op ; une paire **textuellement propre** (déltas disjoints) avec un miroir rouge ⇒ `conflict` (la cleanliness textuelle ne prime **jamais** sur un rouge) ; un `conflict` ⇒ `requires_authority ∧ conflicting_mirrors` non vide ; **pas d'ancêtre commun** ⇒ `unresolvable ∧ OpenQuestion ∧ pas de hash fabriqué` ; **jamais de panique** (même sur cut/senseurs/liens nil) ; **jamais d'écriture** (pur sur ses entrées).
  </Step>
  <Step title="Jumeau front fast-check (l'invariant côté Workbench)">
    `front/web/lib/semantic-merge.test.ts` épingle les **mêmes** invariants côté Workbench (déterminisme, any-red⇒conflict, all-green⇒clean, identité⇒clean-no-op, texte-ne-prime-jamais-sur-rouge, unresolvable⇒pas-de-clean-fabriqué, totalité) sur le jumeau `lib/semantic-merge.ts`, plus les trois critères done sur les triplets canoniques — donc l'écran /semantic-merge décide exactement comme le Go `MergeSemantic` / le geste `/merge-semantic`. Un e2e Playwright (`tests/e2e/semantic-merge.spec.ts`) prouve le critère done **visible à l'écran** : la paire refund EU/US rend `conflict` + « bloqué, override requis », la paire cart rend `conflict`, la paire en espace libre rend `clean`.
  </Step>
</Steps>

La **complétude** tient : `archive.merge.MergeSemantic` a son miroir vivant (fixture + propriété + jumeau front + e2e) ; pas de monstre (aucune vérité sans miroir, aucun miroir orphelin, aucun `clean` fabriqué admis à la place d'`unresolvable`, aucune auto-fusion d'un conflit).

## Méta-méta

Pourquoi laisser le **miroir** décider la fusion plutôt que le **diff de texte** ? Parce que la fusion textuelle répond à la mauvaise question. Git demande « les lignes se chevauchent-elles ? » — mais la **vérité** d'un système n'est pas dans ses lignes, elle est dans son **comportement**, et deux changements aux lignes disjointes peuvent **casser ensemble** un invariant qu'aucun ne cassait seul (KRD §122). Un merge « propre » par le texte peut donc **livrer un monstre** : un système qui compile mais ment. KRD pose que la fusion est jugée sur la **coupe fusionnée** par l'**agrégat récursif** (§109) — VERT seulement si **chaque** partie et l'invariant émergent du tout sont verts **à la fois**. Et que ce jugement réutilise **exactement** l'oracle d'une phase stable (`phases.IsStable`, S23) n'est pas un raccourci : c'est l'unification profonde — une fusion n'est qu'une **phase stable candidate** dont la coupe a deux origines. Le décideur étant une **fonction pure** (jamais un agent qui « juge si ça fusionne »), il applique « le juge est déterministe » (§8) : même `(base, gauche, droite, senseurs)` ⇒ même verdict, hier comme demain, et la même coupe rend toujours la même adresse de contenu (S02). Enfin, refuser de **fabriquer** un `clean` pour une fusion non mappable (rendre `unresolvable → OpenQuestion`) est l'honnêteté anti-Goodhart : on ne **devine** jamais le vert pour faire avancer une fusion ; un trou reste un trou, ouvert et nommé.

## La place dans le noyau

S25 est une couche **Archive** (le décideur de fusion du DAG de versions). Elle **réutilise** l'oracle de coupe cohérente de **S23** (`phases.IsStable`, qui réutilise `links.Resolve` de S17 + le verdict senseur de S07 + l'agrégat récursif référencé de S18/§109), l'adresse de contenu de **S02** (`records.Hash`/`Canonicalize`, jamais forkée), et `requires_authority` de **S16** — sans les éditer, sans forker l'agrégat (S18), la propagation (S19) ni la vague de rouge (S22). Elle **ajoute** le paquet pur `back/archive/merge` (`MergeSemantic`/`MergeResult`, en lecture seule), le geste `/merge-semantic` et la route `/semantic-merge`. Elle n'ajoute **aucune** table de vérité, **aucun** hook, **aucun** MCP, **aucun** verbe CLI (choix explicites, §5). Elle **prépare** : le câblage du résultat `clean` dans le gate ChangeSet S20 (DRAFT→APPLIED) pour qu'une fusion propre devienne une transition de phase stable enregistrée ; la **promotion gated-by-mirror** des branches évolutives (§124, **S26**). Le mur reste intact : `MergeSemantic` et `/merge-semantic` sont des décideurs en lecture seule ; appliquer une fusion propre passe par le chemin ChangeSet S20 (propose → approbation), et résoudre un conflit est une décision d'override humaine enregistrée — jamais une écriture depuis l'écran.
