S18 livre l'**agrégat de vérité compositionnelle** (KRD §108–§112) : le **lien `composes`** comme valeur (parent/enfant épinglés, poids `load-bearing | cosmetic`), un **`Aggregate` récursif pur** `(tree, root) → {GREEN | RED}` qui **consomme** le verdict `own_mirror` de S06 (il ne le re-dérive jamais), l'**activation pondérée et seuillée** de §112, et une **garde de cycle typée**. La **loi** « un composite est vert ssi son propre miroir et tous ses enfants le sont » est celle de l'humain (KRD §109) ; les **arêtes/poids/seuils** d'un vrai projet sont déclarés au-dessus de la ligne. Aucune vérité écrite (le mur).

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/kernel/composes/composes.go`** — le cœur **pur** (aucune I/O, aucune horloge, aucun rng). Le **lien** : `Composes{ Parent Ref, Child Ref, Weight }` où `Ref{ ID, Version }` épingle les deux extrémités et `Weight` est un ensemble **fermé** de deux (`WeightLoadBearing`, `WeightCosmetic`). Le **read-model** : `Node{ LayerID, Version, OwnMirror Verdict, ActivationThreshold }` — `OwnMirror` est **consommé** de S06, jamais re-typé. `Tree{ Nodes, Edges, Changed }` est l'entrée pure. `Aggregate(t, rootID) (Result, error)` calcule, **récursivement et inconditionnellement** (§109) : `verdict := own_mirror` ; pour chaque enfant `composes`, si `Aggregate(enfant) == RED` alors `verdict := RED`. Il rend `Result{ Verdict, DrillDown []PathStep }` — le chemin descend du nœud interrogé vers l'enfant rouge (§110). `Aggregate` est **total** sur un DAG (toujours `GREEN | RED`), **déterministe**, **ne panique jamais** ; sur un **cycle** il rend un `*CycleError` typé nommant les couches (jamais de récursion infinie, jamais d'arête inventée). `Activation(t, parent)` somme `Σ poids(enfants changés)` (cosmetic = 0) ; `ReopensOnChange(t, parent)` rend `activation ≥ seuil_déclaré` — le **signal de changement** que S19 consommera, indépendant du verdict §109. `SerializeComposesBody` **réutilise** le content-hash de S02 (`records.NewRecord` / `Canonicalize` / `Hash`) pour faire chevaucher le lien dans le corps `kernel.link` (`{kind:"link", link_kind:"composes", parent, child, weight}`).
- **`back/migrations/kernel_composes_baseline.sql`** — la migration **Atlas additive, expand-only**. **Choix de placement (l'OpenQuestion S18, tranchée — ADR 0017)** : le **poids** chevauche **dans** le corps JSONB existant de `kernel.link` (exactement la forme S17 — un seul motif, aucun `ALTER`), exposé pour inspection par une **vue** `kernel.composes_edge` ; le **`activation_threshold`** va dans une **nouvelle table append-only** `kernel.layer_activation` (et **non** un `ALTER` de `kernel.layer` — expand-only, jamais muter une table antérieure). Les deux sont des **vérités déclarées** (KRD §112 — jamais apprises) ; le rôle agent reçoit **SELECT-only** et se voit **REVOKE** tout écriture (le mur). Elle **n'altère ni ne dépose** aucune table antérieure (S02 / S17 intacts).

## Méta

Le comportement de S18 est prouvé par **deux miroirs** (chacun de la bonne nature), tous rouges avant le code (le rouge **est** le `/goal`).

## La route Workbench

`front/web/app/truth-tree/page.tsx` → **`/truth-tree`** : Server Component (intro + tutoriel + exemple), arbre rendu par le client `components/TruthTree.tsx` qui joue l'`aggregate` **pur** par nœud contre les miroirs propres basculables — aucune I/O, aucune horloge, aucun rng. Chaque nœud montre son **propre miroir** ET son **agrégat** ; chaque arête son **poids** `composes` et sa **version épinglée** ; chaque composite son **seuil** ; le **drill-down** liste le chemin vers l'enfant rouge. **Lecture seule** (le mur) : le bouton ne change que le snapshot des miroirs propres contre lequel l'agrégat tourne. Thémée (ADR 0010), bilingue (ADR 0011). E2e `tests/e2e/truth-tree.spec.ts` : nœuds + badges de poids, tout vert ⇒ racine **GREEN**, feuille porteuse **RED** ⇒ racine **RED** avec drill-down nommant le control, changement cosmetic ⇒ racine **GREEN**.

## Méta-méta

Pourquoi un agrégat **récursif et pur** plutôt qu'un drapeau « complet » par couche ? Parce que la **vérité d'un tout** n'est pas un fait local : `truth(composite) = Σ truths(parts) + propre vérité émergente`. Un agrégat qui consomme `own_mirror` (au lieu de le re-dériver) garde **une seule source de vérité** par nœud (S06) et n'ajoute que la **composition** — pas un second juge. Mettre le **changed-set** et le **seuil** **hors** du verdict §109 (dans `Activation`/`ReopensOnChange`) sépare deux questions distinctes : *« le tout est-il vert ? »* (la loi, inconditionnelle) et *« ce changement doit-il rouvrir le miroir émergent du parent ? »* (l'activation §112, le signal que S19 pondère). Et **déclarer** poids et seuil au-dessus de la ligne — jamais les apprendre — est la garde anti-Goodhart de §112 : un système qui **apprendrait** ses propres seuils pourrait se rendre vert en abaissant la barre. Ici la barre est **humaine**. La garde de cycle, enfin, rend l'impossible **explicite** (un `*CycleError` typé, KRD §82) plutôt que de boucler en silence.

## Les deux touches de contrat antérieur → ChangeSet + SemanticDiff (ADR 0017)

S18 ne **réécrit pas** S06 ni S12. Deux généralisations sont **enregistrées** comme SemanticDiff (kind **refine**) et seront **appliquées** par le moteur de ChangeSet (S20) quand il atterrira : (1) la complétude **plate** de S06 (`Mirror.aggregate`) → la **loi récursive** (le verdict plat est le cas dégénéré single-node) ; (2) l'entrée du **Stop de S12** nourrie de `Aggregate(L)` au lieu du verdict plat (la forme du `Gate` est inchangée ; seule la source du verdict se généralise, et le hook de S12 **importe** ce paquet plutôt que de ré-implémenter l'agrégation). Les deux ChangeSets restent **DRAFT** (enregistrés, non appliqués) jusqu'à S20/S21. Aucun fichier source de S06/S12 n'est édité par S18.

## La place dans le noyau

S18 est une couche **Kernel** (le lien `composes` + la loi récursive). Elle **réutilise** le content-hash de S02 sans le forker, **consomme** le `own_mirror` de S06, **généralise** sa complétude plate, **prépare** S19 (la propagation pondérée bidirectionnelle, via `Activation`/`ReopensOnChange`) et nourrit le Stop de S12. Le mur reste intact : `kernel.layer_activation` est SELECT-only pour l'agent ; toute écriture passe par propose → ChangeSet → approbation.
