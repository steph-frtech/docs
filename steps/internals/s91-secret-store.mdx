## Implémentation

S91 ajoute le **secret store par app** : `back/runtime/secretstore`. Il détient les secrets de l'app émise (credentials DB, clés API tierces, secrets OAuth), **chiffrés au repos**, **scopés `project_id`**, **jamais** dans le truth-store / git / source émis (DP32, ADR 0043).

**Le chiffrement + l'isolation cryptographique.** `SecretStore` est bâti sur **AES-256-GCM** (`crypto/aes` + `crypto/cipher`). Le load-bearing : le `project_id` est lié dans l'**AAD** (additional authenticated data) de chaque valeur — `aad(projectID)`. Une valeur scellée pour le projet A porte l'AAD de A ; l'ouvrir sous le projet B **échoue la vérification du tag GCM**. L'isolation cross-projet n'est donc **pas** une convention (une clé de map), c'est une frontière **cryptographique** : `Get(B, name)` sur un secret de A renvoie `ErrNotFound`, fail-closed.

**Le scellage reproductible.** La seule non-déterminisme est le **nonce GCM** (une nécessité cryptographique — réutiliser un nonce sous une clé est catastrophique). Il passe par un `Sealer` : `randSealer` (production, `crypto/rand`) ou `NewFixedSealer(seed)` (le miroir de reproductibilité, nonce fixe → ciphertext byte-stable). La valeur en clair est scellée immédiatement et **jamais retenue**.

**L'historique append-only.** `Set` supersède la version live précédente puis appende la nouvelle (la forme S02 réutilisée sous la ligne). `Rotate(project, name, newValue)` réutilise `Set` : la nouvelle valeur devient live, l'ancienne est marquée `superseded` et **jamais re-servie** par `Get` — le critère « la rotation invalide l'ancien secret ». Une rotation d'un secret absent → `ErrNotFound` (on *Set* ce qui n'existe pas, on *Rotate* ce qui existe).

**L'injection au boot (le critère missing-at-boot).** `InjectEnv(projectID, declaredKeys)` est un **set-difference pur** : `dedupeSorted(declared) − present`. Si la différence est non vide → un `blockreason.BlockReason{Code: CodeSecretMissingAtBoot}` **fail-closed**, dont l'explication **nomme les clés manquantes** ; jamais un credential vide/deviné. Sinon il renvoie les `EnvKV` **triés** (`APP_SECRET_<NOM>=<valeur live>`), chaque valeur déchiffrée — le secret ne touche jamais le disque en clair.

**Le scanner anti-fuite (le critère « scan = code »).** `ScanEmission(source, knownValues)` est une fonction **pure** sur les octets émis : un jeu fermé de `leakRules` (regex gitleaks-style — clés AWS, en-têtes de clé privée, bearer tokens, URI Postgres avec mot de passe, affectation à une variable au nom-de-secret) **plus** une recherche verbatim des valeurs de secret connues. Les `Finding` reviennent en ordre stable `(line, rule)` ; l'`Excerpt` est **redacté** (`[REDACTED]`) pour que le rapport ne re-émette jamais le secret en clair. `IsClean` est le booléen que la gate d'émission lit.

**La vue sans-fuite.** `StoreFingerprint(projectID)` est un content-address déterministe des **noms + ciphertext** d'un projet (jamais une valeur en clair) — le « ce qui est stocké » que le Workbench rend sans rien exposer.

**Le code BlockReason.** `CodeSecretMissingAtBoot` ("SECRET_MISSING_AT_BOOT") est ajouté à l'enum fermé de `back/runtime/blockreason` (extension additive, `change_type: refine`), avec son explication FR + un `how_to_fix` non vide (déposer / vérifier le scope / faire une rotation / relancer le boot).

**Le MCP `aidos-secretstore`** (`back/mcp/secretstore`, ADR 0009) expose `set` · `rotate` · `inject` · `scan` · `fingerprint`. **Délibérément pas de `get` brut** : une valeur ne sort que comme variable d'env au boot (`inject`) — le MCP n'est jamais un canal de lecture-de-tout. **Le twin TS** `front/web/lib/secret-store.ts` reflète les jugements purs (le set-difference, le scan, l'isolation par clé) et alimente la route **action-capable** `/secret-store` (SET / ROTATE / INJECT / SCAN — exécutables depuis l'écran, valeurs jamais affichées).

**Les miroirs.** rapid (`secretstore_property_test.go`) : isolation cross-projet (B ne lit jamais A), scan **sound ∧ complete** sur la valeur, scellage **reproductible** (nonce fixe → ciphertext identique + `InjectEnv` déterministe), `InjectEnv` fail-closed (BlockReason ssi une clé manque). Fixtures (`secretstore_fixture_test.go`) : rotation invalide l'ancien secret, missing-at-boot lève un BlockReason actionnable (la clé nommée), le scan trouve URI/AWS/private-key/valeur + passe une émission propre, A ne fuit jamais vers B. fast-check (`secret-store.test.ts`, 8/8) côté twin ; Playwright (`secret-store.spec.ts`, 6/6) côté écran.

## Méta

S91 trace une ligne nette entre **vérité** et **matériel opérationnel**. Un secret n'est pas une vérité du Kernel : il ne porte pas de comportement, il n'a pas de miroir, il n'entre jamais dans le truth-store. Il vit **sous le mur** (CLAUDE.md §2), dans le store chiffré — exactement comme une projection ou un artefact `gen/`. Ce qui *est* une décision Kernel, c'est **quels secrets l'app déclare avoir besoin** (porté par les sources operation/connecteur) ; S91 ne fait que vérifier cet ensemble déclaré contre ce qui est présent. La porte vers le noyau reste `idée → miroir → /goal` ; S91 n'en franchit aucune.

Le choix « pas de `get` brut » est l'application du **principe du moindre canal** : un secret ne quitte le coffre que par la frontière d'injection (variables d'env au boot), jamais par une lecture arbitraire. C'est ce qui empêche le MCP — par construction — de devenir un canal de fuite. L'AAD `project_id` pousse l'isolation **dans la couche cryptographique** plutôt que dans le code applicatif : même un bug de routage ne peut pas ouvrir le secret d'un autre projet.

## Méta-méta

S91 est du **déterminisme-first** appliqué à la sécurité (CLAUDE.md §6/§8) : tout jugement *peut* être une fonction pure, donc l'**est**. Le manque-au-boot est un **set-difference** (déclarées − présentes), pas un avis ; le scan anti-fuite est du **pattern-matching** (regex + recherche verbatim), pas un « LLM qui cherche des secrets » — un agent qui ferait ce qu'une fonction peut faire serait un **trou de déterminisme** qui bloquerait l'étape, au même titre qu'un monstre. La seule entropie est le nonce GCM, une nécessité cryptographique, isolée derrière un `Sealer` pour que le miroir de reproductibilité puisse fixer le nonce et asserter un ciphertext byte-stable.

Et S91 est **fail-closed** partout : un secret manquant → boot refusé ; une valeur d'un autre projet → `ErrNotFound` ; une rotation d'un absent → refusée ; un scan trouve une fuite → l'émission n'est pas propre. Jamais une dégradation silencieuse, jamais une valeur fabriquée (§8 : on n'invente pas une valeur). Le refus porte toujours un `BlockReason` actionnable — le mur bloque sans devenir une prison (KRD §44.5).
