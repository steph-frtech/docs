<Info>Côté détail. Pour le concept, voir [Pour les futurs utilisateurs → S20](/steps/concept/s20-changeset).</Info>

S20 livre l'**enveloppe ChangeSet** (KRD §44, §98, §44.1) : l'enveloppe transactionnelle **atomique et réversible** qui déplace le noyau d'une phase stable à la suivante, enveloppant `spec_delta` (Kernel) et `mirror_delta` (Mirror) **ensemble** dans un corps **adressé par contenu** pour qu'ils ne dérivent jamais. États `DRAFT | APPLIED | REVERTED` uniquement (pas de `FAILED`) ; un `APPLIED` est **immuable** ; un revert est un **nouveau ChangeSet inverse** ajouté au journal (append-only). La **règle** — « un APPLIED est immuable ; un revert est un inverse ajouté ; le commit n'est admis que si la complétude tient » — est celle de l'humain (KRD §44/§98). Aucune vérité écrite par l'agent (le mur).

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/archive/changeset/changeset.go`** — le cœur **pur** (aucune I/O, aucune horloge, aucun rng). Le **Status** est un ensemble **fermé** de trois (`StatusDraft`, `StatusApplied`, `StatusReverted`) — `Statuses()` le rend en ordre canonique pour qu'aucun aval ne l'invente ; il n'y a **pas** de `FAILED`. Le **Delta** porte `Kind` (`add`/`remove`/`refine`, sous-ensemble §44.1), `Target` et un `Body` opaque ; `invert()` négatie le `Kind` (`add` ⇄ `remove`) en conservant `Target`/`Body`, de sorte que **inverser deux fois reconstruit l'original**. Le **ChangeSet** porte `ID`, `Label`, `Status`, `ParentPhase`, `SpecDelta`, `MirrorDelta`, `Reverts`, `AppliedAt`. L'`ID` est le **content hash** (SHA-256 hex) du **corps canonique** (`{kind, label, parent_phase, spec_delta, mirror_delta, reverts}` — **pas** du `Status`/`AppliedAt`, qui sont des estampilles de cycle de vie), donc l'id est **stable** à travers `DRAFT → APPLIED` (le même schéma que le content-store S01, jamais forké). Les fonctions : `Open(label, parentPhase, spec, mirror)` rend un `DRAFT` adressé ; `Apply(cs, appliedAt, complete)` rend une copie `APPLIED` **seulement si** `complete(cs)` passe (sinon le `*BlockReason`, la source non mutée), avec `appliedAt` passé en **argument** (pureté) ; `Edit(cs)` refuse toute édition d'un `APPLIED`/`REVERTED` (`APPLIED_IS_IMMUTABLE`) ; `Revert(source)` construit l'inverse `DRAFT` (deltas négatiés, `reverts == source.ID`) **sans muter la source** ; `StampReverted(source)` rend la copie `REVERTED` (la seule écriture de lignée légale) ; `Discard(cs)` autorise la suppression d'un `DRAFT` (jamais d'un `APPLIED`). La **CompletenessFn** est **injectée** (ce paquet ne touche jamais les schémas kernel/mirrors — le mur) ; le prédicat minimal `SpecHasMirror` refuse un `spec_delta` sans `mirror_delta` par `INCOMPLETE_CHANGESET` + `how_to_fix: [add_mirror_for_spec_delta]`.
- **`back/archive/changeset/store.go`** — l'adaptateur **pgx** append-only (`Persist`/`Stamp`/`Discarded`/`Get`/`List`). Une transition d'état est un **nouvel** enregistrement de cycle de vie (`nextVersion` incrémente v1, v2, … sous transaction), jamais un `UPDATE` en place. `Get`/`List` lisent la vue `changesets.changeset_envelope`.
- **`back/migrations/changesets_lifecycle_baseline.sql`** — la migration **Atlas additive, expand-only**. Elle **n'altère ni ne dépose** la table S02 `changesets.changeset` (le corps de l'enveloppe — l'atome spec+miroir vit **dans** ce JSONB). Elle ajoute la **table d'estampille** `changesets.changeset_lifecycle` portant **deux CHECK** qui **sont** le mur au niveau base : `status IN ('DRAFT','APPLIED','REVERTED')` (l'ensemble fermé — pas de `FAILED`) et `(status = 'DRAFT') = (applied_at IS NULL)` (l'`applied_at` est posé ssi commité). La **vue** `changesets.changeset_envelope` joint le corps S02 à son estampille S20 et surface `spec_delta`/`mirror_delta` **ensemble** depuis l'unique corps. Le rôle agent reçoit **SELECT-only** et se voit **REVOKE** toute écriture ; le rôle writer `aidos` reçoit `SELECT, INSERT` (jamais `UPDATE`/`DELETE` — le journal est append-only).
- **`back/hooks/commit-gate/main.go`** — le **commit-gate** non contournable : `Decide(req)` refuse `DRAFT → APPLIED` si la complétude ne tient pas (`INCOMPLETE_CHANGESET`), et refuse tout `UPDATE`/`DELETE` d'un `APPLIED`/`REVERTED` (`APPLIED_IS_IMMUTABLE`). C'est la double défense du mur au niveau hook.
- **`back/mcp/changeset/main.go`** — le serveur **MCP** (Go MCP SDK, une tool = une op) : `changeset_open`, `changeset_apply` (seul chemin qui estampille `APPLIED`, derrière la gate), `changeset_revert` (ajoute l'inverse), `changeset_discard`, `changeset_status`, `changeset_list`. Le serveur porte le write-grant `aidos` ; l'agent n'écrit jamais la vérité directement.

## Méta

Le comportement de S20 est prouvé par **deux miroirs** (chacun de la bonne nature), tous rouges avant le code (le rouge **est** le `/goal`).

  <Step title="Fixture de cycle de vie (le miroir canonique, N2, authority: above)">
    `back/archive/changeset/changeset_fixture_test.go`, source matérialisée `tests/archive/changeset_lifecycle.fixture.md` — `reflects=changesets.changeset "add-order-discount"`, `test_kind=fixture`, `authority=above`. ## La route Workbench

`front/web/app/changeset/page.tsx` → **`/changeset`** : Server Component (intro + tutoriel + exemple) rendant `components/ChangeSetPanel.tsx` qui joue les fonctions **pures** de `lib/changeset.ts` par ligne — aucune I/O, aucune horloge, aucun rng. Il rend la **carte d'enveloppe** « add order discount » (le `spec_delta` et le `mirror_delta` **côte à côte** — visible : ils ne peuvent dériver), un **badge d'état**, l'`applied_at`, la **table de cycle de vie** (open → apply → apply-incomplet **ROUGE** `INCOMPLETE_CHANGESET` → edit-après-apply **ROUGE** `APPLIED_IS_IMMUTABLE` → revert → apply-inverse → discard) et la **lignée de revert** (`cs-A` estampillé `REVERTED` mais **toujours présent**, lié à l'inverse `cs-B` par `reverts`). **Lecture seule** (le mur) : un vrai apply/revert passe par le MCP changeset / le commit-gate (propose → ChangeSet → approbation), jamais une écriture directe depuis l'écran. Thémée (ADR 0010), bilingue (ADR 0011), lien de nav ajouté. E2e `tests/e2e/changeset.spec.ts` (5 tests, tous verts) : l'enveloppe montre `spec_delta` + `mirror_delta` ensemble ; l'apply complet est `APPLIED` avec `applied_at` ; l'apply incomplet est `INCOMPLETE_CHANGESET` ; l'edit-après-apply est `APPLIED_IS_IMMUTABLE` ; la lignée montre `cs-A` `REVERTED` (présent) lié à `cs-B`.

## Méta-méta

Pourquoi une **enveloppe** plutôt qu'un commit git, et pourquoi un revert qui **ajoute** plutôt qu'un `UPDATE` qui efface ? Parce que deux propriétés du noyau l'exigent. D'abord, la **non-dérive** : lier `spec_delta` et `mirror_delta` dans un seul corps adressé par contenu rend **structurellement impossible** de figer une vérité sans sa preuve — la loi de complétude (KRD §33) devient une garde au commit, pas une politesse. Ensuite, la **non-destruction** : un `APPLIED` immuable + un revert append-only signifie que l'historique ne se réécrit jamais — *un revert crée de l'information* (KRD §44.1). On peut toujours répondre « qu'est-ce qui a été appliqué, puis défait, et pourquoi ». C'est la garde anti-Goodhart au niveau temporel : on ne peut pas se rendre « propre » en effaçant le passé. Et l'absence de `FAILED` est délibérée : un état d'échec persistant serait un déchet ambigu ; un `DRAFT` qui rate est **supprimé** (discard) — il n'a jamais été vérité. La récursion est jolie : S20 **implémente l'enveloppe même** par laquelle toutes les étapes suivantes muteront le noyau ; son propre contrat est celui que tout le reste traverse.

## La touche de contrat antérieur (ADR 0019)

S20 **n'édite aucun** fichier source antérieur. Il **réutilise** le content-hash de S01/S02 sans le forker (l'id du ChangeSet **est** une clé du content-store), et **ajoute** la table d'estampille `changesets.changeset_lifecycle` sans `ALTER` de la table S02 `changesets.changeset`. Les choix genuins — un ChangeSet porte les **deux** plans dans **un** corps canonique ; l'inverse est la **négation** des deltas (pas un re-diff) ; le prédicat de complétude est **injecté** (minimal : spec ⇒ miroir) — sont enregistrés dans l'**ADR 0019**, avec les OpenQuestions épinglées (la profondeur réelle du prédicat de complétude quand il lira kernel/mirrors ; le câblage dans le flux `/goal`).

## La place dans le noyau

S20 est une couche **Archive** (l'axe temporel — l'enveloppe qui déplace d'une phase stable à la suivante). Elle **réutilise** le content-store S01/S02, **consomme** un prédicat de complétude injecté (que S06/S12 raffineront), et **prépare** le `dag` (qui généralise l'arête ChangeSet en nœuds de phase stable, branches et merges), la vague rouge `PostKernelChange` (la propagation sur les projections), le `SemanticDiff` (S21, la classification add/refine/override/…) et le câblage dans le flux `/goal`. Le mur reste intact : `changesets.changeset_lifecycle` est SELECT-only pour l'agent ; toute écriture passe par le MCP changeset / le commit-gate (propose → ChangeSet → approbation).
