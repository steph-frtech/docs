## Implémentation

EL16 livre l'**émetteur déterministe** `EmitIdeas(graph) → []Idea` (`back/runtime/besoin/emit_ideas.go`) + son outil MCP `besoin_emit_ideas` (dans `back/mcp/besoin-intake/`). C'est la **projection batch** d'un BesoinGraph en file de travail d'Ideas candidates. Là où EL15 capture **par rung à la descente**, EL16 projette **le graphe entier d'un coup**. Le mapping est **gouverné par la table close `LevelToProposes` (EL05)** — une fonction pure, jamais un LLM.

### La règle (jamais un cast silencieux)

Pour chaque `LevelNode` :

- **RESOLVED ∧ MAPPING** (`LevelToProposes(level).Kind == emit`) → **exactement une** Idea draft :
  - `Proposes`   = `LevelToProposes(level).Proposes` (la table close) ;
  - `Intent`     = l'**utterance verbatim** du nœud (`Provenance.Detail`) ;
  - `Provenance` = `{Source: human, Detail: utterance verbatim}` ;
  - `Status`     = `draft` (le seul premier état légal).
- **NoEmit** (journey / view / invariant) → **rien** (la contrainte vit dans `anchors_above[]`).
- **Non-resolved** (empty / drafting) → **rien** (seul un rung right-sizé, EL07, projette).

### Les trois portes

| Fonction | Critère « resolved » | Usage |
|---|---|---|
| `EmitIdeas(graph)` | le `node.Status == NodeResolved` stocké | la fonction pure documentée, le miroir Godog |
| `EmitIdeasResolved(graph, metaOf)` | le verdict EL07 `CanDescend(graph, level, meta).Enough` | le côté EL07-gouverné |
| `EmitIdeasUnion(graph, metaOf)` | l'**union** des deux (statut stocké OU verdict EL07) | l'outil MCP `besoin_emit_ideas` |

Les trois réutilisent `projectNode`, donc une Idea émise est **byte-identique** quelle que soit la porte — même adresse de contenu, même que la capture per-rung d'EL15.

### Content-adressage + idempotence

`projectNode` réutilise `ideas.Capture(proposes, utterance, Provenance{human, utterance})` : l'id est `records.Hash(Canonicalize(sketch))` — le **même** schéma S01/S02. `EmitIdeas` sur le **même** graphe redonne les **mêmes ids dans le même ordre** (l'ordre canonique de descente). La persistance MCP est `ON CONFLICT DO NOTHING` : ré-émettre est un **NO-OP**, jamais un doublon. `EmitIdeas` est une **fonction pure** : pas de handle DB, pas de droit noyau, pas d'horloge/rng — elle retourne `[]Idea`, elle n'écrit rien.

### L'outil MCP `besoin_emit_ideas`

`{project, dry_run?, meta}` → charge le graphe persisté, calcule `EmitIdeasUnion(g, metaOf(meta))`, puis **dry_run** prévisualise (ne persiste pas) sinon **persiste** chaque draft via `ideaStore.Insert` (la porte `idea_capture`, le reuse `ideas` schema). **Aucune** écriture `kernel`/`mirrors`/`fitness` — il n'y a aucun GRANT.

## Méta

> *Pourquoi cette forme, et pas une autre.*

- **Pourquoi un émetteur déterministe et pas un agent ?** (determinism-first, CLAUDE.md §6/§8) Le mapping niveau → kind est exactement le genre de décision qu'une **table pure** tranche : un cast LLM serait un *determinism gap*. La table `LevelToProposes` est l'autorité ; aucun LLM n'entre. Le miroir de reproductibilité (`emit_ideas_property_test.go`, rapid) épingle « même graphe → même `[]Idea` ».
- **Pourquoi `HasMirror` toujours false ?** (le mur, §2) Une Idea est un **candidat**, pas une vérité. Le type `ideas.Idea` ne peut encoder **ni version ni miroir** (la double absence). EL16 ne fait que **proposer** ; la promotion = écrire le miroir = `/goal`. L'émetteur ne franchit jamais le mur.
- **Pourquoi NoEmit n'émet rien (et pas un cast vers product) ?** Il n'existe **aucun** kind « journey »/« view » dans `ideas.ProposesKinds()`. Émettre un journey comme un product serait un **mensonge d'altitude**. NoEmit est honnête : la contrainte du rung vit dans les ancres des rungs SOURCE qu'il contraint, jamais dans une fausse idée.
- **Pourquoi trois portes ?** Le miroir Godog prouve la sémantique sur des nœuds explicitement `resolved` (la lecture honnête « nœud résolu »). Mais EL15 persiste les nœuds en `drafting` (le right-sizing est un **verdict recalculé** EL07, pas un drapeau stocké). L'union réconcilie les deux : le MCP émet ce qui est right-sizé **par le verdict** OU **par le statut**, jamais un LLM.

## Méta-méta

> *La garantie de niveau 3 qu'EL16 ajoute, et ce qu'elle ne touche jamais.*

EL16 est un **cliquet additif** (CLAUDE.md §5 : un nouvel artefact AJOUTE une garde, n'en RETIRE jamais). Il ajoute la porte de **projection** du besoin vers la file de travail — la dernière marche de la *montée du besoin* avant le hand-off vers l'app-builder (S64). Il **ne touche pas** au contrat des neuf phases ; il **n'altère** ni la grammaire (EL02), ni la table (EL05), ni la gate (EL07) — il les **lit**.

La garantie qu'il scelle : **rien ne devient code en passant**. Le seul chemin du besoin vers le noyau reste `EmitIdeas` → `idea-intake` (provenance humaine) → S64 (`/grill`) → S66 (`/goal`). La promotion est **toujours** écrire le miroir via `/goal`, jamais une écriture noyau directe — et le miroir Godog + la property + le Testcontainers (kernel refusé via GRANT) prouvent que `HasMirror` reste false et que l'écriture noyau est toujours refusée.

### Le miroir (la preuve)

- **Godog** (`emit_ideas_bdd_test.go` → `back/tests/runtime/emit-ideas.feature`) : 2 rungs mappants → 2 drafts (provenance humaine) ; product+journey → 1 Idea (journey NoEmit, pas de cast) ; ré-émission byte-identique (idempotence) ; un rung `unverifiable` atteint `spiking` uniquement après avoir existé en `draft` (draft → grill → spike, jamais un cast direct) ; aucune Idea ne porte de miroir.
- **Property rapid** (`emit_ideas_property_test.go`) : déterminisme, gouvernance EL05, NoEmit-safe, count-exact, no mirror/version.
- **Testcontainers** (`main_test.go::TestBesoinIntake_EmitIdeasEL16`) : dry_run prévisualise sans persister ; l'émission persiste via `idea_capture` ; ré-émission idempotente (même id, aucun doublon) ; l'écriture noyau est toujours refusée (GRANT).
- **Jumeau TS** (`front/web/lib/emit-ideas.ts` + `.test.ts`, vitest + fast-check) byte-équivalent ; **e2e Playwright** (`tests/e2e/emit-ideas.spec.ts`) prouve que chaque contrôle s'exécute depuis l'écran.

### Dépendances avant (OpenQuestions, non bloquantes)

- **Hand-off S64** (app-builder) : la file de travail émis est l'entrée de S64 ; l'ordre topologique de la file de travail est déjà calculé ici (l'ordre de descente). S64 ouvrira les goals dans cet ordre.
- **Linear** : l'issue de suivi EL16 est best-effort (le MCP Linear demande une ré-authentification OAuth) — notée OpenQuestion, ne bloque pas l'étape.
