## Implémentation

**Le twin de fédération `lib/v2/cellules.ts`** — la source unique de la LOGIQUE, PUR (aucun React/DOM, aucun LLM, aucune horloge, aucun aléa) :

- Types : `CellKernel` (un `KernelNode` de WB2-04 **augmenté** de `cellId` — la donnée d'entrée que la fédération partitionne) ; `Cell` (`id`, `kernelIds` ordonnés, `count`, `grid`) ; `CellContract` (`fromCell`, `toCell`, `from`, `to` — un contrat inter-cellules `depends_on`/Pact, les deux cellules + la cible pinnée) ; `Federation` (`cells` ordonnées, `contracts`, `total`).
- `buildFederation(kernels)` : le **cœur**. Valide (`empty_kernel_id`, `empty_cell_id`), **groupe par `cellId`** (chaque kernel dans **exactement une** cellule — la partition), puis pour chaque cellule **roule sa grille** via `buildGrid` de WB2-05 (`lib/v2/grid`) — le **rollup Σ réutilise le twin existant, aucun fork**. Trie les cellules par id, les `kernelIds` par id. `total = Σ des Cell.count`. Renvoie `{ ok, federation }` ou `{ ok:false, errors }`.
- `withContracts(federation, links)` : classe les liens. Seul un `depends_on` **pinné** (`isPinned` des deux bouts) **partant d'une cellule vers une AUTRE** (`fromCell ≠ toCell`) devient un `CellContract` ; un `composes` interne (même cellule) n'est jamais un contrat ; une extrémité hors cellule connue est ignorée (jamais un contrat fantôme). Contrats triés (fromCell, toCell, from, to). Immuable (renvoie une nouvelle fédération).
- `internalComposes(cellId, cellKernelIds, links)` : les `composes` dont **les deux bouts** sont dans la cellule (la verticale §23 dedans), triés stable.
- `cellContracts(federation, cellId)` : les contrats qui **partent de** ou **arrivent vers** la cellule.
- `findCell(federation, cellId)` : résout une cellule (total — `null` si absente).
- `syntheticFederation()` : la **fédération canonique** déterministe — **3 cellules** (`checkout`, `order`, `inventory`, 10 kernels), 7 `composes` internes, **2 contrats** `depends_on` inter-cellules (checkout→order, order→inventory), chaque cible pinnée `@v1`. OpenQuestion documentée : synthétique tant que le store ne sert pas les cellules live — ne bloque pas (forward-dependency).

**L'écran `app/v2/cellules/CellulesClient.tsx`** (`"use client"`) : `useMemo` appelle `syntheticFederation()` → `buildFederation` → `withContracts` — **la fédération, les rollups et le classement interne/contrat sont computés par le twin pur, jamais à l'écran**. État local `selectedCellId` + `selectedCase`. Le résumé (`v2-cellules-summary`, `data-cell-count`, `data-contract-count`, `data-total`). Le **sélecteur de cellule** (`v2-cellules-picker`, un `<fieldset>`) : un bouton par cellule (`v2-cellules-cell-<id>`, `aria-pressed`, le compte). Au clic, le **drill-down** (`v2-cellules-drilldown`, `data-cell-id`) : la **grille niveau × facette** de la cellule (réutilise le même rendu que WB2-05, `v2-cellules-case-<level>-<facet>`, `v2-cellules-grid-total`), les **liens internes** (`v2-cellules-internal` / `v2-cellules-no-internal`), les **contrats** (`v2-cellules-contracts`, `v2-cellules-contract-<from>-<to>`, entrant ←/sortant →). Au clic d'une case, **ses specs** (`v2-cellules-case-detail`, `v2-cellules-case-list`, chaque `v2-cellules-spec-<id>` → `/v2/anatomie/<id>`). Tokens ADR 0010, jamais de hex en dur.

**La page `app/v2/cellules/page.tsx`** (Server Component) : assemble les chaînes du namespace i18n `v2Cellules` (FR + EN), rend titre / sous-titre / note-du-mur (`v2-cellules-wall-note`), puis `<CellulesClient/>`. Nouvelle route — aucune route existante touchée.

**Le slug dédié `cellules`** : comme `liens` (WB2-08), `cellules` reçoit un écran dédié. `DEDICATED_SLUGS` dans `app/v2/[slug]/page.tsx` passe à `{"liens", "cellules"}` — exclu de `generateStaticParams` ∧ un accès au catch-all sur un slug dédié → `notFound()`. La route statique `cellules/` prime sans ambiguïté. Additif, non-régressant.

**Les miroirs** :

- Reproductibilité — `lib/v2/cellules.test.ts` (Vitest + fast-check) : **déterminisme** (même entrée → même sérialisation) ; **conservation** (le critère de done — `total = Σ des Cell.count = nb de kernels`, et pour chaque cellule la grille rollup conserve son Σ : Σ lignes = Σ colonnes = count) ; **partition** (chaque kernel dans exactement une cellule, aucune duplication ; cellules ordonnées) ; **rejet** (id de kernel/cellule vide → `{ ok:false }`) ; **contrat §49** (tout contrat est inter-cellules `fromCell ≠ toCell` et pinné ; les 7 composes canoniques sont internes → 0 contrat ; seuls les 2 depends_on inter-cellules comptent) ; **cible non pinnée refusée** (un `to` nu n'est jamais un contrat, §41) ; **interne** (`internalComposes` ne rend que des composes dont les deux bouts sont dans la cellule) ; **canonique** (3 cellules, 2 contrats, drill-down cellule → cases → specs : les kernelIds de la grille = les kernelIds de la cellule). GREEN (8 tests).
- e2e — `tests/e2e/v2-cellules.spec.ts` (Playwright) : **naviguer cellule → cases → specs** (le critère de done — clic cellule → drill-down ; clic case product×F → spec `checkout-product` → `href=/v2/anatomie/checkout-product`) ; **Σ cohérente** (la grille de checkout totalise 4) ; **contrats présents** (checkout→order, order→inventory) ; **bas read-only** (aucune requête POST/PUT/PATCH/DELETE) ; **déterministe** (mêmes comptes au rechargement). GREEN (2 tests). Non-régression WB2-05/08 (`v2-grille`, `v2-liens`) GREEN (4 tests) ; vitest `lib/v2` GREEN (87 tests).

## Méta

- **Déterminisme-first.** Aucun agent ne partitionne les kernels, ne roule une grille, ni ne classe un lien en interne vs contrat : `buildFederation`, `withContracts`, `internalComposes` sont des fonctions **pures et autoritatives**, et le miroir fast-check épingle leurs invariants. Le rollup Σ par cellule n'est pas une nouvelle implémentation — c'est `buildGrid` de WB2-05 **réutilisé** sur le sous-ensemble des kernels d'une cellule. Une seule logique de somme, prouvée une fois, appliquée par cellule.
- **La partition, prouvée comme un invariant.** « Aucune spec perdue » (le critère de done) n'est pas une intention : c'est une **property** (la somme des `Cell.count` = le nombre de kernels ; chaque id apparaît dans exactement une cellule, sur tout le domaine généré). La conservation se vérifie à **deux niveaux** : la fédération (Σ cellules = total) ET chaque grille de cellule (Σ lignes = Σ colonnes = count).
- **Dedans vs dehors, prouvé.** Le classement interne/contrat est une property : un `composes` intra-cellule n'est **jamais** un contrat, un `depends_on` inter-cellules en est **toujours** un, une cible non pinnée est **toujours** refusée (§41). La frontière du bounded context est un fait calculé, pas une convention d'écran.
- **Le bas read-only, prouvé.** L'e2e surveille le réseau : descendre dans une cellule, lire sa grille, ouvrir une case, inspecter un contrat — **aucune écriture ne part**. Le mur (§2) est un invariant vérifié.

## Méta-méta

- **La grandeur est un nombre de cellules, pas une taille.** WB2-09 matérialise la thèse §43–§51 : une grosse app ne grossit pas un Kernel, elle **fédère** des cellules petites. Le twin l'impose structurellement — la fédération **partitionne** ; il n'existe pas de kernel « hors cellule » ni de kernel dans deux cellules. La frontière est totale et exclusive, comme un bounded context DDD.
- **Le contrat est la seule porte.** Deux cellules ne se parlent **que** par un `depends_on` pinné (un contrat Pact). C'est ce qui rend chaque cellule **shippable localement** (le fractal §43) : elle dépend de l'**interface publique** d'une voisine (sa version contractée), jamais de ses internals. WB2-09 ne vérifie pas encore le contrat (c'est Pact, S101–S102) — il pose son **substrat** : distinguer un lien interne d'un contrat, et montrer les contrats comme les seules arêtes inter-cellules.
- **Une lecture de plus sur les mêmes kernels.** L'arbre (WB2-04), la grille (WB2-05) et maintenant la fédération (WB2-09) sont **trois projections** des **mêmes** kernels : la composition fractale, les deux axes niveau×facette, et le partitionnement en bounded contexts. Aucune ne duplique la vérité ; chacune la **relit** sous un angle. Le jour où le store sert les cellules live, seule change *l'origine* de la fédération (`syntheticFederation` → le store), pas *comment* elle se partitionne, se roule ou se classe.

## Place dans le cliquet KRD

WB2-09 est une **dent du cliquet de l'outil** : il **lit** la fédération de cellules (§43–§51) sans écrire aucune vérité (le bas read-only, les contrats Pact non encore vérifiés). Sa construction a cliqueté red → green — le miroir fast-check `lib/v2/cellules.ts` (conservation Σ = total, partition exacte, cible non pinnée refusée §41) rouge d'abord, puis vert, plus l'e2e drill-down. Il **réutilise** la phase stable de WB2-05 (`buildGrid`, qu'il roule par cellule) et **laisse** une phase stable où la fédération est lisible avant que Pact (S101–S102) ne vérifie les contrats. La dent s'ajoute aux projections existantes (arbre, grille) sans en casser une seule — anti-overwrite §9.
