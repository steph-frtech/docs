S21 livre le **classifieur SemanticDiff** (KRD §44.1) : la fonction **pure** du Runtime qui lit la **nature** d'un changement entre **deux versions de noyau** (`old@hash → new@hash`) — `add · refine · override · rescope · reweight · deprecate` — au lieu d'un diff textuel, et la commande `aidos diff` qui la rend en **lecture seule**. La **règle** — « un scope qui bouge est un rescope, pas un override ; un `enabled_when` incompatible est un override ; cosmetic→load-bearing est un reweight » — est celle de l'humain (KRD §44.1/§11/§12/§96/§44.2). Aucune vérité écrite par l'agent (le mur) ; `aidos diff` n'écrit rien.

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/runtime/semanticdiff/semanticdiff.go`** — le cœur **pur** (aucune I/O, aucune horloge, aucun rng, **aucune écriture**). Le **`ChangeType`** est un ensemble **fermé** : les six natures que S21 pose (`ChangeAdd`, `ChangeRefine`, `ChangeOverride`, `ChangeRescope`, `ChangeReweight`, `ChangeDeprecate`) — `LandedTypes()` les rend en ordre canonique pour qu'aucun aval ne les invente — plus deux verdicts spéciaux **hors §44.1** : `ChangeUnclassifiable` (« aucune nature ne colle » → une OpenQuestion, jamais une nature fabriquée) et `ChangeNone` (identité). Les deux membres §44.1 hors périmètre (`reauthorize`, `replace_mirror`) sont **délibérément absents**. L'**`Artifact`** est une version de noyau : son `Version` (le content hash, S02) + son `Body` (le JSONB canonique) ; un `Body` vide est l'« absent » (le terrain libre du cas `add`). La fonction **`Classify(old, new Artifact) → SemanticDiff`** est **totale, déterministe, ne panique jamais** ; elle dispatche par **précédence** : 1 identité → `none` ; 2 old absent → `add` ; 3 mouvement de lifecycle → `deprecate` ; 4 scope seul → `rescope` ; 5 poids seul → `reweight` ; 6 `enabled_when` changé → `override` ; 7 resserrement cohérent → `refine` ; 8 sinon → `unclassifiable` (+ OpenQuestion). Le `SemanticDiff` porte le `change_type` **calculé** ; `blast_radius`/`requires_authority`/`red_wave` sont laissés vides (référencés, non recalculés).
- **`back/runtime/semanticdiff/classify.go`** — les **prédicats par nature**, purs sur les deux corps décodés. `isDeprecation` : le `status`/`lifecycle` passe d'une valeur vivante (`active`/absente) à une morte (`deprecated`/`shadowed`/`removed`), corps **par ailleurs inchangé**. `isScopeOnlyChange` : le `scope` (S15) a changé et le **reste du corps est égal** — *le critère de done : un scope qui bouge est un rescope*. `isWeightOnlyChange` : le `weight` composes (§96) a changé, le reste égal — *cosmetic→load-bearing est un reweight*. `isEnabledWhenOverride` : sur un control, l'`enabled_when` a changé (non égal canoniquement, donc **non impliqué** par l'ancien dans le sous-ensemble décidable conservateur) — *un enabled_when incompatible est un override*. `isRefinement` : `new` est un **sur-ensemble strict** des champs de `old` (au moins un champ ajouté), chaque champ existant **inchangé** (pas de contradiction). L'égalité de corps **réutilise** `records.Canonicalize` de S02 (l'ordre des clés est neutralisé) — elle ne **forke** pas le schéma de hash.
- **`back/cmd/aidos/diff.go`** — la commande `aidos diff <id> --from <v> --to <v>`, surface **en lecture seule** (KRD §82.1 : `aidos diff` produit le SemanticDiff). Elle lit deux versions de noyau et imprime le diff en **langage humain** (le `change_type`, la phrase en clair, les `blast_radius`/`requires_authority`/`red_wave` référencés). Aucune écriture (le mur). La **source de lecture des versions** est un catalogue déterministe des trois paires canoniques (les mêmes artefacts que la fixture) ; brancher la requête store SELECT-only `<id>@<version>` réelle est une dent ultérieure (**OQ-S21-1**) qui ne change pas cette surface. La classification est `semanticdiff.Classify`, le **même** classifieur que la route `/semantic-diff` exécute, donc CLI et écran s'accordent.

## Méta

Le comportement de S21 est prouvé par **deux miroirs** (chacun de la bonne nature), tous rouges avant le code (le rouge **est** le `/goal`). Le diff est un **algorithme déterministe**, jamais un « agent de diff LLM » (CLAUDE.md §6 determinism-first).

## Méta-méta

Pourquoi un **classifieur** plutôt qu'un diff textuel, et pourquoi la **précédence** des natures importe-t-elle ? Parce que la **signification** d'un changement, pas son texte, décide de l'autorité et de la propagation (KRD §44.1). Un diff textuel est aveugle : il ne distingue pas un `enabled_when` qui se **relâche** (une promesse révoquée, dangereuse) d'un scope qui s'**élargit** (une portée, pas la règle). La précédence encode une hiérarchie d'honnêteté : on teste d'abord les natures **sûres et nommables** (identité, terrain libre, lifecycle, scope, poids), puis l'**override** (le cas dangereux), puis le **refine** (le resserrement cohérent), et **seulement à la fin** on rend `unclassifiable` — jamais une nature **fabriquée** pour faire « propre ». C'est la garde anti-Goodhart au niveau du diff : le classifieur préfère dire « je ne sais pas, voici une OpenQuestion » que deviner. L'**implication** d'expressions est en général indécidable ; le choix délibéré est le **sous-ensemble décidable conservateur** — `new` est impliqué par `old` **ssi** ils sont canoniquement égaux — donc tout `enabled_when` qui change est « non impliqué », un override. Aucun prouveur de théorèmes fabriqué : l'honnêteté du sous-ensemble décidable plutôt que l'illusion d'une décision générale. Et le classifieur est **pur et déterministe** par construction : un diff est un **algorithme**, jamais un agent — rejouable, vérifiable, le même hier et demain.

## La place dans le noyau

S21 est une couche **Runtime** (le harnais qui lit la nature d'un changement avant qu'il ne touche le noyau). Elle **réutilise** la canonicalisation/hash de S02 sans la forker, **lit** les formes de contrat antérieures (S02 records, S08 `enabled_when`/Expr, S11 control, S15 `TruthScope`, §96 poids composes, S—lifecycle status) sans les éditer, et **référence** (jamais ne recalcule) `blast_radius`/`requires_authority`/`red_wave` depuis S15/S16/S17. Elle **n'ajoute aucune** table de vérité (`Classify` lit des lignes existantes), **aucun** hook (le mur S04 + la gate ChangeSet S20 existent déjà), **aucun** MCP (`aidos diff` est la surface). Elle **prépare** : `reauthorize` (via l'AuthorityGraph S16), `replace_mirror` (via le plan Mirror S06), et le câblage du `SemanticDiff` dans la gate `DRAFT→APPLIED` du ChangeSet pour que `requires_authority` soit **enforcé**. Le mur reste intact : `aidos diff` est en lecture seule ; appliquer un changement passe par un ChangeSet (propose → approbation).
