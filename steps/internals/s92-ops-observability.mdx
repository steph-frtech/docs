## Implémentation

S92 ajoute l'**observabilité d'exploitation par app** : `back/runtime/opsobservability`. Elle rend les logs/traces/erreurs de l'app émise dans un panneau d'ops PAR APP (latence, taux d'erreur, logs), **distincte** de la télémétrie-senseur du noyau (E12 / le RealityMirror, `back/runtime/reality`). DP17, ADR 0043 ; substrat OTel → SigNoz/GlitchTip.

**Le signal OTel.** `Signal` est un signal d'observabilité façon OpenTelemetry : un `ProjectID` (le scope app), un `Kind` dans l'ensemble **fermé** `{log, span, error}` (les trois signaux cœur d'OTel), une `Route`, une `DurationMs` (load-bearing pour `span`), une `Severity` (load-bearing pour `log`/`error`), un `Body`, un drapeau `IsError` (un span dont la requête a échoué), et un `AtUnixNano` (le temps d'événement, **fourni par l'appelant** — jamais une horloge arg-less, déterminisme). C'est du **matériel opérationnel**, jamais une vérité.

**La frontière d'ingestion.** `Ingest(s)` **valide** un signal, fail-closed : un `ProjectID` vide → `ErrEmptyProject` ; un `Kind` hors de l'ensemble fermé → `ErrUnknownKind` (un `metric` n'est pas accepté — l'ensemble est déclaré, jamais deviné). Une sévérité vide sur un log/error normalise à `info` (un défaut rendable), jamais une sévérité plus haute devinée. Pure : même signal → même verdict d'accept/reject.

**L'agrégation (le critère Godog).** `BuildDashboard(projectID, signals)` agrège les signaux du projet en son `Dashboard`, **déterministiquement**, et **prouve qu'elle n'écrit aucune vérité** (`Report.WroteKernel == false`). Elle **ignore tout signal non scopé à `projectID`** (l'isolation par app : le signal d'une app A n'entre jamais dans le panneau d'une app B). Elle produit : `TotalRequests` / `TotalErrors` / `ErrorRate` (sur tous les spans), la latence `p50/p95/p99` globale, le détail **par route** (trié par nom de route), le **fil de logs** et le **fil d'erreurs** (les logs error/fatal + les signaux error — la surface error-tracking de DP17), et une `Fingerprint`.

**La latence : nearest-rank.** `percentile(durations, p)` est le percentile **nearest-rank** : il trie une **copie** (jamais le slice de l'appelant), indexe par `ceil(p/100 · n)` clampé à `[1,n]`, et renvoie `0` sur l'ensemble vide. Nearest-rank est le percentile canonique, sans dérive flottante, de la vue de latence — un percentile est **toujours** une durée observée (pas une interpolation inventée).

**Le taux d'erreur.** `rate(errs, total)` est `errs/total` dans `[0,1]`, arrondi à 4 décimales pour un rendu byte-stable (pas de dérive flottante dans le miroir de reproductibilité) ; `0` quand `total == 0`.

**La redaction (la loi S91 réappliquée).** `redactLog(body)` masque tout segment façon-secret d'un corps de log avec `[REDACTED]` — le **même** geste gitleaks-style déterministe qu'au S91 (`logLeakRules` : clés AWS, en-têtes de clé privée, bearer tokens, URI Postgres avec mot de passe, affectation à une variable au nom-de-secret). Un panneau qui afficherait un secret loggué par mégarde serait lui-même une fuite ; la redaction l'empêche, avant que le corps n'atteigne le fil.

**L'empreinte.** `fingerprint(d)` content-adresse le dashboard entier (via `records.Hash`) sur son rendu canonique (stats par route + fil), **sans** le champ `Fingerprint` lui-même — même signaux → même empreinte. Le `Report{Dashboard, WroteKernel: false}` porte la **preuve du mur** explicite et testable.

**Le MCP `aidos-ops-observability`** (`back/mcp/ops-observability`, ADR 0009) expose `ops_ingest` · `ops_dashboard` · `ops_fingerprint`. Chaque outil est une fonction **pure** de son entrée (pas de DB, pas d'horloge, pas de RNG), et **chaque outil porte `WroteKernel: false`** — l'observabilité est une couche de rendu, jamais un on-ramp noyau. **Le twin TS** `front/web/lib/ops-observability.ts` reflète les jugements purs (validation, percentiles, taux, redaction, isolation) et alimente la route **action-capable** `/ops-observability` (ÉMETTRE un signal + CONSTRUIRE le dashboard — exécutables depuis l'écran ; un jeu de démo en un clic). Le panneau affiche explicitement `wroteKernel: false`.

**Les miroirs.** rapid (`opsobservability_property_test.go`) : **writes-no-truth** (`WroteKernel` toujours false sur des signaux arbitraires), **reproductibilité** (mêmes signaux → même empreinte), **isolation** (les signaux d'un autre projet ne changent pas le panneau de P), **percentile sound ∧ monotone** (un percentile est une durée observée, et p50 ≤ p95 ≤ p99), **redaction** (un secret connu ne survit jamais au rendu), **taux d'erreur ∈ [0,1]**. Fixtures (`opsobservability_fixture_test.go`) : l'app émet des spans → le dashboard rend latence + taux d'erreur ; l'app émet des logs → le dashboard rend le fil de logs + le fil d'erreurs ; un secret loggué est redacté ; A ne fuit jamais vers B ; un `Kind` inconnu est refusé. fast-check (`ops-observability.test.ts`, 11/11) côté twin ; Playwright (`ops-observability.spec.ts`, 4/4) côté écran.

## Méta

S92 trace la même ligne que S91, mais sur un autre axe : entre **rendre** et **apprendre**. AIDOS a deux usages de la télémétrie qu'il ne faut **jamais** confondre. Le **senseur du noyau** (E12, `RealityMirror`) est l'**unique** on-ramp de la réalité vers la vérité : un incident qui *contredit* le noyau devient une *idée*, qui devra acquérir son miroir et passer un `/goal` (Incident → Learn → Idea → [humain] Mirror → Goal → Kernel). L'**observabilité d'exploitation** (S92) est l'**inverse** : un panneau que l'utilisateur lit pour opérer son app. Voir une latence n'est **pas** une décision de vérité. S92 vit **sous le mur** (CLAUDE.md §2) — comme une projection — et son `Report.WroteKernel == false` est la matérialisation testable de cette frontière.

Le scope `project_id` est le même principe d'isolation qu'au S91, mais ici il n'a pas besoin d'être cryptographique : un panneau d'ops n'est pas un secret, et l'isolation est une simple partition à l'agrégation (un signal non-scopé est ignoré). Le geste de **redaction** est, lui, importé verbatim du S91 : la loi « un écran ne montre jamais un secret en clair » est transversale, pas propre au coffre.

## Méta-méta

S92 est du **déterminisme-first** appliqué à l'observabilité (CLAUDE.md §6/§8) : tout jugement *peut* être une fonction pure, donc l'**est**. Les percentiles sont une **mesure** (tri + nearest-rank), pas un avis ; le taux d'erreur est un **tally** ; la redaction est du **pattern-matching** ; la validation de signal est un **test d'appartenance** à un ensemble fermé. Aucun LLM n'entre — un agent qui « analyserait les logs » à la place d'une agrégation pure serait un **trou de déterminisme** qui bloquerait l'étape. Le seul temps qui entre est `AtUnixNano`, **fourni par l'appelant**, jamais une horloge arg-less : c'est ce qui rend le panneau byte-stable et autorise le miroir de reproductibilité (mêmes signaux → même empreinte).

Et S92 est **fail-closed** sur l'ingestion (un `Kind` inconnu / un projet vide est refusé, jamais deviné) et **isolant par construction** (un signal d'un autre projet est ignoré, pas mélangé). Surtout, il est **mur-clos** : `WroteKernel` est *toujours* false, sur tous les chemins, prouvé par property — l'étape ne peut pas, même par accident, transformer un panneau d'exploitation en porte vers le noyau. La seule porte de la réalité vers la vérité reste le RealityMirror de E12.
