## En une phrase

S52 ajoute `back/kernel/agentlayer` (la **couche**, au-dessus de la ligne) et `back/runtime/agentrun` (l'**exécution**, sous la ligne) — deux packages Go **purs** qui modélisent un agent comme une vérité gouvernée : `Validate` force les deux droits toujours-false, `MayWrite` réutilise le prédicat de ligne de flottaison S04 et refuse toute écriture au-dessus de la ligne avec `AGENT_WRITE_ABOVE_WATERLINE`, `Propose` rend toujours `proposed` (jamais `admitted`), et un `AgentRun` ne porte ni version ni miroir (un run n'est pas une couche).

## Implémentation

    `Validate(CoucheAgent)` : `Kind` dans le triplet fermé ; `peut_modifier_noyau == false` ET `peut_modifier_fitness == false` **toujours** ; aucune `ZonesEcriture` ne résout au-dessus de la ligne (via `aboveWaterline`, le prédicat S04) ; `Autorite`/`Scope` bien formés (S16/S15). `MayWrite(spec, target)` refuse tout target au-dessus de la ligne avec le `BlockReason` S13 `AGENT_WRITE_ABOVE_WATERLINE`, **quel que soit le rôle**. `Propose(c, scenario)` rend toujours `status == "proposed"` + les approbateurs humains S16, et **n'écrit rien**. `Approve(c, p, approver)` refuse l'auto-approbation (rôle/nom de l'agent) et n'admet que sur un approbateur **humain** nommé dans le graphe.

## Méta — pourquoi c'est construit ainsi

- **Réutilisation, pas de fork.** Le mur S04 (`Classify`) est le prédicat de ligne de flottaison ; comme il vit dans `package main` (le binaire hook) et n'est pas importable, `agentlayer.aboveWaterline` **reproduit son prédicat verbatim** (mêmes schémas, mêmes préfixes) — c'est une OpenQuestion (OQ-S52-wall : extraire le prédicat S04 dans un package importable). Le `BlockReason` `CodeAgentWriteAboveWaterline` (S13) est **réutilisé**, aucun code inventé. `AuthorityGraph` (S16) et `TruthScope` (S15) sont importés tels quels.
- **Déterminisme-first.** Tout est une fonction pure et autoritaire : `Validate`, `MayWrite`, `Propose`, `Approve`, `Record`, `ApplyWall`. Aucun chemin LLM ici — décider des droits d'un agent ou de l'admission d'une proposition est une **décision déterministe**, jamais déléguée à un agent. Un agent qui déciderait seul de ses droits, ou s'auto-approuverait, serait à la fois une **brèche du mur** et un **écart de déterminisme**.
- **La couche vs l'exécution.** La séparation `agentlayer` (kernel, au-dessus) / `agentrun` (runtime, en dessous) est la frontière conceptuelle du step, reflétée dans le code (deux packages, deux schémas) et dans le type (`AgentRun` sans `Version`/`Mirror`).

## Méta-méta — la garantie de niveau 3

S52 ne touche **ni la fitness ni le mur lui-même** : il les **réutilise**. Le `kernel.agent_layer` est *lui-même* gouverné par le mur qu'il décrit — la ligne `agent_layer` est SELECT-only à l'agent, exactement comme toute vérité. La garantie inviolable est que **rien dans la modélisation d'un agent n'ouvre une porte au-dessus de la ligne** : les deux droits structurels sont false, `MayWrite` refuse tout target au-dessus de la ligne pour tout rôle, et `Approve` interdit l'auto-approbation. La méta-loop **ajoute** un garde-fou (la gouvernance de l'agent), elle n'en retire aucun.

## Limites connues

- **Pas de câblage /goal de l'admission.** Une proposition devient vérité seulement via le flux S29 `/goal` appliqué par le rôle `aidos` — un câblage ultérieur (ici, `Propose`/`Approve` sont des fonctions pures non encore reliées à la porte d'admission `/goal`).
- **Pas de boucle d'orchestration runtime.** `equipe_agents` / `orchestration` sont modélisables (la taxonomie) mais la gouvernance multi-agents (qui orchestre qui) n'a pas de boucle d'exécution à ce step.
- **OQ-S52-wall.** Le prédicat de ligne de flottaison S04 devrait être extrait dans un package importable pour que `MayWrite` l'importe au lieu de le reproduire.
- **Pas de nouveau hook / MCP / Skill / codegen** — le mur S04 refuse déjà les écritures au-dessus de la ligne, la porte idea-intake S27 reçoit déjà les propositions, et une couche agent ne *génère* aucun artefact.
