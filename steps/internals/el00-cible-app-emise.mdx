## En une phrase

EL00 grave la **cible de l'app émise** comme une **vérité Go unique** — `back/runtime/agentloop.EmittedTargetEL00()` (un record `EmittedTarget`) — **pinnée ≡** le bloc `emitted_target` d'`arch-fitness.json` (la config que FN04/S84 enforce) par un **property test de parité**. Aucun package neuf, aucune écriture vérité : un ADR (`docs/adr/0040`) + une déclaration + sa preuve.

## Méta — pourquoi c'est construit ainsi

- **Une seule source, jamais double-typée (CLAUDE.md §9).** La cible vit en **une** vérité Go (`EmittedTargetEL00()`) ; `arch-fitness.json` en est la projection config ; le twin TS en est le reflet front. Le **property test de parité** garde les trois en phase — exactement le pattern FN04 (`TestArchFitnessConfig_MatchesEmittedInvariants`) que EL00 réutilise et étend, sans le forker. C'est pourquoi EL00 ne crée **aucun** package neuf : il **compose** FN04 et ADR 0006.
- **Déterminisme-first.** La cible est une **fonction pure** (sans horloge/rng/IO) et la parité est un `reflect.DeepEqual` / un `verifyParity` par champ — jamais un LLM qui « juge si l'app est assez Hono ». Le miroir de reproductibilité (rapid + fast-check) pin « même entrée → même sortie ». La pureté FN02 désormais sur TS **EST** le déterminisme d'émission (même Kernel → octets byte-identiques) appliqué à la sortie.
- **ADR-only, comme FN02.** EL00 grave une **cible**, pas un mécanisme : exactement comme FN02/ADR 0036 a gravé le **mandat** fonctionnel avant que FN03/FN04 ne l'implémentent. Les émetteurs Hono/TS réels arrivent à FN03/S87+ ; EL00 ne fait que **trancher la cible** et la prouver pinnée.
- **L'interpréteur n'est pas dupliqué.** D7 tranche l'OpenQuestion : un **callback vers un service Go**, pas une ré-émission TS. Dupliquer une logique gouvernée romprait la parité de comportement ; le trade-off accepté est un sidecar Go dans le déploiement émis — la seule dépendance Go de votre app, versionnée avec le Kernel.

## Méta-méta — la garantie de niveau 3

EL00 ne touche **ni la fitness ni le mur** : il les **réutilise**. Aucune écriture `kernel`/`mirrors`/`fitness` ; le record `EmittedTarget` est une donnée above-the-line, `WritesTruth:false` est **vérifié par le test** (pas seulement affirmé). La garantie inviolable : **graver une cible d'émission n'ouvre aucune porte d'écriture-vérité côté TS**, et la frontière ne peut dériver silencieusement — le property test de parité la fige (`arch-fitness.json` ≡ le record Go ≡ le twin TS). Élargir/assouplir la frontière est un **changement de VÉRITÉ** (idée → miroir → /goal). La méta-loop **ajoute** une garde (la parité de la cible émise), elle n'en retire aucune.

## Limites connues

- **Pas d'émetteurs Hono/TS encore.** EL00 grave la cible ; FN03/S87 émettent réellement le Hono/TS pur (handlers + workers + client). EL00 ne produit aucun arbre `gen/` Hono — il déclare et prouve la cible.
- **L'enforcement TS de FN04 est à venir.** FN04 bascule l'enforcement des trois invariants vers `dependency-cruiser` + un linter de pureté TS sur `gen/` ; aujourd'hui `ScanEmittedTree` parse encore du Go (FN04/ADR 0036). EL00 ne change pas l'enforceur, il déclare que les invariants sont neutres au langage.
- **Le sidecar interpréteur Go n'est pas déployé ici.** D7 est tranchée mais réalisée en S90/S77 (le handler Hono → service Go) ; EL00 ne câble aucun service.
- **OQ-0040-front / OQ-0040-driver.** Le framework front exact (Hono JSX/SSR vs client `hc`) est tranché en S93 ; le client Postgres TS (postgres.js / Drizzle / Kysely) par le spike S88 — OpenQuestions déclarées, non bloquantes.
- **Pas de nouveau hook / MCP / Skill / migration / codegen** — EL00 est ADR-only : il grave une cible et la prouve pinnée, rien de plus.
