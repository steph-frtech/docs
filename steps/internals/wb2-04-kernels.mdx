## Implémentation

**Le twin d'arbre `lib/v2/kernel-tree.ts`** — la source unique de la LOGIQUE, PUR (aucun React/DOM, aucun LLM, aucune horloge) :

- Types : `KernelNode` (un kernel plat de la relation `composes` : `id`, `level` (verticale §23 / band), `facet` (FKE-1.3), `label`, `parentId: string | null` — `null` = racine) ; `TreeNode` (le nœud projeté que React Arborist consomme : id + `children` + métadonnées + **`depth`** calculée, racine = 0) ; `TreeError` (`duplicate_id`, `orphan_node`, `cycle`, `level_unknown`, `facet_unknown`, `empty_id`).
- `validateComposes(nodes)` : la liste ordonnée & stable des `TreeError`. Détecte : id vide, id dupliqué, niveau/facette hors jeu clos (réutilise `isLevel` de `besoin-grammar` et `isFacetLetter` de `lib/v2/idea`), **orphelin** (un `parentId` qui ne résout vers aucun id — le critère « aucun nœud orphelin »), et **cycle** (remontée bornée par `parentId` : on doit toujours atteindre une racine sans repasser deux fois par le même id).
- `buildKernelTree(nodes)` : le cœur. Valide ; sinon `{ ok:false, errors }`. Sinon groupe les enfants par `parentId`, **ordonne chaque fratrie** par `compareSiblings` (rang de niveau dans `SOURCE_ORDER` puis id en tie-break stable), construit récursivement en calculant la `depth`, renvoie `{ ok:true, roots }`. « Aucun orphelin » est **garanti** par la validation préalable.
- `flattenTree(roots)` : parcours préfixe → la liste plate (sert au miroir : le compte est préservé). `countNodes(roots)` : le total (le compteur de virtualisation).
- `syntheticComposes(n)` : une relation `composes` synthétique déterministe de N kernels (un produit racine, des branches fractales descendant la verticale ; coordonnées dans les jeux clos) — pour peupler l'écran à 240 nœuds et prouver la virtualisation. PURE : même N → même relation.

**L'écran `app/v2/kernels/KernelTreeClient.tsx`** (`"use client"`) : `useMemo` appelle `syntheticComposes(240)` → `buildKernelTree` → adapte `TreeNode` en `ArboristNode` (`{id, name, level, facet, depth, children}`). Rend `<Tree data={roots} idAccessor childrenAccessor openByDefault={false} height={520} rowHeight={32} overscanCount={8}>` (React Arborist — **virtualisé**). Chaque ligne (`KernelRow`) : un bouton chevron (`node.toggle()` — déplier/replier, `data-open`), un bouton de sélection (`onSelect` → state local) montrant la facette + le libellé + le niveau. La sélection ouvre une barre avec un `<Link href={/v2/anatomie/${id}}>` (**clic → anatomie**). `data-testid` : `v2-kernels-tree`, `-count`, `-node-<id>`, `-toggle-<id>`, `-select-<id>`, `-selected`, `-open-anatomy`.

**L'écran partagé `app/v2/kernels/KernelsScreen.tsx`** (Server Component) : rend l'identité canonique du concept depuis le glossaire (`entry("arbres")` → `v2-concept-title` = « Arbres », `v2-concept-def`), le titre/sous-titre/note-du-mur (namespace i18n `v2Kernels`), puis `<KernelTreeClient/>`. **Deux routes** le rendent : `app/v2/kernels/page.tsx` (la route de l'étape) et `app/v2/arbres/page.tsx` (le slug du concept « Arbres », atteint depuis la carte/nav de `/v2`). Les deux sont des **segments statiques** qui priment sur `/v2/[slug]` et **conservent le contrat de navigation WB2-02** (le bloc « Arbres » → `v2-concept-title` = « Arbres »).

**Le stub `app/v2/anatomie/[kernel]/page.tsx`** : l'anatomie réelle (six paires-miroir) est l'étape WB2-06 (forward dependency, exception bootstrap §6). Ce stub **résout le clic** (jamais un lien mort), affiche l'`id` du kernel ciblé (`v2-anatomie-kernel-id`) et une note ambre. Namespace i18n `v2Anatomie`. **OpenQuestion documentée** : remplacé par l'anatomie réelle à WB2-06.

**Les miroirs** :

- Reproductibilité — `lib/v2/kernel-tree.test.ts` (Vitest + fast-check) : **aucun orphelin** (un `parentId` non résolu refusé) ; **compte préservé** (`countNodes(buildKernelTree(nodes)) === nodes.length`) ; **déterminisme** (même entrée → même sérialisation préfixe) ; **profondeur** (racine = 0, enfant = parent + 1) ; **fratries ordonnées** (rang de niveau puis id) ; id dupliqué / cycle / coordonnée hors jeu clos / id vide refusés ; **200+ nœuds** (`syntheticComposes(240)` se compose sans orphelin). GREEN (11 tests).
- e2e — `tests/e2e/v2-kernels.spec.ts` (Playwright) : 200+ nœuds **virtualisés** (le compteur affiche 240, mais le DOM ne matérialise qu'une fenêtre < 240 lignes) ; **déplier/replier** la racine (`data-open` bascule, l'enfant apparaît/disparaît) ; **clic → anatomie** (`/v2/anatomie/k0`, l'id affiché) ; **garde anti-écriture** (aucune requête POST/PUT/PATCH/DELETE) ; coexistence (`/v2/kernels` 200, `/v2/arbres` rend l'arbre avec `v2-concept-title` = « Arbres », `/` 200). GREEN (2 tests).

## Méta

- **Déterminisme-first.** Projeter l'arbre est une **fonction pure** (`buildKernelTree`), jamais un agent : grouper/ordonner/calculer-la-profondeur/détecter-orphelins-et-cycles sont du code, autoritatif. **React Arborist n'est QUE du rendu virtualisé** ; il ne décide ni l'ordre, ni la profondeur, ni la validité. L'ordre est **déclaré** (`SOURCE_ORDER`, la verticale §23, puis l'id) — jamais appris. Le miroir fast-check épingle le déterminisme (même entrée → même arbre).
- **« Aucun nœud orphelin », prouvé par construction.** Un orphelin (un `parentId` qui ne résout pas) est **refusé** par `validateComposes` *avant* la construction ; donc `buildKernelTree` ne produit jamais un arbre orphelin — c'est un invariant de type (`{ ok:false }`), pas une vérification a posteriori. Le cycle est traité de même (l'arbre ne se compose pas plutôt que de boucler).
- **Réutiliser, ne pas réinventer.** Les niveaux et leur ordre viennent de `besoin-grammar` (`SOURCE_ORDER`, `isLevel`), les facettes de `lib/v2/idea` (qui réutilise `lib/facets`). Le step n'invente aucune coordonnée ; la lib d'arbre (React Arborist, slot gelé ADR 0053 pour l'arbre dense) est choisie pour la **virtualisation** (200+ nœuds), pas pour la logique.
- **Le mur, prouvé.** L'arbre est une projection de lecture : l'e2e **surveille le réseau** — aucune écriture ne part en naviguant/dépliant/ouvrant une anatomie. Le mur (§2) est un invariant vérifié, pas une promesse.

## Méta-méta

- **La forme suit la nature de la vérité.** La composition `composes` (§17) **est** un arbre fractal (§49) ; on la rend donc en arbre, pas en liste — le choix de représentation n'est pas esthétique, il est dicté par la structure de la vérité (qui compose qui, et à quelle profondeur). C'est le même principe que « la forme de miroir suit le niveau » (EL10) : ici, la forme d'écran suit le lien.
- **Un step qui prépare le suivant.** WB2-04 produit le `TreeNode` (la donnée) ; WB2-06 consommera la cible du clic (l'anatomie d'un kernel) ; WB2-05 réutilisera les mêmes coordonnées (niveau × facette) pour la grille. Le stub `/v2/anatomie/[kernel]` est la **couture explicite** entre les steps — une OpenQuestion documentée, pas un lien mort, conforme à l'exception bootstrap (« mocks what doesn't exist yet »).
- **Le synthétique comme banc d'essai déterministe.** `syntheticComposes(240)` n'est pas un faux : c'est un **générateur pur** qui prouve la propriété qui compte (la virtualisation tient à 200+ nœuds sans orphelin) sans dépendre d'un store de kernels encore non câblé. Le jour où le store exposera ses `composes` réels, le twin et l'écran ne changeront pas — seule la source des `KernelNode` changera. La logique est déjà prouvée, indépendamment de la donnée.
