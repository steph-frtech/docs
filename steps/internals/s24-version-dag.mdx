<Info>Côté détail. Pour le concept, voir [Pour les futurs utilisateurs → S24](/steps/concept/s24-version-dag).</Info>

S24 livre les **trois mouvements de navigation du DAG de versions** (KRD §121) : les fonctions **pures** `Branch` / `CheckoutAncestor` / `Rebranch` sur une valeur DAG **append-only** ; les tables **`dag.node`** (nœuds = phases stables) + **`dag.edge`** (arêtes = ChangeSets) ; le serveur **MCP `dag`** qui porte le rôle writer ; et la route Workbench **/version-dag**. La **règle** — « l'espace des versions est un DAG, append-only, à tête mutable ; brancher / revenir / rebrancher ; l'ancienne ligne n'est jamais détruite ; plusieurs têtes parallèles ; stratifié par la ligne de flottaison » — est celle de l'humain (KRD §120–§125). Aucune vérité écrite par l'agent (le mur) ; `dag` est au-dessus de la ligne (agent SELECT-only).

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/archive/dag/dag.go`** — le cœur **pur** (aucune I/O, aucune horloge, aucun rng, **aucune écriture**). Les types : **`Node`** (`id` = adresse de contenu, `parent_ids []string` ≥1 — un DAG, pas un arbre ; `head bool` ; `stratum above|below`, §124 ; `label`), **`Edge`** (`from`, `to`, `changeset` = un `changesets.changeset.id` existant de S20), **`DAG`** (valeur immuable de nœuds + arêtes — chaque mouvement rend un **NOUVEAU** DAG, jamais une mutation en place). Les trois mouvements : **`Branch(d, from, label, changeset)`** ajoute un nœud parenté sur `from` (héritant son stratum) + l'arête, et déplace la tête **si `from` était la tête** (sinon deux têtes parallèles, §125) ; **`CheckoutAncestor(d, ancestor)`** est un **déplacement du flag de tête** — il efface le flag des descendants de l'ancêtre et le pose sur l'ancêtre, **n'ajoute et ne supprime rien** ; **`Rebranch(d, ancestor, label, changeset)`** ajoute une nouvelle ligne parentée sur l'ancêtre **sans** effacer le flag de tête de l'ancêtre. Les lecteurs : **`Heads`** (peut en rendre plusieurs, §125), **`Ancestors`**, **`IsReachable`** (irréflexive, cycle-safe). Tout est **total** et **ne panique jamais** (une phase inconnue est une `Error` rendue, pas un crash) ; une refus ne mute **jamais** le DAG.
- **Réutilisation, pas réinvention** — **`NodeID(parentIds, stratum, label)`** réutilise `records.Canonicalize` + `records.Hash` de **S02** (jamais forké) : l'id d'un nœud est le hash de son body canonique `{kind:"phase", parent_ids, stratum, label}`, donc content-addressed et rejouable. L'**arête** réutilise `changesets.changeset.id` de **S20** : le DAG est une **relation sur des lignes existantes**, il **référence**, il ne **copie** jamais un body de phase ou de ChangeSet.
- **`back/migrations/dag_node_edge_baseline.sql`** — **expand-only / append-only**, **ADDITIVE**. **`dag.node`** (`id text PK` = hash, `body jsonb`, `version` avec CHECK `version = id`, **`head boolean`** = la SEULE colonne mutable, `stratum` avec CHECK `IN ('above','below')`, `label`, `created_at`). **`dag.edge`** (`from_node`/`to_node` **REFERENCES `dag.node(id)`**, `changeset text` = l'id S20, PK `(from_node, to_node, changeset)`, CHECK `from_node <> to_node` — pas de boucle sur soi, ça reste un DAG). La **parentage** est la relation `dag.edge` — **une seule** représentation, jamais dupliquée sur le nœud (ADR 0021 §1). **Le mur** : `dag` est au-dessus de la ligne — l'agent a **SELECT seulement**, tous ses writes révoqués ; le rôle writer `aidos` a `INSERT` + **`UPDATE (head)` seul** (un checkout/branche déplace le flag), **jamais `DELETE`** (append-only — la ligne abandonnée n'est jamais détruite). Les tables S02 `dag.phase` / S23 `dag.stable_phase` sont **intactes** (aucun ALTER, §9).
- **`back/mcp/dag/main.go`** — le serveur **MCP `dag`** (Go MCP SDK ; un outil = une op backend ; ADR 0009), **l'unique porte** portant le DSN writer `aidos`. Les outils : **`dag_branch`**, **`dag_checkout_ancestor`**, **`dag_rebranch`** (écrivent — append nœud/arête, déplacent la tête), **`dag_heads`**, **`dag_ancestors`**, **`dag_get`** (lisent). Le serveur **charge** le DAG, exécute la **fonction pure**, et persiste le **delta append-only** (nouveaux nœuds/arêtes + flags de tête) — il ne ré-implémente **jamais** la décision. Un refus pur (phase inconnue) est rendu **Blocked**, jamais un crash, et ne persiste **rien**.

## Méta

Le comportement de S24 est prouvé par **trois miroirs** (chacun de la bonne nature) plus un roundtrip de persistance et un test d'activation/fault-injection du MCP, tous rouges avant le code (le rouge **est** le `/goal`). Les mouvements sont des **algorithmes déterministes**, jamais un « agent qui décide où va la tête » (CLAUDE.md §6/§8 — determinism-first).

<Steps>
  <Step title="Fixture de navigation (le miroir canonique, N2, authority: above)">
    `back/archive/dag/dag_fixture_test.go` — `reflects=dag.node/dag.edge "version-dag-§120"`, `test_kind=fixture`. `state` = un DAG · `command` = un mouvement · `events` = `{Branched|HeadMoved|Rebranched}` + l'état résultant. Les rangées : **brancher depuis la racine** ⇒ `Branched`, nouveau nœud parenté, la tête bouge, l'origine **non supprimée** ; **brancher depuis un ancêtre interne** ⇒ **deux têtes parallèles** (§125) ; **checkout d'un ancêtre** ⇒ `HeadMoved`, `ancestor.head==true`, **chaque nœud ultérieur existe encore** (append-only) ; **rebrancher** ⇒ `Rebranched`, nouveau nœud parenté sur l'ancêtre, **accessible depuis la racine**, la ligne abandonnée **existe encore** (*LE critère done*) ; chaque `Node.id == Hash(Canonicalize(body))` (content-addressed, S02).
  </Step>
  <Step title="Propriété rapid (l'invariant ∀, N1, authority: below)">
    `back/archive/dag/dag_property_test.go` — `reflects=dag movements`, `test_kind=property`, `cert_language=rapid`. Sur **toute** séquence `branch/checkout_ancestor/rebranch` : le DAG **ne fait que croître** (nœuds + arêtes monotones non-décroissants — append-only) ; il reste un **DAG** (aucun cycle — `IsReachable` irréflexive) ; **≥1** tête, possiblement **plusieurs** (§125) ; `checkout_ancestor` est un **déplacement du flag de tête** (aucun nœud/arête ajouté ou retiré) ; `rebranch` crée un nœud dont les `parent_ids` contiennent l'ancêtre ; chaque `Node.id == Hash` du body canonique ; **jamais de panique**, **jamais de suppression**.
  </Step>
  <Step title="Roundtrip de persistance (Testcontainers, intégration)">
    `back/archive/dag/migration_roundtrip_test.go` — applique S02 + S23 + S24 contre un vrai Postgres jetable : `dag.node` existe avec le CHECK content-address (`version ≠ id` **refusé**) et le CHECK de **stratum** (`above|below`, §124) ; `dag.edge` **référence** des nœuds existants (FK — relation sur des lignes existantes, un nœud fantôme **refusé**) et refuse une **boucle sur soi** ; **expand-only** (les `dag.phase` / `dag.stable_phase` antérieurs intacts) ; **le mur** — l'agent a **SELECT-only**, ses `INSERT/UPDATE(head)` **refusés** ; le writer `aidos` peut `INSERT`er un nœud/arête et **déplacer le flag de tête**, et un nœud **référencé par une arête ne peut être supprimé** (la FK protège la lignée — append-only).
  </Step>
  <Step title="Activation + fault-injection du MCP (ADR 0009)">
    `back/mcp/dag/main_test.go` — pilote les handlers contre un vrai Postgres et prouve le **round-trip §120 de bout en bout** : branche off racine → off v1 → off l'ancêtre interne (deux têtes), checkout de l'ancêtre (déplacement du flag, v2/w1 restent), rebranche (nouvelle ligne accessible depuis la racine, la ligne abandonnée reste — *le critère done*), le DAG **ne fait que croître**. **Fault injection** : un mouvement sur une phase **inconnue** est **Blocked** et persiste **rien** (le serveur défère à la décision pure et ne corrompt jamais le store).
  </Step>
  <Step title="Jumeau front fast-check (l'invariant côté Workbench)">
    `front/web/lib/version-dag.test.ts` épingle les **mêmes** invariants côté Workbench (croissance append-only, no-cycle, checkout = déplacement de flag, rebranch parenté sur l'ancêtre, têtes parallèles), donc l'écran /version-dag anime exactement comme le Go `dag` / le MCP.
  </Step>
</Steps>

La **complétude** tient : `dag.node`/`dag.edge` + les trois mouvements ont leur miroir vivant (fixture + propriété + roundtrip + MCP) ; pas de monstre (aucun mouvement sans sa rangée de fixture, aucune forme nœud/arête sans propriété qui la couvre, **aucune** suppression qui violerait l'append-only).

## Méta-méta

Pourquoi un **DAG append-only à tête mutable** plutôt qu'une histoire linéaire qu'on réécrit ? Parce qu'une histoire qu'on écrase **perd les chemins non pris** — et avec eux la matière même de l'exploration. KRD §120 pose que l'espace des versions est un **DAG** où **revenir n'efface rien** : le mouvement « en arrière » ne **détruit** pas la ligne quittée, il déplace seulement le **flag de tête**. L'ancienne ligne reste accessible — un **stepping stone** prêt à être ré-emprunté (§123). C'est l'unification profonde du §124 : la **même** structure sert l'**undo humain** et la **mémoire évolutive** (QD) — variante = branche, stepping stone = ancêtre recheckout-é, niche = branche parallèle, élite = phase stable gardée. « Revenir à l'ancienne version » et « échantillonner un stepping stone » sont **littéralement le même geste** : checkout d'un ancêtre + rebranche. Le caractère **content-addressed** ferme la boucle anti-écrasement : un nœud **est** son hash, on ne peut pas le « modifier » — on en crée un **nouveau**, et le DAG garde les deux. Et que ces trois mouvements soient des **fonctions pures** (jamais un agent qui « décide » où va la tête) est l'application directe de « le juge est déterministe » (§8) : le même DAG + le même mouvement rendent toujours le même DAG, hier comme demain. L'agent **écrit** ces mouvements au build ; il ne **s'assoit pas** dans la boucle d'exécution à faire ce qu'une fonction fait.

## La place dans le noyau

S24 est une couche **Archive** (l'axe structurel du DAG de versions). Elle **réutilise** l'adresse de contenu de **S02** (`records.Hash`/`Canonicalize`, jamais forkée), l'arête **ChangeSet** de **S20** (`changesets.changeset.id`, jamais re-modélisée), et la **phase stable** de **S23** comme nœud — sans les éditer. Elle **ajoute** les tables **`dag.node`** + **`dag.edge`** (au-dessus de la ligne — une vérité, agent SELECT-only) et le serveur **MCP `dag`** (l'unique porte d'écriture). Les choix de représentation — parentage = relation d'arête, `head` = flag par nœud, body de hash `{kind, parent_ids, stratum, label}` — sont figés dans l'**ADR 0021**. Elle **prépare** : le **merge sémantique** (§122/§130, **S25**) qui rejoue les miroirs sur la coupe fusionnée ; la **promotion gated-by-mirror** des branches évolutives (§124) et l'**échantillonnage QD** des stepping stones (§123, **S26**). L'**OQ-S24-1** (dépendance forward by-design) : la route /version-dag utilise un id local déterministe pour animer un mouvement hors-ligne ; l'adresse de contenu autoritaire (le `records.Hash` Go) est surfacée via `dag_get` quand le Workbench lira le DAG vivant par le rôle SELECT-only — un branchement ultérieur qui ne change pas la sémantique. Le mur reste intact : /version-dag est en lecture seule ; enregistrer un nœud/arête ou déplacer la tête passe par le rôle writer `aidos` via le MCP `dag` (propose → approbation).
