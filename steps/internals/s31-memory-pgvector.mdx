<Info>Côté détail. Pour le concept, voir [Pour les futurs utilisateurs → S31](/steps/concept/s31-memory-pgvector).</Info>

S31 livre l'**adaptateur mémoire** du store `/brain` comme une capacité de l'**Archive** (`back/archive/brain/memory`) : **écrire** un `MemoryItem` et le **rappeler par similarité** sur des embeddings **pgvector**, à travers les **quatre mémoires indexables** de KRD §136 (épisodique / sémantique / procédurale / structurale). L'adaptateur **réutilise** le content-hash de S01 (l'`id` est l'adresse du corps, jamais forké) et **expand** la table `brain.memory_item` créée en S30, sans la redéfinir. La mémoire reste du **carburant** : S31 ne livre **aucun** chemin vers le noyau (la promotion MemoryFirewall §119.1 est une préoccupation séparée). Le store est **sous** la ligne de flottaison — l'agent y `SELECT/INSERT`, jamais `UPDATE/DELETE`, et **aucun** grant sur les schémas de vérité (le mur réaffirmé).

## Implémentation

<Note>La couche **Implémentation** est complétée au vert (CLAUDE.md §6) — code réel, fichiers. Les couches **Méta** et **Méta-méta** ci-dessous sont écrites dès le grill.</Note>

- **`back/archive/brain/memory/memory.go`** — le cœur pur. Le **`MemoryItem`** porte `Kind` (∈ `{episodic, semantic, procedural, structural}`), `Content`, `Provenance`, `ValidityScope`, `ExpiresAt`, `Confidence`, `Taint []Taint` (`unverified | stale | user_claim | incident_derived | external_source`), `Branch`, `CreatedAt`. **`(MemoryItem).ComputeID()`** calcule l'`id` = hash du corps canonique (réutilisant le content-hash de S01 — **jamais** forké). Un seul **port `Store`** : `Write(ctx, WriteInput) → (id, error)`, `Recall(ctx, RecallQuery) → ([]Hit, error)`, `Get(ctx, id) → (MemoryItem, error)`. `RecallQuery = {QueryText/QueryEmbedding, Kind?, Branch?, K}` ; `Hit = {Item, Score}`. Le **score = `1 - distance cosinus`** (plus haut = plus proche), de sorte que `Recall` trie **toujours** par score décroissant et borne à **≤ k**.
- **`back/archive/brain/memory/embedder.go`** — le port **`Embedder`** (`Embed(text) → []float32` de longueur **384**), **injecté**. `NewHashEmbedder(seed)` est l'embedder **déterministe** du mock (un schéma de bucketing par hash, sans modèle — même texte ⇒ même vecteur, **toujours**), seedé : le rappel est **reproductible** sous un seed fixe. Le runtime nomme **son** modèle dans la provenance, de sorte qu'un changement de modèle est un **réindexage tracé** (ADR 0025), jamais une dérive silencieuse.
- **`back/archive/brain/memory/mockstore.go`** — **`MockStore`** : en mémoire, cosinus **exact** sur les vecteurs du `HashEmbedder`. Aucune base, aucun réseau. C'est le backend des tests rapides et le jumeau de référence pour l'équivalence observationnelle.
- **`back/archive/brain/memory/pgxstore.go`** — **`PgxStore`** : `brain.memory_item` via pgx, ANN **HNSW + cosinus** (`<=>`, `vector_cosine_ops`). Les filtres `kind`/`branche` sont un `WHERE` SQL (le rappel ne ramène que les lignes pertinentes), l'ordre est `ORDER BY embedding <=> $query` (score = `1 - distance`). Une écriture est un `INSERT … ON CONFLICT (id) DO NOTHING` : réécrire le **même** corps est idempotent (même adresse), un corps **changé** est une **nouvelle ligne**.
- **Injection par constructeur, pas de global** : `NewMockStore(emb)` et `NewPgxStore(pool, emb)` reçoivent le même `Embedder`. La couture `Store` est ainsi prouvée de bout en bout : la **même** fixture s'exécute sur les deux et passe à l'identique.
- **`back/migrations/brain_memory_pgvector_baseline.sql`** — migration **expand-only / append-only**. Elle **AJOUTE** l'extension `vector`, **AJOUTE** à la table S30 les colonnes `kind`, `content`, `embedding vector(384)`, `provenance`, `validity_scope`, `expires_at`, `confidence`, `taint text[]`, et **AJOUTE** un index ANN **HNSW** (`vector_cosine_ops`). Elle ne **modifie** ni ne **supprime** rien de S30 (les trois CHECK S30 restent intacts) ; les nouvelles colonnes sont *nullable-or-defaulted* pour que les anciennes lignes restent valides. Une contrainte CHECK borne `kind` aux **quatre** mémoires indexables. **GRANT** : l'agent garde `SELECT + INSERT` sur `brain.memory_item` (le store est **sous** la ligne — carburant inscriptible), **aucun** `UPDATE/DELETE` (append-only gardé) et **aucun** grant sur `kernel`/`mirrors`/`fitness` (le mur réaffirmé au pied du fichier).
- **`back/mcp/memory/main.go`** — le **MCP memory** (Go MCP SDK, une op = un outil) : `memory_write` (un `MemoryItem`), `memory_recall` (par similarité, filtré `kind`/`branche`, top-`k`), `memory_get` (lire une ligne pour le rendu). Le serveur est **construit avec le `Store` configuré** (mock pour les tests, pgx pour le runtime) — la couture d'injection traverse la capacité. Pas de Hook (aucune nouvelle règle non-contournable — le mur S04 couvre déjà la vérité, `/brain` est délibérément sous la ligne), pas de Skill (les outils MCP + la boucle standard suffisent), pas de codegen (rien à émettre depuis un store de carburant).

## Méta — pourquoi cette forme

<Field name="Un port Store, deux adaptateurs vraiment interchangeables" type="MockStore exact ↔ PgxStore ANN, la fixture les juge identiques">
  L'unité de S31 n'est pas « pgvector », c'est la **couture**. Le mock (cosinus exact, sans base) et le pgx (HNSW, vraie base via Testcontainer) sont derrière la **même** interface, injectés par constructeur. « Les deux backends injectables » n'est pas une affirmation : c'est la **même** fixture qui passe à l'identique sur les deux. Le mock garantit des tests rapides et déterministes ; le pgx prouve que la vraie base honore le même contrat.
</Field>

<Field name="L'Embedder est un port, pas une dépendance dure" type="dimension 384 figée à la création de colonne, modèle nommé dans la provenance">
  Le mock n'a **besoin d'aucun modèle** (un `HashEmbedder` seedé) — donc les tests n'embarquent pas de poids et restent reproductibles. Le runtime **nomme son modèle** dans la provenance de l'item. La dimension **384** est figée à la création de `vector(384)` (ADR 0025) : un changement de modèle force un **réindexage délibéré** de la table append-only, jamais un `ALTER` en place. Le seam d'embedding est donc explicite et tracé.
</Field>

<Field name="Le rappel est de l'arithmétique, jamais un agent (determinism-first)" type="score = 1 - cosinus, trié desc, ≤ k, même seed ⇒ même ordre">
  `Recall` est une **fonction pure** : embedder la requête, comparer par cosinus, trier par score décroissant, borner à `k`, appliquer les filtres `kind`/`branche`. Sous un **seed fixe**, la même requête rend **toujours** le même ordre — épinglé par la propriété rapid (Go) et son jumeau fast-check (front). Un « RAG-agent qui devine la pertinence » serait un **trou de déterminisme** interdit : le rappel ne tranche rien, il classe.
</Field>

<Field name="Append-only : la supersession est une nouvelle ligne, gravée dans les GRANTs" type="INSERT idempotent par content-hash, aucun UPDATE/DELETE">
  Une mémoire ne s'**édite** jamais. Réécrire le même corps est idempotent (l'`id` est son adresse) ; une mémoire « superseded » est une **nouvelle ligne**, l'ancienne reste rappelable, l'expiration est `expires_at`. La migration grave cette règle dans Postgres : l'agent n'a **aucun** grant `UPDATE/DELETE`. Le code et les GRANTs disent la **même** chose à deux niveaux — comme à S30.
</Field>

## Méta-méta — la loi que ça sert

<Field name="« Carburant de contexte, jamais une vérité » (KRD §136 / §119.1)" type="indexable et branch-aware, mais non-décisoire">
  Tout le LIVRE XXIV tient en une asymétrie : la mémoire est **lisible, indexable, branch-aware** — et **non-décisoire**. S31 ne livre que la moitié *fuel* : on écrit et on rappelle, rien n'atteint le noyau. Un item rappelé ne **tranche** rien ; il ne peut faire échouer un run que s'il est **promu** en miroir ou en sensor (le flux MemoryFirewall, une autre tooth). La provenance et le taint accompagnent **chaque** hit pour que le carburant reste lisible comme tel.
</Field>

<Field name="Réutiliser, ne pas réinventer — content-hash S01, table S30, lib pgvector" type="ADR 0007 / 0008">
  L'`id` réutilise le content-hash de S01 (jamais forké) ; la table `brain.memory_item` **expand** celle de S30 (jamais redéfinie) ; le vecteur et l'ANN sont **pgvector natif** (`replaceable` adapter, jamais un service externe — claude-mem est la mémoire de l'agent qui *construit* AIDOS, pas ce brain). La nouveauté est strictement la **couture de rappel** et son contrat ; tout le reste est composé.
</Field>

<Field name="La couture de confiance, posée mais non tranchée ici (KRD §138)" type="confidence numérique ↔ ordinale du ContextRouter S33">
  S31 stocke une `confidence` **numérique** (0..1) ; KRD §138 / le ContextRouter de S33 filtrent sur une échelle **ordinale** (`observed_once | repeated | proven_by_sensor`). Le mapping est **détenu par S33**, pas inventé ici (OpenQuestion enregistrée, ADR 0025 / 0008). S31 ne décide pas de la forme que le router et le store partageront — il livre le store et laisse la couture explicite.
</Field>

<Field name="Pas de monstre — chaque contrat a son miroir vivant" type="fixture ×{mock,pgx} + propriété rapid + jumeau front">
  La loi de complétude (§29/§33) exige que chaque comportement ait son miroir. La **fixture write-then-recall** couvre chaque op (`write` → id content-hash, `recall` → plus proche d'abord ≤ k trié desc, filtres `kind`/`branche`, supersession → nouvelle ligne) sur **les deux** backends ; la **propriété rapid** épingle l'invariant ∀ du contrat `Store` ; le **jumeau fast-check** front pin la même reproductibilité. Aucun backend sans la fixture qui prouve l'équivalence — aucun monstre.
</Field>

## Tests (miroirs)

- **`memory_fixture_test.go`** (N2, `authority: above`) — `state → command → events`, **paramétré sur `backend ∈ {mock, pgx}`** (le pgx via un Testcontainer pgvector). Le cas done : écrire un item sémantique → `id == ComputeID()` (S01) puis rappelable ; rappeler `~"shopping cart"` k=2 sur les quatre kinds → le sémantique « cart » d'abord, `len == 2`, trié par score décroissant ; filtre `kind: semantic` + `branch: main` → seules les lignes correspondantes ; une écriture superseding → `count + 1` (nouvelle ligne), et réécrire le **même** corps est idempotent. Les deux backends passent **à l'identique** — c'est « les deux backends injectables ».
- **`memory_property_test.go`** (N1, rapid, `authority: below`) — le miroir de reproductibilité ∀ : `Recall(k)` rend ≤ k hits triés par score décroissant ; les filtres `kind`/`branche` tiennent toujours ; `Write` rend `id == content hash` du corps puis l'item est rappelable ; append-only (une écriture superseding incrémente le compte, aucune op ne supprime) ; le `taint` round-trip intact ; même seed ⇒ même ordre (déterminisme).
- **`front/web/lib/memory.test.ts`** (fast-check) — le jumeau front pin le **même** rappel pur (cosinus trié desc, ≤ k, filtres) que le `MockStore` Go : les hits à l'écran correspondent à ceux du moteur.
- **`tests/e2e/memory-backends.spec.ts`** (Playwright) — `/memory-backends` rend les quatre chips de kind, une requête de rappel → hits triés par score décroissant (le plus proche d'abord), le filtre `kind: semantic` ne laisse que du sémantique, la bascule de backend (mock ↔ réel) rend le même top hit (interchangeables), chaque hit montre son `taint`/`provenance`, et la bannière « carburant, jamais une vérité » est présente.
