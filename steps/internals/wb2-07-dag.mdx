## Implémentation

**Le twin de DAG `lib/v2/version-dag.ts`** — la source unique de la LOGIQUE, PUR (aucun React/DOM, aucun LLM, aucune horloge, aucun aléa) :

- Types : `Stratum` (`above` | `below`, le jeu clos `STRATA` + `isStratum`) ; `DagNode` (`id` = hash content-adressé, `label`, `parentIds` — un DAG, ≥1 parents —, `head`, `stratum`) ; `DagEdge` (`from`, `to`, `changeset` = l'id du ChangeSet S20) ; `VersionDag` (`nodes`, `edges`) ; `DagError` (`empty_node_id`, `duplicate_node_id`, `stratum_unknown`, `dangling_parent`, `dangling_edge`, `cycle`, `no_head`) ; `DagResult`.
- `versionHash(label, parentIds, stratum)` : **l'identité content-adressée**. Corps canonique (`label` + parents **triés** + `stratum`) → djb2 → `v:<hex>`. Même corps → même id ; **l'ordre des parents n'affecte pas l'identité** (corps trié).
- `validateDag(dag)` : la liste ordonnée des `DagError`. Rejette : id vide ; id dupliqué ; strate hors jeu clos ; parent pendant ; arête pendante ; **cycle** (via `hasCycle`, un Kahn qui détecte les nœuds non sortis) ; **pas de tête** (≥1 head sur un DAG non vide).
- `topoSort(dag)` : **Kahn**, tie-break déterministe (ordre d'entrée des nœuds). Un parent précède **toujours** son enfant ; sur un cycle, renvoie ce qui a pu sortir (le caller valide d'abord).
- Les **trois mouvements append-only** (§121) : `branch(dag, fromId, label, changeset)` ajoute un nœud (`head:true`) + une arête, déplace la tête depuis l'ancien head, **ne supprime rien** ; idempotent (même corps → même id → DAG inchangé). `checkoutAncestor(dag, phaseId)` : un **head-flag move** — `nodes.map(head = id===phase)`, **aucune arête touchée**, tous les nœuds présents. `rebranch` = un `branch` depuis l'ancêtre re-checkout.
- Lecture : `ancestors(dag, id)` (parents transitifs, triés) ; `isReachable(dag, from, to)` (irréflexif sur soi) ; `heads(dag)` (les nœuds `head:true` — plusieurs lignes parallèles possibles, §125).
- `syntheticDag()` : le **DAG canonique §120** déterministe (`v0→v1→v2`, branch `w1` off `v1` en `above`, branch `g1` off `v1` en `below`, rebranch `v2a` off `v1`, tête sur `v1` après checkout) + un atlas `labelToId`. Les ids sont des hashes ; les `label` restent lisibles pour l'écran et l'e2e. OpenQuestion documentée : synthétique tant que le store ne sert pas le DAG live — ne bloque pas (forward-dependency).

**L'écran `app/v2/dag/DagClient.tsx`** (`"use client"`) : `useMemo` appelle `syntheticDag()` + `topoSort`. Rend en **React Flow** (`@xyflow/react`, ADR 0053) : un nœud custom `VersionNode` (`v2-dag-node-<label>`, `data-head`, `data-stratum`, le head en `ring-2 ring-primary`, l'abandonné en `opacity-70`), positionné déterministiquement (x = rang topologique × 190, y = bande de strate). Les arêtes portent le `changeset` en label. Le canvas (`v2-dag-canvas`) a `panOnDrag`, `zoomOnScroll`, `zoomOnPinch` + les `<Controls/>` (pan/zoom action-capable). `onNodeClick` ouvre un détail (`v2-dag-node-detail` : `v2-dag-detail-hash`, parents, strate, `v2-dag-detail-reachable` via `isReachable(dag, rootId, …)`, `v2-dag-detail-readonly`). Le résumé (`v2-dag-summary`, `data-node-count`, `data-edge-count`, `v2-dag-head`) + les deux bandes (`v2-dag-band-above`, `v2-dag-band-below`).

**La page `app/v2/dag/page.tsx`** (Server Component) : assemble les chaînes du namespace i18n `v2Dag` (FR + EN), rend titre / sous-titre / note-du-mur (`v2-dag-wall-note`), puis `<DagClient/>`. Nouvelle route — aucune route existante touchée.

**Les miroirs** :

- Reproductibilité — `lib/v2/version-dag.test.ts` (Vitest + fast-check) : **hash stable** (même corps → même id ; ordre des parents indifférent) ; **acyclique** (toute séquence de mouvements laisse un DAG sans cycle, `isReachable` irréflexif) ; **append-only** (branch/checkout/rebranch ne font que croître — nœuds & arêtes monotones non-décroissants) ; **checkout = head-flag move** (aucune arête touchée, tous les nœuds présents, exactement la cible en tête) ; **topo-trié** (un parent précède toujours son enfant) ; **déterminisme** (même séquence → même DAG) ; le **DAG canonique §120** valide (acyclique, v0 atteint v2a, v2 abandonnée présente, deux bandes) ; **rejet** (id vide / dupliqué / strate inconnue / cycle / sans tête). GREEN (8 tests).
- e2e — `tests/e2e/v2-dag.spec.ts` (Playwright) : **une branche s'affiche** (les six versions + leurs arêtes, tête `v1` mise en avant `data-head=true`, `v2` abandonnée présente, deux bandes, comptes 6 nœuds / 5 arêtes) ; **pan/zoom** (`.react-flow__controls` présent, clic zoom-in) ; **action-capable** (clic `v2a` → détail hash / atteignabilité / read-only) ; **bas read-only** (aucune requête POST/PUT/PATCH/DELETE) ; **déterministe** (mêmes hashes au rechargement). GREEN (2 tests). Non-régression WB2-05/WB2-06 (`v2-grille`, `v2-anatomie`) GREEN (4 tests).

## Méta

- **Déterminisme-first.** Aucun agent ne compose le DAG, ne le trie, ni ne calcule un hash : `versionHash`, `topoSort` (Kahn), `isReachable` sont des fonctions **pures et autoritatives**, et le miroir fast-check épingle leurs invariants (hash stable, parent-avant-enfant, irréflexivité). « Un diff est un algorithme de diff, jamais un agent » (§6) prend ici la forme : un **DAG est un algorithme de graphe**, jamais un jugement.
- **L'append-only, prouvé comme un invariant.** Le cœur de S24 — « la ligne abandonnée n'est jamais détruite » — n'est pas une intention : c'est une **property** (les compteurs de nœuds & arêtes sont monotones non-décroissants pour **toute** séquence de mouvements ; `checkoutAncestor` ne touche **aucune** arête). Le mouvement arrière est un *head-flag move*, vérifié, pas une suppression.
- **L'identité par le contenu, pas par un compteur.** `versionHash` rend l'identité **reproductible** : rejouer la même construction donne le même graphe, byte-identique (le miroir « même séquence → même sérialisation »). C'est le content-addressing de S01 porté au plan des versions — pas d'auto-incrément, pas d'horloge.
- **Le bas read-only, prouvé.** L'e2e surveille le réseau : naviguer, zoomer, cliquer une version, lire son détail — **aucune écriture ne part**. Le mur (§2) est un invariant vérifié, pas une promesse.

## Méta-méta

- **Le DAG est la mémoire du refus d'effacer.** Le principe append-only d'AIDOS (rien n'est détruit, la tête est mutable) est le plus profond de la méthode : il transforme chaque exploration ratée en **stepping-stone** potentiel (la curation QD, S26, y puise). WB2-07 en fait une **image** — la ligne abandonnée reste dessinée, en sourdine, jamais effacée. Voir le DAG, c'est voir AIDOS **refuser l'oubli**.
- **Une seule source, trois temps de la même donnée.** Comme l'arbre (WB2-04) et l'anatomie (WB2-06), le DAG consomme un synthétiseur déterministe (`syntheticDag`, le canonique §120) qui sera remplacé par le store réel **sans toucher à l'écran**. La logique (acyclicité, topo-tri, atteignabilité) est prouvée indépendamment de l'origine de la donnée ; le jour où le DAG devient live, seul change *d'où* viennent nœuds et arêtes, pas *comment* le graphe se compose.
- **La ligne de flottaison sépare deux régimes de vérité.** Les bandes `above` (humain) / `below` (évolutionnaire) ne sont pas décoratives : elles disent **qui a le droit d'écrire quoi**. Au-dessus, la vérité humaine (le mur, §2) ; en dessous, l'exploration machine quarantainée (l'EvolutionSandbox, S42). Le DAG les **co-héberge sans les confondre** — le même graphe, deux régimes, une frontière dessinée.
