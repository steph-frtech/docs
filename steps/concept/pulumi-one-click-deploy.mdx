## En une phrase

Le bouton **« Déployer »** de `/v2` est branché sur un **VRAI déploiement Pulumi PAR PROJET** : un clic lance `aidospulumi up --project X --env dev --entities <X>` (l'exécuteur de l'[item 1](/steps/concept/dp-pulumi-per-project)), qui **émet l'app de X** (`emitApp` → ses **PROPRES** entités) puis fait monter par **Pulumi** la full-stack **réelle** de X — une **db seedée** du schéma et des entités de X **+ l'app brandée X** — routée en HTTPS à **`X-dev.sagedesk.fr`** (vrai cert Let's Encrypt). Pulumi devient **LE moteur** de déploiement ; l'ancien `docker compose` est **remplacé** (ADR 0052 amendé), le compose-emit reste une **projection dérivable jamais exécutée**.

## Le problème que ça résout

L'[item 1](/steps/concept/dp-pulumi-per-project) a livré l'**exécuteur** — `aidospulumi up`, qui lève **pour de vrai** une full-stack par projet×env via Pulumi (`@pulumi/docker`), preuve `demoshop-dev` live. Mais cet exécuteur restait **en ligne de commande** : depuis l'écran `/v2/deploy`, le bouton « Déployer » ne lançait encore qu'un **planificateur compose** — il *décrivait* la conteneurisation sans la **lever vraiment**, et pour un déploiement réel il fallait des **one-offs** (alphashop, guestbook montés à la main).

L'exigence utilisatrice du 2026-06-14 tranche, **item 2** : le bouton « Déployer » de `/v2` doit lancer le **vrai** déploiement Pulumi **par projet** — un clic, et c'est la full-stack **réelle** du projet qui prend vie, avec ses **propres** entités (pas un gabarit), routée en HTTPS. *Tout se fait par écran* : la capacité réelle de déploiement, jusqu'ici headless, devient un **bouton** qui *exécute*.

## Le geste capital — un clic = la full-stack réelle de X, ses propres entités

Le cœur, c'est que le bouton ne *planifie* plus : il **exécute** l'exécuteur prouvé de l'item 1, en lui passant les entités **propres** du projet.

```text
[ /v2 · clic « Déployer » sur le projet X ]
            │  (garde ADR 0052 : auth + rate-limit)
            ▼
deployStackPulumi(project=X, entitiesJSON = entityToSource(emitApp(state)))
            │  écrit les entités de X dans un fichier temp (mkdtemp / finally rm)
            ▼
go run ./cmd/aidospulumi up --project X --env dev --entities <tmp>   (execFile, JAMAIS un shell)
            │  l'exécuteur item 1 : aidosappemit(X) → schéma + entités + APP_NAME=X
            ▼
pulumi up   →   X-dev-db   (Postgres SEEDÉE du schéma & des entités de X)
                X-dev-app  (l'app brandée X)        réseau traefik_default (externe)
            │
            ▼
UpResult{ url, containers, stack }  →  l'écran affiche :
   URL live   https://X-dev.sagedesk.fr   (vrai cert Let's Encrypt)
   conteneurs X-dev-app, X-dev-db
   cible      X-dev.sagedesk.fr           statut « up »
```

Trois choses sont **capitales** :

- **Les entités déployées sont CELLES de X, par projection PURE.** L'écran calcule la source de l'app avec `emitApp(state)`, puis `entityToSource(entity)` projette chaque entité en `[]EntitySource` (mapping **scalaire clos** S35→type Go — `text`/`numeric`/`int`/`bool`/`timestamptz`, **ordre source préservé**, `id` content-adressé). C'est une **fonction pure** : la db déployée est seedée du schéma **réel** de X, pas d'un gabarit.
- **Le projet est résolu par UN SEUL juge.** `projectOf(entity)` **=** `subdomainOf` : le sous-domaine `X` et le nom de projet `X` sont **le même** — d'où la cible `X-dev.sagedesk.fr` exacte, jamais devinée.
- **Pulumi monte les conteneurs ; l'action ne fait que les matérialiser et lancer.** `deployStackPulumi` écrit les entités dans un fichier **temp** (`mkdtemp`/`finally rm`) et exécute `aidospulumi up` via `execFile` — `project` et les arguments **ne passent JAMAIS par un shell**. Le JSON `UpResult` de l'exécuteur est parsé **tel quel** : la sortie « live » est la **vérité de l'exécuteur**, jamais inventée.

## Pulumi = le moteur, compose = projection dérivable jamais exécutée

C'est le basculement gravé par l'ADR 0052 amendé (et l'ADR 0043 amendé). Jusqu'ici le bouton de `/v2/deploy` matérialisait un `docker-compose` ; désormais **Pulumi est LE moteur** — c'est lui qui **fait monter** les conteneurs, par projet. Le `docker-compose`-emit n'est pas supprimé pour autant : il devient une **projection dérivable** de la **même** source (le `StackManifest` / l'app émise), **jamais exécutée** — une vue parmi d'autres (anti-overwrite §9, **une source → N cibles**). Le planificateur compose (`v2-deploy-deploy`) reste **accessible** à l'écran, en **secondaire** ; le bouton **primaire** est le déploiement Pulumi réel.

## Le mur — un geste gaté qui n'écrit aucune vérité

DP grave ici la frontière du mur (§2). L'action de déploiement est un **geste gaté side-effectant** : le bouton est **gardé** par la garde ADR 0052 (auth + rate-limit) **en amont**, et il **n'écrit AUCUNE vérité** — rien dans `kernel`/`mirrors`/`fitness` ; il **matérialise** des entités (une projection below-the-line) et **lance** l'exécuteur. Les entités elles-mêmes sont une **projection PURE** de l'état de l'écran (`entityToSource`), **aucun** LLM n'entre. Et la **porte de validation humaine DP28** reste **en amont** du staging : l'`env` est **`dev` par défaut**, jamais un push silencieux vers la prod.

## Ce que ça autorise

À partir de maintenant, **déployer un projet de /v2 = un clic** : `deployStackPulumi(X)` lève la full-stack **réelle** de X — Postgres seedée de **ses** entités, app brandée X, routée HTTPS à `X-dev.sagedesk.fr` avec un vrai cert — sans ligne de commande, sans one-off. Le déploiement 1-clic par projet **supersede** les déploiements one-off (`alphashop`, `guestbook`) : chaque projet de `/v2` déploie **ses propres** entités, en un geste. Ce que ça **préserve intact** : l'exécuteur de l'item 1 (`MaterialiseApp` + `EmitPulumiStackApp` + `APP_NAME`) n'est pas touché — il est **réutilisé** ; le `StackManifest` reste la source unique ; le compose-emit reste une projection dérivable (jamais exécutée) ; et le `BuilderClient` est laissé tel quel (son real-deploy reste sur le pipeline existant, ses kernels candidats ne portant aucun champ d'entité typé que `--entities` exige — rien n'est cassé, §9). Pulumi est **LE moteur**, l'écran le **déclencheur**, et la garde + DP28 la **discipline** — *tout se fait par écran*, un clic restant un **geste gaté**, jamais une écriture de vérité.
