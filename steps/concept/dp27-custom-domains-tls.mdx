## En une phrase

DP27 grave les **domaines custom** et le **TLS automatique** : un domaine custom est **câblé dans l'Environment** DP06 (résolu pour cet environnement), puis l'app y est servie en **HTTPS** par les **labels Traefik émis** (DP03, la **source unique**) — avec un **certificat ACME** minté par le **certresolver** (`letsencrypt`) et un **redirect HTTP→HTTPS**. Le binding domaine→projet reste **injectif** (un domaine = un projet) et DP27 **étend** `domainbind` de S97, ne le **duplique** pas.

## Le problème que ça résout

S97 a posé le **binding de domaine** : un domaine custom **lié à un projet** de façon **injective** — un domaine = **un seul** projet, refusé sinon avec `DOMAIN_ALREADY_BOUND` (fail-closed, nommant le propriétaire), avec la normalisation (`normalizeDomain`), la validation (`validDomain`) et la décision « ce binding sert-il l'app en HTTPS ? » (`ServesHTTPS`) toutes prouvées. Mais S97 décrivait *quel* domaine pour *quel* projet — sans dérouler *où* : **dans quel environnement** le domaine vit, et **comment** Traefik le sert concrètement en HTTPS.

L'EPIC D avait pourtant déjà appris à raisonner ces deux pièces : DP06 sait câbler une capacité **dans un Environment** (prod, staging, local…) et savoir lequel porte le TLS, et DP03 sait **émettre les labels Traefik** d'une stack (le routeur, le certresolver, le redirect HTTP→HTTPS). Restait à **brancher** ces moteurs sur le domaine : *résoudre ce domaine pour cet environnement*, puis *émettre les labels HTTPS qui le servent* — sans jamais réécrire un second jeu de labels qui dériverait du premier.

Le réflexe naïf serait d'écrire un **second** vocabulaire de labels HTTPS à côté de DP03 — un « domaine avec ses propres labels ». Ce serait dupliquer la convention Traefik, et faire dériver deux jeux divergents. DP27 pose la règle inverse : **une seule source** de labels HTTPS, dont le compose YAML **et** le binding de domaine **dérivent** ; et **étendre** S97 additivement, sans rien casser de l'injectivité ni de la décision HTTPS.

## Le geste capital — un domaine custom servi en HTTPS dans son Environment

Le cœur de DP27, c'est que le domaine reste **résolu dans son environnement**. On câble un domaine custom dans un Environment DP06 ; DP27 le **résout pour cet environnement** (en réutilisant la normalisation et la validation de S97 et les bindings de l'environnement de DP06), puis **émet les labels Traefik HTTPS** qui le servent — le routeur, le certificat ACME via le certresolver, et le redirect HTTP→HTTPS.

```text
domaine custom + Environment (prod)   →  EnvDomainBinding{ URL https://…, labels Traefik, TLS=true }
domaine custom + Environment (local)  →  REFUSÉ (un env local sans TLS ne sert pas un domaine HTTPS)
domaine custom + Environment inconnu  →  REFUSÉ
```

La **règle TLS est fail-closed** : un environnement qui ne porte **pas** de TLS (le `local`) **refuse** un domaine HTTPS, et un environnement **inconnu** est refusé. On ne sert jamais « en clair par défaut » : si l'environnement ne peut pas garantir le HTTPS, il ne sert pas le domaine. Et c'est le **code** qui juge si l'environnement sert HTTPS (`EnvServesHTTPS` délègue au `ServesHTTPS` de S97) — **jamais** un LLM.

## La source unique des labels HTTPS — DP03 réutilisé, jamais dupliqué

Le point décisif de DP27, c'est l'**unicité de source**. Le vocabulaire des labels Traefik HTTPS — le routeur, la règle d'hôte, le certresolver, le port de service, le middleware de redirect — est extrait dans **UNE seule fonction pure** : `TraefikHTTPSLabels`. C'est désormais la **source unique** :

```text
TraefikHTTPSLabels(router, host, certResolver, redirectMiddleware, port)  →  []TraefikLabel
        ↑ source unique
        ├── le compose YAML (DP03 renderTraefikLabels) en dérive  (sortie BYTE-IDENTIQUE)
        └── le binding domaine→Environment (DP27) en dérive
```

Le rendu YAML de DP03 (`renderTraefikLabels`) **délègue** maintenant à cette fonction — et sa sortie reste **byte-identique** (le miroir le prouve : les labels du compose n'ont pas bougé d'un octet). Il n'y a **jamais** deux jeux de labels divergents : le compose et le domaine **dérivent du même** vocabulaire. C'est l'unicité-source poussée jusqu'au label : changer la convention HTTPS la change *partout*, en un seul endroit.

## Le câblage domaine→Environment — la forme exposable au front

Quand on résout un domaine pour un environnement, DP27 rend un **`EnvDomainBinding`** : une forme complète, prête pour le front (un onglet `/domain-bind` par-environnement, si on l'ajoute plus tard) :

| Champ | Rôle |
|---|---|
| `Environment` / `Domain` / `Project` | le domaine résolu pour cet environnement, lié à son projet |
| `URL` | l'URL **HTTPS** live (`https://<domaine>`) |
| `RouterName` / `RedirectMiddleware` | le routeur Traefik + le middleware de redirect HTTP→HTTPS |
| `CertResolver` | le certresolver ACME (`letsencrypt`) qui minte le certificat |
| `TLS` / `Managed` | l'environnement porte-t-il le TLS ; le domaine est-il managé |
| `Labels` | les labels Traefik **émis** (DP03 réutilisé — `TraefikHTTPSLabels`) |

`ResolveInEnvironment` est une **fonction pure** : (a) elle résout le domaine pour l'environnement (réutilise `normalizeDomain`/`validDomain` S97 + `envbindings.BindingsFor` DP06), (b) elle émet les labels via `composeemit.TraefikHTTPSLabels` (port 0, route vers le service déclaré). Le `RouterName` réutilise `routerNameOf` de S97 ; le `CertResolver` est le `DefaultCertResolver`.

## Le mur — le domaine dans l'Environment, vérité ou résolution pure

DP27 respecte le mur (§2) sur **deux niveaux**. **Résoudre** un domaine pour un environnement (`ResolveInEnvironment`) est **below-the-line** : une résolution **pure** qui ne grave **aucune** vérité — elle re-projette ce que S97 et DP06 figent déjà.

Mais **fixer** un domaine **dans** un environnement, c'est une **vérité d'environnement**. DP27 ne l'écrit donc **jamais en passant** : `ProposeEnvironmentDomain` suit le chemin **propose→ChangeSet** (le même pattern que DP24) — il ouvre un **DRAFT ChangeSet** (S20 `changeset.Open`) qui porte un `spec_delta(env_domain_binding)` **et** son `mirror_delta` complet (pas de monstre), content-adressé et reproductible, **toujours** en `StatusDraft` (jamais `APPLIED` — le mur). Et il **refuse** (pas de DRAFT) si le binding est invalide ou si l'environnement ne porte pas de TLS. La seule porte vers le kernel reste : idée → mirror → `/goal` → approbation humaine.

## Traefik OWNS le réseau — DP27 n'émet que des labels

Le partage de responsabilité est net : **Traefik possède le réseau et les ports** (les conventions `/data/dockers`, le reverse-proxy, l'obtention du certificat ACME). DP27 n'**émet** que les **labels** qui déclarent à Traefik *comment* router le domaine — il ne touche **ni** au réseau, **ni** aux ports, **ni** au cycle ACME. Le binding de domaine est une déclaration ; Traefik l'exécute.

C'est le **déterminisme-first** (§6/§8) : normaliser un domaine, le résoudre pour un environnement, émettre un jeu de labels et calculer un binding sont des décisions **pures** — aucune horloge, aucun RNG, aucune I/O, aucun docker, **aucun LLM**. Même domaine + même environnement ⇒ mêmes labels et même binding (le miroir de reproductibilité le prouve).

## Ce que ça autorise

DP27 transforme le binding de domaine en un **câblage par-environnement** : ce que ça **autorise**, c'est de servir un domaine custom **en HTTPS** dans son Environment (URL `https://…`, certificat ACME via le certresolver, redirect HTTP→HTTPS), avec les **labels Traefik émis** comme **source unique** (le compose YAML et le domaine en dérivent, jamais un second jeu divergent), et de fixer ce domaine dans l'environnement par un **DRAFT ChangeSet** (jamais un write direct). Ce que ça **préserve intact**, c'est S97 dans son entier : `Bind`, `DOMAIN_ALREADY_BOUND`, `IsInjective`, `ServesHTTPS`, `normalizeDomain`, `validDomain` ne bougent **pas** — un domaine reste **un** projet, injectif `forall`. La loi de complétude veille : le geste ne vit que parce qu'il porte sa preuve vivante — le miroir Go (HTTPS sur tout env TLS, local refuse HTTPS, env inconnu refusé, labels == `composeemit.TraefikHTTPSLabels`, injectivité préservée, propose DRAFT reproductible). Reste pour le front (additif) le greffage d'un onglet `/domain-bind` par-environnement sur la forme `EnvDomainBinding` — la lib front S97 (`lib/domainbind.ts`) reste verte, intacte.
