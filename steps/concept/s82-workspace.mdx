## En une phrase

S82 donne à **chaque projet son propre bac à sable isolé** — un workspace dédié (conteneur + dépôt git/jj + worktree + limites de ressources) où le code de votre app vit, compile et prouve ses miroirs, **sans jamais voir** un autre projet ni le truth-store.

## Le problème que S82 résout

Quand AIDOS construit votre application, le code généré doit **vivre quelque part** : un endroit pour s'écrire, compiler et exécuter ses tests. Si tous les projets partageaient le même répertoire, deux risques apparaîtraient :

- **La fuite (escape)** : le projet A pourrait lire l'arbre, le build ou les secrets du projet B — ou pire, le truth-store d'AIDOS lui-même.
- **Le voisin bruyant (noisy-neighbor)** : un projet parti en boucle infinie (CPU à 100 %), une fork-bomb ou un remplissage de disque pourrait **affamer** tous les autres.

S82 supprime ces deux risques par construction : chaque projet reçoit un **workspace isolé**, raciné sous son propre arbre, avec des **limites de ressources** que le système d'exploitation fait respecter.

## Comment vous l'utilisez

Depuis le panneau **« Bac à sable par projet »** du Workbench :

1. **Provisionner** : nommez un projet, et son workspace isolé est créé — racine dédiée, zones ADR 0001, worktree git/jj privé, plafonds de ressources déclarés.
2. **Vérifier l'isolation** : demandez si un chemin est lisible. Un chemin sous un autre projet (ou sous le truth-store) revient `SANDBOX_ESCAPE`.
3. **Vérifier les ressources** : simulez une charge. Un dépassement d'un plafond positif (CPU/mém/disque/temps) revient `SANDBOX_RESOURCE_LIMIT` — le runaway serait tué.

## Le mur tient toujours

Un workspace **n'écrit aucune vérité**. Sa racine est *sous la ligne* (le code, les essais du projet). Le truth-store d'AIDOS (kernel, miroirs, fitness) est **hors** de tout workspace : l'atteindre, c'est précisément un `SANDBOX_ESCAPE`. La capitalisation d'un artefact d'un projet vers un autre passe par la **porte légale** (idée → miroir → /goal), jamais par une lecture directe de son arbre.
