## En une phrase

L'app qu'AIDOS construit pour vous n'est **pas** une application : c'est **une seule spec** — déclarée au-dessus du mur (entités · opérations · invariants · vues · contrôles) — qui se **projette vers N plateformes**. **Backend** = un serveur **Hono / TypeScript** (les opérations deviennent des routes) **+ un sidecar interpréteur Go** (qui exécute les opérations sur la base) ; **Web** = **React** (Hono + React) ; **Mobile** = **Expo / React Native** (« expo go ») ; **Desktop** = **Electron** (« l'app en dur »). La **plateforme est une dimension** de l'émission, **jamais** une seconde source à maintenir, et chaque cible est une **projection déterministe byte-stable** de la même vérité. La clé de voûte runtime de **toutes** les plateformes est le **même** sidecar interpréteur Go : il **réutilise `operation.Interpret` verbatim**, n'écrit **aucune** vérité, et ne touche **que** le schéma de l'app émise. **Une source → N plateformes.**

## Le problème que ça résout

Vous décrivez **une fois** ce que votre app doit faire — ses entités, ses opérations, ses règles, ses écrans. Puis vous voulez la même app **partout** : dans un navigateur, sur un téléphone, sur un poste de travail. Le piège habituel : **réécrire** l'app pour chaque plateforme. Maintenir un backend, un front web, une app mobile et une app desktop comme **quatre sources divergentes** qui dérivent l'une de l'autre au premier oubli. Chaque chemin casse l'unicité de la source : la vérité du « quelles entités, quelles opérations, quelles règles » se met à exister en quadruple, et le multi-plateforme devient une **traduction manuelle** fragile.

AIDOS pose la règle inverse. Il n'y a **qu'une** source — votre spec, au-dessus du mur — et **N projections** en dessous. Changer de plateforme, ce n'est pas réécrire : c'est **demander une cible de plus** à l'émetteur. La même déclaration produit le serveur Hono, le front React, l'app Expo et l'app Electron, **déterministiquement**, **sans** jamais toucher la source. **Multi-plateforme par projection, jamais par réécriture.**

## La stack multi-plateforme — une source, N plateformes

| Plan | Plateforme | Ce qu'AIDOS émet |
|---|---|---|
| **Backend** | serveur émis | un router **Hono / TypeScript** pur-fonctionnel : chaque **opération** devient une **route** (valide → route → projette) |
| **Backend** | exécution op→DB | le **sidecar interpréteur Go** : il **exécute** les opérations sur la base, en réutilisant `operation.Interpret` |
| **Web** | app web | **React** (Hono + React — SSR/JSX ou API Hono + client `hc` typé) |
| **Mobile** | app native | **Expo / React Native** (« expo go ») — partage le client typé et les types |
| **Desktop** | « l'app en dur » | **Electron** — empaquète le même front React + le serveur Hono + le sidecar |

Le fil rouge : **un seul** modèle de types partagé et **un seul** client de données typé (`hc` de Hono) irriguent Web, Mobile **et** Desktop — pas de double-typage, pas de re-déclaration par plateforme. La base de données (dialecte Postgres) et son schéma (DDL) sont **neutres à la plateforme** : la même base sert les quatre.

## La clé de voûte — le sidecar interpréteur Go

Toutes ces plateformes ont un point commun : pour **exécuter** une opération (créer une commande, vider un panier, appliquer une règle), elles appellent **le même** sidecar interpréteur Go. C'est lui qui détient la **seule** logique d'interprétation, **gouvernée**, **non dupliquée** :

- Il **réutilise `operation.Interpret` verbatim** — **aucune** règle d'interprétation n'est réécrite, et il n'est **jamais** ré-émis en TypeScript : une seule source d'interprétation autoritaire (même règle → même résultat, prouvé une fois).
- Il expose un **contrat HTTP** simple : `POST /interpret` `{operation, input, auth?}` → `{result, events}`, et `GET /healthz`. Le serveur Hono émis s'y branche par un simple appel — il **valide/route** côté TS, **délègue** l'exécution au sidecar Go, **projette** le résultat.
- Il **n'écrit aucune vérité** : il ne touche **que** le schéma de votre app (lire, créer, vider une entité), **jamais** le noyau d'AIDOS (`kernel`/`mirrors`/`fitness`). Le mur tient.

## Prouvé runnable — pas une promesse

Le sidecar **tourne aujourd'hui**. Treize miroirs le scellent, tous **verts** : `createOrder` crée un `Order` depuis le panier, **vide** le panier, et émet les événements `[OrderCreated, CartCleared]` ; un refus de policy (`DENY`), une opération inconnue ou un panier absent donnent un **échec typé** **sans** `Order` ; un miroir property (rapid) prouve que le **même** input sur le **même** état produit le **même** effet (reproductible) ; six contrats `httptest` épinglent le **fil** de bout en bout ; et deux miroirs d'intégration tournent contre un **Postgres réel** (Testcontainers) — read / insert / delete réels, avec un *skip* gracieux quand Docker est absent. Le binaire a été booté, et un `curl /interpret` a renvoyé un `Order` **réel**.

## Le serveur de boutique Go était une divergence — corrigée

La toute première démonstration (la slice de bout en bout, §S46) avait livré un serveur de boutique **en Go**. C'était une **divergence** de spec : l'app émise héritait par défaut de la stack **d'AIDOS lui-même** (Go), pas de sa propre cible. La cible canonique de votre app, c'est **Hono/TS** — le Go in-process a été remplacé par le couple **serveur Hono émis + callback vers le sidecar Go**. Le serveur Go subsiste comme **preuve d'exécution** de l'interpréteur (la parité de comportement que le sidecar préserve), pas comme cible de déploiement.

## Le déploiement réel — par Pulumi

Une fois émise, votre app multi-plateforme se **déploie pour de vrai** : le bundle Hono/TS (front React + routing back) **+ le sidecar interpréteur Go** (la seule dépendance Go, partagée et versionnée avec le noyau) est provisionné par **Pulumi** — un **stack par projet×env**, réel, prouvé par `demoshop-dev` en ligne (routé Traefik, vrai certificat Let's Encrypt), et **portable** vers le cloud par simple changement de provider. L'app **mobile** (Expo) et **desktop** (Electron) s'empaquettent par leurs toolchains natives, au-dessus du **même** serveur Hono + sidecar.

## Ce que ça autorise

Vous décrivez votre app **une fois**, et AIDOS la projette **partout** : un serveur Hono, un front React, une app Expo, une app Electron — **une source → N plateformes**, chacune une **projection déterministe** de la même vérité, le **même** sidecar interpréteur Go en clé de voûte. Ce que ça **préserve intact**, c'est le reste : le mur tient (le sidecar n'écrit aucune vérité, ne touche que le schéma de votre app), l'interprétation reste **gouvernée et non dupliquée** (`operation.Interpret`, jamais ré-écrit en TS), et la porte vers le noyau reste, comme toujours, idée → miroir → `/goal` → approbation humaine. La plateforme est une **dimension** que vous *choisissez*, jamais une re-déclaration que vous *maintenez* — *tout se fait par écran*, une cible de plus restant un **paramètre**.
