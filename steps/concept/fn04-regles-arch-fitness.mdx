## En une phrase

FN04 grave les trois invariants du mandat fonctionnel en **règles arch-fitness** déterministes et **fail-closed** sur le code émis (`back/gen/`) : **pas de globale mutable**, **pas d'`init()`**, **graphe d'appel acyclique** — vérifiées par une marche d'AST, jamais par un jugement LLM, et prouvées par un miroir de **fault-injection** (rouge d'abord).

## Le problème que ça résout

FN02 a **gravé** le mandat (ADR 0036) ; FN03 a **réformé** l'émetteur pour *produire* du pur et a prouvé que l'émetteur **ne peut pas** émettre une violation. Mais une garde qui ne vit que dans l'émetteur peut **pourrir** : un futur émetteur, un patch, un raffinement pourrait re-glisser une variable globale, un `init()` ou une récursion dans `gen/`, et chaque « determinism-first ✓ » par-step passerait quand même.

FN04 fait du mandat une **garde de build** : une règle déterministe qui **scanne** l'arbre émis et **refuse** toute violation — exactement comme la règle « une seule fonction LLM » (BA14) refuse un second import de SDK ailleurs que dans le `provider`.

## Les trois règles

<CardGroup cols={3}>
  <Card title="EMITTED_NO_GLOBAL_MUTABLE">
    Aucune variable mutable au scope paquet dans un fichier émis. Les tables sont **retournées par valeur** et threadées (le `typeBindings()` du spike). Les `const` et les types restent permis (immuables) ; une assertion `var _ X = …` (vérification de compilation) n'est pas un état mutable et n'est pas signalée.
  </Card>
  <Card title="EMITTED_FUNCTION_PURE">
    Aucun `init()` au niveau d'un fichier émis : un `init()` introduit un **état au démarrage** hors des entrées de la fonction. Chaque symbole émis est une valeur/type pur — même entrée → même sortie, structurellement.
  </Card>
  <Card title="EMITTED_CALL_GRAPH_ACYCLIC">
    Le graphe d'appel intra-fichier du code émis est **acyclique** : pas de récursion directe ni mutuelle. Chaque fonction est **une couche + un nœud** d'un graphe acyclique — l'intention Understand-Anything, et l'index dont dépendra FN05.
  </Card>
</CardGroup>

## Les idées-clés

<CardGroup cols={2}>
  <Card title="Fail-closed : le doute est rouge">
    Un Go émis qui ne **parse même pas** ne peut être certifié fonctionnel : c'est une violation (`EMITTED_UNPARSEABLE`), jamais un vert silencieux. La règle refuse par défaut et n'accepte que ce qu'elle a prouvé sain.
  </Card>
  <Card title="Une marche d'AST, jamais un LLM">
    « Est-ce fonctionnel ? » est une question **déterministe** : on parse le code et on inspecte l'arbre. Même entrée → mêmes violations. Un « LLM qui juge si c'est fonctionnel » serait une fracture de déterminisme qui bloquerait le step.
  </Card>
  <Card title="Portée tranchée : les sorties émises seulement">
    Seuls les fichiers portant le marqueur « CODE GENERATED BY AIDOS » sont contraints — les **projections** émises (l'app de l'utilisateur). La logique des émetteurs et le code généré par sqlc sont **hors portée** : AIDOS reste un OS impératif qui *émet* du fonctionnel.
  </Card>
  <Card title="Prouvée par fault-injection">
    Une règle qui ne se déclenche jamais est morte. Le miroir **injecte** une globale, un `init()`, un cycle dans du code émis et exige que la règle correspondante passe **rouge** — la preuve que la garde fire.
  </Card>
</CardGroup>

## Ce que vous voyez à l'écran

Sur le panneau **/emitters** du Workbench, chaque projection Go émise porte un bouton **« Vérifier arch-fitness »**. Un clic lance la règle sur les octets émis et affiche le verdict : **conforme** (aucune globale mutable, aucun `init()`, graphe acyclique) ou **refusé** avec le code de la violation. Le verdict est **calculé**, jamais déclaré.

## Le mur

FN04 n'écrit **aucune vérité**. Les règles sont du code *sous la ligne* : elles **lisent** `gen/` et **rapportent** des violations ; elles ne touchent ni `kernel`, ni `mirrors`, ni `fitness`. Élargir la portée ou assouplir un invariant est un **changement de vérité** (idée → miroir → /goal → approbation), jamais une édition silencieuse.
