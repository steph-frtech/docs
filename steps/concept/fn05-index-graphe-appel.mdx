## En une phrase

FN05 construit, pour chaque fichier émis, l'**index de son graphe d'appel** — qui-appelle-qui — comme une **fonction pure** du code (même code → même graphe → même empreinte) ; cet index est la **carte Understand-Anything** fournie à l'agent comme contexte, et le **ContextRouter** (S33) la consomme pour cibler **uniquement le sous-graphe affecté** par un changement.

## Le problème que ça résout

FN04 a prouvé que le graphe d'appel du code émis est **acyclique** (`EMITTED_CALL_GRAPH_ACYCLIC`). Mais une garantie n'est pas une **carte** : pour qu'un agent travaille sur l'app émise sans tout recharger, il lui faut savoir précisément *qui appelle qui* et *que touche un changement donné*.

FN05 transforme ce même graphe en un **index** de première classe, content-addressé, et **complète le ContextRouter** (S33) : là où S33 route par red-set et bounded-context au-dessus du `ContextGraph` du kernel, FN05 lui permet de cibler **aussi** par la structure d'appel de l'app émise — « chaque fonction = une couche + un nœud » — pour charger le sous-graphe affecté, jamais tout l'arbre `gen/`.

## Les idées-clés

<CardGroup cols={2}>
  <Card title="L'index est une fonction pure du code">
    Même code → même graphe → même empreinte. C'est une **marche d'AST** sur le Go parsé, jamais un « LLM qui lit le code ». Les nœuds sont triés, les appelés de chaque nœud sont triés : l'encodage est byte-identique et content-addressé (le critère de done).
  </Card>
  <Card title="Le sous-graphe affecté remonte les dépendants">
    Changer une fonction **feuille** ripple **vers le haut** : tous ceux qui l'appellent, directement ou par une chaîne, sont affectés — ce sont exactement les couches que l'agent doit recharger. <code>AffectedSubgraph(index, changé)</code> calcule cette clôture des dépendants. Comme le graphe est garanti acyclique (FN04), le calcul termine toujours.
  </Card>
  <Card title="Consommable par le ContextRouter (S33)">
    Le router cible le sous-graphe touché plutôt que tout l'arbre émis : il **complète** la compilation du ContextPack avec la structure d'appel de l'app émise. C'est le second critère de done — « le router peut le consommer pour cibler le sous-graphe affecté ».
  </Card>
  <Card title="Hors-portée / illisible → index vide (honnêteté)">
    Seuls les fichiers portant le marqueur « CODE GENERATED BY AIDOS » sont indexés (ADR 0036 §3). Une source non marquée, ou un Go émis illisible, rend l'index **vide** : l'index n'invente jamais un nœud ni une cible qu'il ne peut dériver (la règle d'honnêteté).
  </Card>
</CardGroup>

## Ce que vous voyez à l'écran

Sur le panneau **/emitters** du Workbench, chaque projection Go émise porte un bouton **« Indexer le graphe d'appel »**. Un clic lance l'index déterministe sur les octets émis et affiche : les **nœuds** (fonction → appelés), l'**empreinte** de l'index (même code → même graphe), et le **sous-graphe affecté** par un changement de la première fonction — ce que le ContextRouter consomme. Le résultat est **calculé**, jamais déclaré.

## Le mur

FN05 n'écrit **aucune vérité**. L'index est du code *sous la ligne* : il **lit** le code émis et **rapporte** le graphe (contexte / télémétrie) ; il ne touche ni `kernel`, ni `mirrors`, ni `fitness`. Le router *consomme* l'index ; il ne fait jamais écrire de vérité depuis l'écran.
