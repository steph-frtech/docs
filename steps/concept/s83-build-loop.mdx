## En une phrase

S83 est **l'agent qui construit réellement votre app** : il prend la liste des tests rouges, écrit le code pour les faire passer au vert, **vérifie avec les miroirs** (jamais sur sa propre parole), et **s'arrête honnêtement** — soit parce que tout est vert, soit parce qu'il dépense sans avancer.

## Le problème que S83 résout

Une fois votre besoin transformé en **red set** (des tests rouges qui *sont* le but, S66), il faut quelqu'un pour écrire le code qui les rend verts. C'est le travail de l'agent exécutant. Mais un agent LLM laissé seul a deux failles dangereuses :

- **Il peut tourner en rond sans fin** — réécrire le même diff, faire passer un test au vert puis le casser au tour suivant, brûler des tokens sans jamais converger.
- **Il pourrait se déclarer « fini » sans l'être** — c'est exactement ce que le KRD interdit (« done is computed, never declared »).

S83 ferme ces deux failles : le **juge est le miroir déterministe** (pas le LLM), et un **disjoncteur** arrête honnêtement une boucle qui dépense sans avancer.

## Comment vous l'utilisez

Depuis le panneau **« Boucle de build »** du Workbench :

1. **Donnez le red set** : les miroirs rouges qui sont le but (un par ligne).
2. **Donnez l'état vivant** : quels senseurs sont déjà verts, les conditions du Stop (mutation / plancher / vert antérieur / monstres), l'historique d'itérations, et le budget déclaré.
3. **Évaluez la terminaison** : AIDOS calcule le verdict — **VERT** (le Stop non-gameable passe), **NO_PROGRESS** (le disjoncteur a tripé ou over-budget), ou **CONTINUE** (on itère encore).

Le verdict est une **fonction pure de l'historique** : le même historique donne toujours le même verdict d'arrêt. Aucun jugement « je pense qu'on est coincé » d'un LLM n'entre dans la décision.

## Pourquoi « le disjoncteur est déterministe » compte

La stagnation est une **propriété structurelle de l'historique** : deux diffs identiques d'affilée, c'est de la pure répétition ; un miroir qui passe vert puis redevient rouge, c'est du thrashing ; aucun miroir nouvellement vert sur la fenêtre déclarée, c'est l'absence d'avancée. Ces signaux se **calculent** — ils ne se devinent pas. C'est la garantie qu'une boucle ne dépensera jamais à l'infini, et que deux exécutions sur le même historique s'arrêteront exactement de la même façon.

## Le mur tient toujours

L'agent de la boucle **n'écrit aucune vérité**. Il écrit du code dans **votre bac à sable** (sous la ligne, S82). Toute tentative d'écriture *au-dessus de la ligne* (kernel, miroirs, fitness) est refusée avec `AGENT_WRITE_ABOVE_WATERLINE` — pour tout rôle. Quand le travail implique une vérité, la boucle **propose** un ChangeSet (S85) qu'un humain approuve ; elle n'écrit jamais la vérité directement. Et la décision de terminaison elle-même est un **calcul sous la ligne** — elle n'écrit rien.
