## En une phrase

S32 livre le **`ContextGraphDecision`** (KRD §119.2) : la **porte déterministe et sans LLM** qui décide si une **décision passée** peut être **réutilisée** pour une nouvelle requête, en vérifiant **exactement quatre dimensions déclarées** — *time / scope / authority / conditions* — et en émettant `{may_reuse, reason, checked, required_human_review}`. **Le graphe permet ou bloque ; les agents proposent ; l'Execution Layer agit.**

## Le problème que ça résout

Une décision prise hier — « accorder cette dérogation de SLA », « ce barème de remise » — a été prise **dans un contexte** : une **région**, une **fenêtre de temps**, sous une **autorité**, sous des **conditions**. La réutiliser **aveuglément** demain, hors de ce contexte, est une **hallucination structurelle** (KRD §13.7 : *« une décision réutilisée hors scope est une hallucination structurelle »*). Il faut donc une **porte** : « cette décision passée tient-elle encore *ici, maintenant, pour cette requête* ? ». S32 est cette porte — et elle est **déterministe** : la même entrée donne toujours le même verdict, car **`now` est passé en paramètre** (jamais lu sur l'horloge) et **aucun LLM ne vit dans cette couche**.

## Les idées-clés

<Field name="Exactement quatre dimensions DÉCLARÉES" type="time · scope · authority · conditions">
  La porte vérifie **quatre** dimensions, ni plus ni moins (KRD §119.2) : **time** (la `time_window` / `expires_at` du candidat doit contenir `now`), **scope** (le `TruthScope` du candidat — région/tenant/target/user_segment/environment — doit être un **sur-ensemble** du contexte de la requête), **authority** (le détenteur d'`AuthorityGraph` du candidat doit **encore tenir** pour le domaine/truth_kind de la requête), **conditions** (les prédicats de réutilisation **déclarés** doivent tenir). Les prédicats sont **déclarés, jamais appris**.
</Field>

<Field name="FALSE-DOMINANT" type="le moindre contrôle qui échoue bloque">
  Le verdict est **`false`-dominant** : on évalue les quatre dimensions **dans l'ordre** et le **premier** contrôle qui échoue **bloque** la réutilisation, en **nommant** la dimension fautive. `may_reuse == true` **⇔** les **quatre** dimensions ont été évaluées **et** ont toutes passé. Le champ `checked` enregistre **quelles** dimensions ont été vérifiées — le verdict s'**explique** lui-même.
</Field>

<Field name="Le LLM ne vit pas dans le ContextGraph" type="permet ou bloque — il n'agit pas">
  La clé de voûte de §119.2 : **« Le LLM ne vit pas dans le ContextGraph. »** Le ContextGraph **permet ou bloque** ; les **agents proposent** ; l'**Execution Layer agit**. `Decide` est une **fonction pure** — pas d'I/O, pas d'horloge (`now` est passé), **aucun appel LLM, jamais**. Un agent qui ferait ce qu'une fonction peut faire serait un **écart de déterminisme** (CLAUDE.md §8).
</Field>

<Field name="time ⇒ expired = non réutilisable" type="le critère « done » (1/2)">
  Une décision dont la fenêtre de validité est **dépassée** par `now` donne `may_reuse: false`, avec `"time"` dans `checked` et une raison **nommant la fenêtre expirée**. C'est le cas canonique du `ContextGraphMirror` : *given `{decision, region: EU, date: expired}` → expect `{may_reuse: false}`*.
</Field>

<Field name="scope ⇒ hors-scope = non réutilisable" type="le critère « done » (2/2) — no_reuse_outside_scope">
  Une décision prise pour une **région** que la requête ne vise pas (candidat EU, requête US) donne `may_reuse: false`, avec `"scope"` dans `checked`. C'est la loi **`no_reuse_outside_scope`** (KRD §82.2 / §13.7) : réutiliser hors scope est une **hallucination structurelle**.
</Field>

<Field name="authority qui ne tient plus ⇒ revue humaine" type="required_human_review">
  Si le détenteur d'autorité du candidat ne **gouverne plus** le domaine de la requête, la porte ne réutilise pas en silence : elle pose `required_human_review: true` — un **humain re-décide** (KRD §13.8).
</Field>

## Ce que S32 n'est PAS

<Warning>
S32 livre **uniquement la porte de réutilisation** sur un ContextGraph **déjà construit**. Ce n'est **pas** le **ContextRouter / la compilation du ContextPack** (§119.3, §141–§142, la *couche information* — quelles vérités/mémoires donner au modèle — étape ultérieure) ; **pas** la **construction/traversée** du ContextGraph (§142, consommée en entrée) ; **pas** le **flux de promotion** `Memory → ContextPack → Idea → Mirror → Goal → Kernel` (le MemoryFirewall §119.1, S30) ; **pas** d'AST `TruthScope` (S15) ni `AuthorityGraph` (S16) re-définis ; **aucun** LLM, RAG ou embedding.
</Warning>
