## En une phrase

S29 livre le **moteur de goal** §56–§59 : la **seule porte légitime** d'une **idée** (une vérité-candidate) vers la vérité — `idea → mirror → /goal`. Le moteur **ouvre** un **ChangeSet DRAFT** (S20) portant atomiquement le `spec_delta` + le `mirror_delta` de l'idée, **dérive** le **set rouge** (les miroirs qui échouent et **qui sont** le goal, §56), et n'autorise sa **fermeture** que par un **stop non-gameable** : `set rouge → vert ∧ vert antérieur intact ∧ mutation ≥ seuil ∧ aucun monstre` — **calculé**, jamais déclaré par l'agent.

## Le problème que ça résout

La commande `/goal` existe déjà dans le harnais (Codex CLI, Claude Code) — mais son **stop par défaut est faible** : l'agent **note sa propre copie** (« je pense avoir fini »). C'est exactement la faille que KRD §57 ferme. La contribution de KRD est un **stop NON-GAMEABLE** : « le set rouge du noyau passe au vert, sans casser un seul vert existant » — **déterministe**, **computationnel**, **sans auto-évaluation**. Le moteur ne lit **jamais** la confiance de l'agent ; « done » est **calculé**. Et avant même la fermeture, l'**ouverture** est gardée : une idée n'entre dans le goal que **par son miroir** (idea → mirror → /goal). Une idée **sans miroir** est un **vœu** — un monstre ; une idée **déjà verte** n'est pas un goal (rien à fermer). Entre le désir et la vérité, il y a **exactement une porte**, et elle ne peut pas être truquée.

## Les idées-clés

<Field name="Un goal = un ChangeSet DRAFT + le set rouge (§56 / §57)" type="le test rouge EST le goal ; le set rouge EST la todo-list">
  Ouvrir un goal, c'est **ouvrir un ChangeSet DRAFT** (S20) qui porte **ensemble** le `spec_delta` (le plan noyau) et le `mirror_delta` (sa preuve) — atomiquement, ils ne peuvent jamais dériver — **plus** le **set rouge** : l'ensemble ordonné des miroirs qui **échouent** et **qui sont** le goal. « Le test rouge EST le goal ; le set rouge EST la todo-list » (§56). Tant que le set rouge n'est pas vert, le goal n'est pas atteint.
</Field>

<Field name="Une idée sans miroir est un vœu — refusée (§57 / LIVRE XX)" type="IDEA_WITHOUT_MIRROR — aucun ChangeSet ouvert">
  La **seule** porte vers la vérité est `idea → mirror → /goal`. Une idée qui n'apporte **pas** de `mirror_delta` est un **vœu** — un monstre : `OpenGoal` la **refuse** avec le `BlockReason` actionnable `IDEA_WITHOUT_MIRROR` (`how_to_fix` : `draft_mirror_for_idea`), et **aucun** ChangeSet n'est ouvert. On ne promeut jamais une idée en silence.
</Field>

<Field name="Une idée déjà verte n'est PAS un goal (§56)" type="NO_RED_SET — rien à fermer">
  Le set rouge est **dérivé** (par la vague de rouge, S22) du `spec_delta` de l'idée : ce sont les miroirs que le changement fait **rougir**. Si ce set est **vide** — le miroir est déjà vert —, il n'y a **rien à fermer** : ce n'est **pas** un goal. `OpenGoal` la refuse avec `NO_RED_SET`. Un goal existe **seulement** s'il porte **≥1 miroir rouge**.
</Field>

<Field name="Le stop est non-gameable : quatre conditions calculées (§57 ① / §8)" type="set rouge→vert ∧ vert antérieur intact ∧ mutation ≥ seuil ∧ aucun monstre">
  Un goal se ferme **seulement** quand **les quatre** conditions tiennent : (1) chaque miroir du set rouge est **vert** ; (2) le **vert antérieur** reste **intact** (aucune régression sur une vérité existante, §8) ; (3) le **score de mutation** est ≥ le **seuil déclaré** ; (4) **aucun monstre** (ni orphelin, ni vérité sans miroir). `IsClosed` calcule ce verdict — **déterministe**, **sans** aucune entrée de **confiance** de l'agent. Un miroir encore rouge, un vert cassé, une mutation trop basse, ou un monstre **garde le goal OPEN**.
</Field>

<Field name="« Done » est calculé, jamais déclaré (§8)" type="le moteur ne lit jamais la confiance de l'agent">
  L'agent ne peut **pas** se déclarer fini. `OPEN`/`CLOSED` est **calculé** par `IsClosed`, surfacé par le hook `Stop:goal-check` qui **refuse** la fermeture avec `GOAL_STILL_RED` tant qu'une condition échoue. L'agent **n'écrit jamais** la vérité et **n'estampille jamais** un goal `CLOSED` : il a `SELECT` seulement sur `ideas.goal` ; le gel est écrit par le rôle `aidos` via la porte de commit (S20). C'est tout l'objet de S29 : l'agent ne note **jamais** sa propre copie.
</Field>

<Field name="Les budgets sont la garde secondaire (§57)" type="temps / tours / tokens — déclarés, jamais appris">
  Les **budgets** (temps, tours, tokens) bornent la boucle — c'est la garde **anti-emballement secondaire**, **déclarée** (jamais apprise). Ils ne sont **pas** une condition de fermeture : la fermeture est le stop à quatre parties. Le Workbench en montre le **burndown**.
</Field>

## Ce que S29 ne fait pas (dents ultérieures)

- **Pas la motion red→green TDD elle-même** : ce moteur **ouvre** le goal et **calcule** son stop ; tourner le set rouge au vert est le travail `/src` de l'agent (la boucle `/tdd`), pas ce moteur.
- **Pas l'enveloppe ChangeSet ni la porte de commit** : S20 possède l'enveloppe `DRAFT → APPLIED` et le commit-gate ; ici on les **consomme**, on ne les redéfinit pas.
- **Pas le SemanticDiff** : S21 le possède ; consommé.
- **Pas la vague de rouge** : S22 décide **quels** miroirs rougissent ; S29 l'**appelle** (`Impact`) pour dériver le set rouge, il ne la réimplémente pas.
- **Pas la boucle /evolve ② ni la boucle réalité ③** : seulement la **boucle interne ①** (le `/goal`, stop non-gameable).
- **Pas de codegen / pas de nouveau MCP** : `OpenGoal`/`IsClosed` sont une bibliothèque pure et `/goal` est un geste du harnais ; idea-intake et le MCP changeset existent déjà.

## Le mur

Le moteur est la machinerie du **harnais au-dessus du mur** (CLAUDE.md §2) : `OpenGoal`/`IsClosed` **ne renvoient que des valeurs** — la persistance d'une ligne `ideas.goal` passe par le **rôle writer `aidos`** via le flux `/goal`, **jamais** l'agent. La table `ideas.goal` donne à l'agent **`SELECT` seulement** : ouvrir un goal et l'estampiller `CLOSED` sont des **écritures de vérité** réservées au rôle `aidos` + la porte de commit (S20). L'écran **/goal** est en **lecture seule** : il **rejoue** le même verdict pur que le moteur Go (les quatre conditions du stop) et **n'écrit aucune** vérité. C'est l'**asymétrie** qui **incarne** le stop non-gameable **dans le schéma** : l'agent ne peut **littéralement pas** écrire une ligne `CLOSED`.
